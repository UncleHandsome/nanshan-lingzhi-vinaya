# 提示詞．每段判定版

## 材料

[測試_100段.txt](測試_100段.txt)（T-0001～T-0100）或 [測試_T2.txt](測試_T2.txt)（T2-0001～T2-0100）。

## 提示詞（複製整段）

```text
你是漢文佛教律典譯文的校閱者。下面 100 段是《南山三大部》白話譯文的抽樣，每段附原文與現行白話。

【第一階段：逐段判定】
請對每一段輸出一行，順序與材料完全相同，不可省略任何一段：

編號 ｜ 判定 ｜ 理由
T-0001 ｜ OK ｜ 對比原文「…」與譯文「…」，意思一致
T-0002 ｜ P1 ｜ 原文「三趣」指人、非人、畜生，譯文作「三惡趣」，名相有誤

判定代碼：
- OK：這一段沒有問題
- P0：意思相反、漏譯、張冠李戴、律制事實錯誤
- P1：術語、名相、因果、程序理解偏差
- P2：標點、體例、錯字

要求：
1. 必須剛好 100 行，編號連續。
2. 寫 OK 也要寫理由，指出你比對了哪個詞或哪個數字。
3. 不確定就寫「存疑」，不要直接寫 OK。

【第二階段：完整替換】
最後另列「有問題清單」，對每個非 OK 的段給整段替換文字：

### T-0002｜P1｜名相
建議：（完整段落，除問題句外與現譯逐字相同）
```

## 回來給我

把第一階段的 100 行存成 `verdict_T.txt`（或 `verdict_T2.txt`），格式：

```
T-0001	OK
T-0002	P1
```

我會用 `key.tsv` 算召回率與誤報率，跟上一版（23% / 0%）直接比較。

## 為什麼這樣改

上一版只要求「回報有問題的段」，AI 可以只挑最明顯的七段就交差。這版強制每段都要寫理由，等於逼它逐段讀，也讓你一眼看出它有沒有真的看（行數不足、理由空洞就是沒看）。
