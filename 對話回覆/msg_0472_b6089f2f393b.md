## 一、提示詞是否太 case-by-case？（膨脹與注意力稀釋問題）

**是的。** 可以明顯看出每當實測（如 L5 第 06/07 組、HTTP 400、短段膨脹）抓到一次失誤，就在提示詞裡直接追加一條微觀規則。這帶來三個副作用：

1. **單條規則過長，引發「中間迷失」（Lost in the Middle）**：
   * 例如 `BLIND_PROMPT` 的第 2、3 點，每點都變成將近 400～500 字的長段落，裡面塞了十幾條毫無關聯的微規範（古今異義、標點、括號、反切、身體戒相勿用委婉語、`〔疑作X〕` 等）。模型在翻譯時很難同時顧及這麼多平行的負面約束。
   * 許多極度特化的規則屬於「詞彙級補丁」，例如：`「若…者」須分辨條件假設與話題提頓（至於…）`、`「以…故」多為因果連詞，惟「故」亦可能作「故意」解`、`科判語之「文」多指所釋鈔文／疏文該段原文，勿譯作「文章」「文字」`。這類例子越多，模型越容易產生過度校正或忽略其他未舉例的詞彙。
2. **跨層級大量重複**：
   * 典籍簡稱表（`伽論`、`婆沙`、`善生`……）在「系統 prompt、一審、審核、修訂」各出現一次。
   * 《尼鈔》不可硬套比丘制的規範，在「系統 prompt 第 2 點、系統 prompt 第 4 點、盲翻、裁決、審核」總共重複了 4～5 次。
   * 原本《隨機羯磨》《含注戒本》《四分律》的「文／注／律」指代，也是每一關重複貼。
3. **實作細節洩漏進提示詞**：
   * `JUDGE_PROMPT` 直接寫出 `前後背景可能於 900／600 字處截斷`。這是程式參數，模型不需要知道精確字數（且萬一未來調成 1200 字就失真了），只需知道「前後背景可能非從段首開始或於中途截斷」即可。

## 二、提示詞之間的自相矛盾與邏輯衝突

### 1. 圓括號 `()` 的「生殺標準」上下游打架（最嚴重）
四支提示詞對圓括號的許可清單**不一致**：
* **盲翻（BLIND）與 裁決（JUDGE）**：明確允許 **3 類** 圓括號：
  1. 不補則句意殘缺或方向相反的省略指代／前提條件
  2. 原文夾注、反切讀音與通假義
  3. 銜接【記文】所牒實詞的極簡原字
* **審核（AUDIT）**：在「可保留項」裡**只列了第 2、3 類**（加上 `〔補字〕`/`〔疑作X〕`），把第 1 類（省略條件／指代）漏掉了，緊接著又說：**「其餘解說性圓括注一律 FIX」**！
* **修訂（REVISE）**：只寫了**「嚴禁以圓括號添加解說或背景」**，完全沒告訴修訂模型「夾注、反切、記文原字」是可以保留的。
* **後果**：盲翻或裁決好不容易依照指令用括號補了一個「不補會反義」的條件，審核卻因為清單沒列這項而判 `FIX` 要求刪除；或者審核要修訂改別處，修訂卻順手把合法的反切或夾注括號一起刪了。

### 2. 審核被要求「參考裁決引用的書名卷次」，但程式早就把它刪光了
* `AUDIT_PROMPT` 寫道：「`不得沿用裁決判斷而不覆核原典，但得援引裁決所註書名卷次為檢索線索以省重複搜尋。`」
* 但是看 `mk_audit_materials.py` 第 173–184 行的實際做法：
  ```python
  _m = re.match(r'(.*?｜裁決[^：:]{0,15}[：:])(.*)', _s)
  if _m:
      _head = _m.group(1)
      _why = _m.group(2)
      _tag = '甲' if '甲優' in _head else ('乙' if '乙優' in _head else '重修')
      _brief.append(_head + '採' + _tag)
  ```
  程式為了防偏向，把裁決第 2 欄的理由 `_why`（**書名卷次與原文引據都在這一段裡**）全部砍掉，只留下 `採甲／採乙／採重修`！也就是說，**審核根本看不到裁決引用的書名卷次**，提示詞卻教它去引用，容易誘使模型無端猜測或覺得資料不全。

### 3. `BLIND_PROMPT` 內部的自我重複與數字打架
`BLIND_PROMPT` 第 3 點裡，同一件事寫了兩遍且口徑不一：
* 前半句寫：`僅在「不補則句意殘缺或方向相反」之省略指代與前提條件，或「銜接【記文】所牒實詞須附原字」時（**兩處**）才加極簡圓括號`
* 緊接著兩行後寫：`圓括號僅限**三處**——……省略條件／指代、原文夾注與反切讀音／通假義、銜接記文所牒實詞之極簡原字`
* 同樣在第 3 點：先寫 `〔〕 僅用於原典明顯脫漏之補字（如「〔不〕」），遇疑似訛字勿強順擴寫、亦勿自寫校勘按語`，五句之後又重寫一次幾乎一樣的話，但變成了 `僅得以極簡 〔補字〕／〔疑作X〕 標明`。

### 4. `REVISE_PROMPT` 的典籍全稱打錯字
* 其他提示詞都是：`伽論＝《薩婆多部毘尼摩得勒伽》`
* `REVISE_PROMPT` 寫成：`伽論＝《薩部毘尼摩得勒伽》`（漏了「**婆多**」二字）。一旦修訂階段依照自己的清單去補寫全稱，就會寫出錯書名。

### 5. `BASE_PROMPT`（一審）與後續管線口徑脫鉤
* `BASE_PROMPT` 還保留著 `以 〔補字〕 或段末簡註標明`（允許段末加註），以及 `易混典籍簡稱全段統一或首見附全稱`，這兩條在盲翻、裁決、修訂都是嚴禁「附帶出處、解說或段末註」的。若混用一審稿（A1）進後續流程，這類註記會被後面的審核判成硬傷。

### 6. `JUDGE_PROMPT` 要求「防範雙譯同誤」，但程式直接跳過同文比對
* `JUDGE_PROMPT` 第 2 點要求：「即使甲、乙譯法一致，仍須核對有無共同漏譯、施受反轉……皆須檢索查證後裁定。」
* 但 `mk_judge_materials.py` 第 187 行只要 `_same(_a, _b)` 為真，就直接跳過裁決寫成 `PASS_A`。雖然後面還有 `Audit` 把關不算漏審，但因為跳過了裁決的檢索查證，變成把「防雙譯同誤」的壓力全壓在審核身上；另外這個分支複製的 `.md` 還是舊材料格式（含 `BASE_PROMPT` 與 `（現譯）`），不是 `JUDGE_PROMPT`。

## 三、提示詞與程式碼之間的錯配及隱藏 Bug

除了提示詞本身，對照你貼出的程式碼與文件，有幾處**明確的程式 Bug** 與**質檢誤殺**：

### 1. `qc_scan.py` 會誤殺提示詞教出來的 `〔疑作X〕`
* 盲翻、裁決、審核、修訂四支提示詞都明文允許寫 `〔疑作X〕`。
* 但 `qc_scan.py` 的正則寫的是：
  ```python
  if re.search(r'〔[^〕]{0,20}(?:據|疑|脫|補|按)', out):
      issues.append('〔〕內疑含校勘按語')
  ```
  只要譯文出現合法的 `〔疑作X〕`，因為含有「`疑`」字，就會被 `qc_scan` 判成異常。

### 2. `qwen_local.py` 的四個實作 Bug（與第 4.4 / 7.6 節文件不符）
* **第 8 輪達到上限必崩潰（`NameError`）**：在 `for _round in range(MAX_TOOL_ROUNDS):` 迴圈結束後的保底發送（第 536 行），寫了 `_payload['tools'] = TOOLS`，但全域與迴圈內變數名都是 `payload`，沒有 `_payload`，跑滿 8 輪會直接噴 `NameError` 失敗。
* **同查詢免重搜快取沒生效（死碼）**：`local_search` 裡寫了 `memo = stats.setdefault('local_memo', {})` 並檢查 `if key in memo:`，但整個函式從頭到尾**從未把結果寫進 `memo[key]`**，因此「相同查詢直接沿用結果、不計額度」實際上沒有作用（`local_log` 在正常命中時也沒寫入）。
* **「查無結果前 2 次免扣額度」並未實作**：`local_search` 是在 `_LC.find` 之前就執行 `_local_budget(stats)` 扣額度；後面只寫了 `if not hits and _raw_n ...` 退額度——這代表只有「原本有搜到，但因為和待審原文重疊（`_own`）被全部過濾掉」才會退額度；**真正查無（`_raw_n == 0`）照樣扣額度**。
* **雙反斜線正則失效**：7.11 節提到修過 `r'[\s　]'` 雙斜線，但 `qwen_local.py` 第 210、224 行的 `re.sub(r'[\\W_]+', '', ...)` 與第 369 行的 `re.sub(r'^\\s*【...', ...)` 依然在 `r'...'` 原始字串裡寫了 `\\W` 與 `\\s`，這會只匹配字面反斜線 `\` 與字母 `W`/`s`，導致自搜過濾與重貼原文偵測的去除空白標點功能失效。

### 3. `run_pipeline.py` 中的 `packjudge` 與 `long` 分支接線錯誤
* **`packjudge` 分支**：`run_pipeline.py` 呼叫 `pack_judge.py --materials 測試/重譯/bk/_材料`。但 `_材料` 裡面只有 `（原文）` 和 `（現譯）`，**沒有 `（譯本甲）` 與 `（譯本乙）`**！`pack_judge.py` 抓的是 `(原文|譯本甲|譯本乙)`，直接拿 `_材料` 打包會把兩份譯文全丟掉，只剩原文；且拆回時複製 `_材料` 的 `.md` 給 `audit`，裡面的標籤也不是 `（譯本甲）`，遇到 `PASS_A_KEEP_A` 時 `MI.from_jia()` 會回傳空字串。它應該在 `pack_judge` 前先經過 `mk_judge_materials` 產出裁決材料再打包，或讓 `pack_judge` 直接吃 `--a`/`--b`。
* **`long` 分支**：`run_pipeline.py` 把 `_長段/_終審` 同時當成 `mk_revise_materials.py` 的 `--r1` 和 `--audit`。但 `mk_revise_materials` 會對 `--r1` 的回覆呼叫 `col3_safe()` 找「修正後的譯文」，而 `_終審` 是審核報告，沒有第 3 欄「修正後的譯文」，會導致全部長段都印出 `⚠ 修訂回覆異常，略過`。（這部分在 7.14 節提到的獨立腳本 `run_long_audit.py` 應該另有修正，但 `run_pipeline.py` 這段目前是壞的）。

### 4. `pack_judge.py` 的鄰接檢查正則與漏號風險
* 第 73–74 行的 `_na = re.search(r'(\\d+)$', it['key'])` 同樣有 `r'...'` 雙反斜線問題，永遠匹配不到尾端數字，導致 `_gap` 恆為 `False`——如果中間曾因長段或未配對段跳過了幾段，不連續的段落依然會被硬打包在一起。
* `do_split` 第 155 行用 `if i not in _by_i:` 判斷該段是否沒改動（直接強制改寫為 `PASS_A_KEEP_A`）。萬一裁決在第 2 欄把 `[1][2]` 合併寫成一條、或漏了 `[2]` 標記，但第 3 欄其實改了第 2 段的譯文，拆回腳本會直接**無聲覆蓋成 `PASS_A_KEEP_A`**，把裁決的修正丟掉。

### 5. `norm.py` 的兩個小 Bug
* **7.12 節修補未生效**：第 60–65 行確實算出了文本既有的 `_lab`（如 `疏文`、`記文`），但第 67 行 `for _a, _target in LABEL_FIX.items(): _txt = _txt.replace(_a, _target)` 仍然直接套用寫死為 `'【鈔文】'` 的字典，`_lab` 變數完全沒有被使用。
* **巢狀引號正規化失效**：第 44–50 行用單一布林值 `_in` 判斷是否在引號內。遇到 `「……『……』……」` 的引中引時，一碰到內層的 `』`，`_in` 就會被設為 `False`，導致後半段明明還在外層 `「……」` 原文引句裡的字被當成白話文做了異體字轉換。應改為深度計數器 `depth`。

### 6. `build_a2.py` 依賴意外的 fallback 解析修訂稿
* `REVISE_PROMPT` 要求模型「直接輸出完整譯文（以 `【疏文】` 等開頭）」，不要寫三欄報告。
* 但 `build_a2.py` 卻用 `col3()` 去切修訂回覆（先找 `修正後的譯文`，找不到才找 `【疏文】` 標籤）。目前是靠後面這段 fallback 才剛好運作，一旦模型偶爾漏了標籤或前面加了說明文字就容易出錯。修訂回覆其實應該直接當純譯文讀取（加上清理偶發前綴即可），不需要走三欄切割。

## 四、精簡與重構建議

如果你想在不掉品質（甚至更穩）的前提下解決「太 case-by-case」和「互相打架」的問題，建議這樣整理提示詞：

1. **抽出共用的《規範與術語表》（Single Source of Truth）**：
   把「括號三原則 + `〔補字〕`/`〔疑作X〕`」、「書名號/問答體例」、「典籍簡稱對照表」、「文／注／律指代與《尼鈔》原則」寫成模組化的共用區塊（就像你已經做的 `book_config.py`），由 Python 統一注入，**不要在五支提示詞裡手寫五套不同版本**。這能立刻根除「《薩部》錯字」、「括號規則上下游打架」、「重複寫兩遍」的問題。
2. **合併「微觀詞彙補丁」為少數高階原則**：
   * 把「若…者」、「以…故」、「文勿譯作文章」這類散落的特例，濃縮進兩句原則就好，例如：「辨析文言虛字多義性（區分假設與提頓、因果與實詞『故』等）及科判專指（如『初／次／今文』指所釋原文）」。
   * 把「身體戒相勿用委婉語」改寫進 `SYSTEM_PROMPT` 或資料詞典，只留一句簡短的「宗教律典學術語譯，身體與戒相要件須如實直譯」。
3. **決定 `BASE_PROMPT` 的去留**：
   如果主力流程已確定是「盲翻 → 裁決 → 審核 → 修訂」，建議明確把 `BASE_PROMPT` 標記為獨立舊路徑，避免同時維護兩套「到底允不允許段末簡註」的標準。
4. **修復 `AUDIT_PROMPT` 與 `mk_audit_materials` 的線索斷鏈**：
   既然不希望審核被裁決的「結論」帶偏，但又想讓它省掉重複檢索的錢，可以在 `mk_audit_materials.py` 用正則只從 `_why` 裡把 `《書名》卷X` 抽出來附在參考欄裡（例如：`採乙（線索：《業疏記》卷上）`），或者乾脆把 `AUDIT_PROMPT` 裡「援引裁決所註書名卷次」那半句刪掉，讓提示詞與程式實際輸入完全一致。
