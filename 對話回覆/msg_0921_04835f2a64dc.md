### 一、建議立刻修的程式 Bug（實質會誤判或印錯）

#### 1. `materials_io.py` `_looks_empty()` 的判斷順序寫反了（會把 `PASS` 誤判成 `FIX`）
* **位置**：`materials_io.py` 第 103–110 行
* **原因**：
  ```python
  if any(w in s for w in ('須', '應', '補', '刪', '改', '修', '缺', '漏', '誤', '錯')):
      return False
  return s.startswith(('無', ..., '無必改', '無需修改', '正確無誤')) and len(s) <= 40
  ```
  因為 `'改'`、`'修'`、`'誤'`、`'須'` 先被 `any()` 攔截，如果審核模型在【必改硬傷】寫了「**無需修改**」「**無必改**」「**無須修改**」「**正確無誤**」，程式會**在第一關就直接 `return False`**，永遠走不到下面那行白名單，導致 `verdict()` 強行把 `PASS` 翻盤成 `FIX`！
* **修法**：把明確否定/無誤的整詞判斷移到 `any(...)` **之前**（例如先判斷 `if re.fullmatch(r'(?:均|皆|並|悉|經核)?(?:無|沒有|暫無|未見|未發現)(?:任何)?(?:硬傷|問題|必改|錯誤)?[。.]?|(?:無[須需]修改|正確無誤)[。.]?', s): return True`）。

#### 2. `materials_io.py` `is_keep_a()` 的 `沿用` 門檻放太寬（可能誤殺真實譯文）
* **位置**：`materials_io.py` 第 90 行
* **原因**：新版加了：
  `if len(s) <= 120 and ('譯本甲' in s and (...) or s.startswith('沿用')): return True`
  如果遇到一段沒有段標籤（或已被剝掉標籤）的短白話譯文，開頭剛好是「**沿用舊有的制度即可，不須另作羯磨……**」（120 字以內），會被誤判成 `PASS_A_KEEP_A`，把原本 `REVISED` 的新譯直接丟掉換回甲。
* **修法**：放寬到 120 字時應限定**必須同時提到「甲」或「譯本甲」**；純 `s.startswith('沿用')` 維持原本的極短字串判斷即可（如 `s in ('沿用', '沿用甲', '沿用譯本甲', '沿用甲譯')`）。

#### 3. `qwen_local.py` 自動拆書名放寬時的兩個小 Bug
* **位置**：`qwen_local.py` 第 183–201 行
* **問題 A（第 186–187 行）**：
  ```python
  _hits_pre = 0
  hits = _filter_own(_LC.find(_core, None, rows, pad=240, ctx_book=_cur_book))
  if not hits:
      _self_only = True
  ```
  ` _hits_pre` 寫死 `0` 卻沒拿來判斷，導致即使全庫根本查無 `_core`（`_LC.find` 回傳空），也會把 `_self_only` 設為 `True`，誤告訴模型「僅本段／本注自身命中」。應改為先存 `_raw3 = _LC.find(...)`，檢查 `if _raw3 and not hits: _self_only = True`。
* **問題 B（第 199–201 行）**：
  從第 189 行（`_split_work` 觸發放寬）走進來時，原本的 `work` 是 `None`，結果第 201 行會印出：`「原指定《None》查無，已改從全庫查得…」`。應改為 `% (work or _aw)`。

#### 4. `qc_scan.py` 新增檢查的三處假警報
* **位置**：`qc_scan.py` 第 55、61、73 行
* **問題 A（第 55 行）**：你在 `STYLE_SPEC` 第 2 條剛補上「**惟校勘異文（如 `〔一本作X〕`、〔補：X〕、〔疑作X〕）保留〔〕原貌**」，`qc_scan.py` 拿掉了 `補[：:]`，但第 55 行裡面**還留著 `一本`**（`他本|一本`），模型照規矩保留 `〔一本作X〕` 還是會被掃出警告。
* **問題 B（第 61–65 行）**：檢查 `《成實論》《優婆塞戒經》《毘尼母經》` 等全稱時，**沒先比對原文 `src`**。道宣偶爾在原文自己就會寫出全稱（如《成實論》《毘尼母經》），不加 `and _full not in src` 會產生大量誤報。
* **問題 C（第 73 行）**：你把 `尽、乐、复、并、当` 加進 `qc_scan.py` 的簡體字警報，但 **`norm.py` 的 `SIMP` 沒加這幾個字**（其中 `('乐', '樂')` 與 `('尽', '盡')` 若非引文幾乎無歧義可加進 `norm.py`；而 `并` 在律典史料偶見於「并州」地名，放在 `qc_scan` 人工覆核倒很安全）。

### 二、剩餘的小錯位與提示詞收尾（低風險、順手清掉）

#### 5. `mk_review_materials.py` 第 253 行漏傳 `book` 給 `get_prompt`
* **位置**：`mk_review_materials.py` 第 83、253 行
* **問題**：`emit()` 在處理配對組時呼叫 `get_prompt(False)`，沒把 `book` 傳進去，導致跑《戒疏》一審（或用它產《戒疏》底材料時），提示詞會吃到預設的 `SHUJI_CTX_YS`（《隨機羯磨》）而非 `SHUJI_CTX_JX`（《含注戒本》）。把 `get_prompt(False, book or '')` 接上去就解決了。

#### 6. `業疏／戒疏` 單邊純【律文】【註文】【序文】的空白括號
* **位置**：`mk_judge_materials.py` 第 154 行、`mk_audit_materials.py` 第 143 行、`mk_revise_materials.py` 第 218 行
* **問題**：設成 `note = ''` 後，組出來的提示詞會變成：
  * 裁決：`### 原則（）`
  * 審核：`### 檢核（；只抓實質錯誤，不挑純修辭）`
  * 修訂：`（本段所屬：）`
* **修法**：設為 `note = '%s單欄原文' % book`（或直接 `book`）比空字串乾淨許多。

#### 7. `REVISE_PROMPT` 原則 4 與頂部 `STYLE_SPEC` 輕微打架＋重複
* **問題**：你把完整的 `{style_spec}` 放進 `REVISE_PROMPT` 最開頭了，這很好！但原則 4 下半段卻還保留著舊的縮寫版複述，結果兩處字面反而對不上：
  * 頂部 `STYLE_SPEC` 第 4 條剛改為：**「戒條標目開頭及行文中的戒名（如波羅夷）均不加引號」**
  * 底下 `REVISE_PROMPT` 原則 4 卻還寫著：**「戒條標目戒名不加引號」**（漏了「行文中的戒名」，且前面又漏了 `某某反`、`第X篇` 不加句號、`〔補：X〕`）。
* **修法**：既然 `{style_spec}` 已經在最上面了，原則 4 可以直接瘦身為一句指向，完全不會再不同步：
  > `4. **修訂護欄與自核**：僅就清單涉及之句套用上方【全書體例與格式規範】（未涉及之句照舊保留，勿借題擴改體例）。輸出前核對：未反轉施受或攝屬方向、未漏主賓與條件、未新增解說括號。`

#### 8. 最後確認一處無害小細節：`make_hybrid.py` / `mk_blind_materials.py` 的 `--force`
* `mk_blind_materials.py` 第 102 行改成了 `if os.path.exists(rp) and not args.force:`，這能防止強制重產材料後把舊回覆誤標成最新 hash，搭配 `make_hybrid.py` 後面自己重寫 `hybrid_keep` 並補算 `src_hash`，兩邊配合得很好。
