## 2. 每支腳本參數與輸出

### 2.1 `_src/mk_reaudit_materials.py`

從 `定稿/<book>.jsonl` 取 `segments` 作 parts（**不讀 `docs/`、舊材料、`AI語譯/out`**），依卷排序打包。

```text
python -X utf8 _src/mk_reaudit_materials.py --book 義鈔 --target-chars 20000 --check-raw
python -X utf8 _src/mk_reaudit_materials.py --book 業疏 --out 測試/重譯/業疏/_再審
python -X utf8 _src/mk_reaudit_materials.py --book 業疏 --check-raw --dry-run
```

| 參數 | 預設 | 說明 |
|:--|:--|:--|
| `--book` | `業疏` | 六書之一：行事鈔／戒疏／業疏／尼鈔／義鈔／資持記 |
| `--target-chars` | `20000` | 每檔目標字數；預設計**整份 `.md`** |
| `--count-mode` | `md` | `md`＝整份材料（預設）、`body`＝原文＋現譯、`source`＝僅原文 |
| `--group-by` | `vol` | 不跨的層級：`vol`＝卷（預設）、`chunk`＝分卷 chunk |
| `--out` | `測試/重譯/<book>/_再審` | 輸出目錄；`--dry-run` 可省略 |
| `--check-raw` | off | 逐單位驗 `source == 底本 raw[a:b]`，並出 `_原文核驗.md` |
| `--gap-mode` | `cut` | 正文缺口：`cut` 切檔／`note` 加禁止代譯提示／`off` 不處理 |
| `--gap-min` | `20` | 缺口判定門檻（漢字） |
| `--limit` | `0` | 只輸出前 N 檔（試跑） |
| `--dry-run` | off | 只統計，不寫檔 |
| `--force` | off | 允許覆寫既有材料（有回覆時預設中止） |

輸出（每檔一組）：

```text
<book_id>_r0001.md     提示詞＋背景＋逐段原文／現譯
<book_id>_r0001.json   idx/key/chunk/vol/raw_start/raw_end/labs/parts/src_hash/hash …
索引.json              全書包清單與統計
_原文核驗.md           只有 --check-raw 時產生
```

材料格式（與 AGENTS §7A.4 一致）：

```markdown
### [01]（key: 01a_卷一之一_0012）
■ 疏文（原文）[01]
……
■ 疏文（現譯）[01]
……
■ 記文（原文）[01]
……
■ 記文（現譯）[01]
……
```

實作要點：

- **單位原子化**：一個 `定稿` unit（含疏＋記 parts）不切、不合併；單一超長 unit 自成一檔。
- **不跨卷**：`vol` 邊界一定切檔；`--group-by chunk` 可鎖到 chunk（見 §4 待決）。
- **20K 預算**：`md` 模式以實際 render 長度貪婪裝箱，硬上限 `target × 1.02`（20,000→20,400）；`--count-mode body` 則以原文＋現譯計量。
- **背景**：前文背景＝前接原文 ≤1500 字＋前鄰現譯 ≤400 字；後文背景＝後接原文 ≤600 字＋後鄰現譯 ≤300 字；皆不跨卷。
- **正文缺口**：缺口落在兩單位間→預設切檔；落在段內或同卷兩側是缺口填補單位（GAP／JE 等）→加【正文缺口提示】禁止代譯。同卷 `raw_start` 非單調 >5% 的書（目前戒疏）自動停用 gap 切檔，避免假缺口切出碎片檔。
- **資持記所釋鈔文**：以 `mother_corpus.chao_for_units()` 取，`≤2500` 字；`mother_corpus._seq_json()` 原本每次重讀 6.4MB JSON，本腳本只在同一行程快取一次（未改來源檔）。
- **定稿殘留**：parts 原文／現譯若含 `【後文背景…】`、`【必改硬傷】`、行首 `■`／`###` 等材料殘留，逐字照錄並加〔定稿殘留〕標記與【定稿殘留提示】，不刪改。

### 2.2 `_src/split_reaudit.py`

```text
python -X utf8 _src/split_reaudit.py --book 義鈔 --bisect
python -X utf8 _src/split_reaudit.py --materials 測試/重譯/業疏/_再審
```

| 參數 | 預設 | 說明 |
|:--|:--|:--|
| `--materials` | `測試/重譯/<book>/_再審` | 材料目錄（`<key>.json`＋`回覆/`） |
| `--book` | 空 | 決定預設材料目錄；同時過濾該書 |
| `--out` | 同 `--materials` | 計畫輸出目錄 |
| `--plan-name` | `_再審拆回_計畫.json` | 計畫檔名 |
| `--bisect` | off | 異常檔自動對半切 |
| `--bisect-out` | `<materials>/_bisect` | 切半材料輸出 |
| `--min-units` | `2` | 可切半的最少單位數 |
| `--dry-run` | off | 只檢查，不改名、不寫檔 |

驗證與拆回規則：

1. 回覆必須有【分段核驗表】，且 `[01]..[N]` 全部到齊；支援 `[01]`、`[1]`、`[01-03]`、`[01]–[03]`。
2. 以下一律判異常：`_400審查.txt` 存在、只有 `_截斷.txt`、缺核驗表、漏號、編號越界、缺【必改硬傷】、引號／括號未成對（疑截斷）、硬傷段號越界或未標段號。
3. 異常處理：原回覆改名（或改寫）為 `<key>_異常.txt`（含異常原因標頭），並記入 `_異常清單.log`；不計入 FIX／PASS。若 `<key>_異常.txt` 已存在而回覆未重跑，回報「先前異常，尚未重跑」，不會誤判成待跑。
4. FIX 拆回：【必改硬傷】逐項以行首 `[n]` 對回該包第 n 個單位（支援 `- [n]`、`**[n]**`、續行 `問題／依據／修正方向`）；同一單位多項合併。未被點名的單位全部 PASS。
5. `--bisect`：把異常包依單位數對半切成 `<parent>_b1`／`_b2`（各自重算背景、缺口、md/json，`parent`／`part` 記錄來源），供補跑。切半不呼叫 qwen。

輸出：

```text
_再審拆回_計畫.json {
  generated, materials, book,
  packs{key:{units,covered,fix,pass,status,reason}},
  fix{unit_key:{pack,no,items:[{n,text}]}},
  pass[unit_key…],
  abnormal{pack:reason}, pending[pack…],
  bisect[{parent,reason,children}], bisect_skipped[pack…],
  stats{packs,ok,abnormal,pending,units_fix,units_pass,fix_ratio}
}
_異常清單.log       key<TAB>reason
_bisect/*.md/.json  切半材料
```

### 2.3 `_src/mk_rerevise_materials.py`

```text
python -X utf8 _src/mk_rerevise_materials.py --book 義鈔
python -X utf8 _src/mk_rerevise_materials.py --materials …/_再審 --out …/_再審修訂
```

| 參數 | 預設 | 說明 |
|:--|:--|:--|
| `--book` | 空 | 決定 `--materials`／`--out` 預設 |
| `--materials` | `測試/重譯/<book>/_再審` | 再審材料目錄 |
| `--plan` | `<materials>/_再審拆回_計畫.json` | 拆回計畫 |
| `--out` | `測試/重譯/<book>/_再審修訂` | 修訂材料輸出（回覆放 `<out>/回覆/`） |
| `--max-evidence` | `2200` | 檢索摘錄字數上限 |
| `--no-evidence` | off | 不附摘錄 |
| `--force` | off | 允許覆寫既有材料／回覆 |
| `--dry-run` | off | 只統計 |

只處理計畫中的 FIX 單位，每單位一份 `<unit_key>.md`＋`.json`。材料內含：

- 【原文】逐段（疏＋記不拆，含〔定稿殘留〕標記）。
- 【目前譯文】逐段標籤（輸出格式即依此標籤）。
- 前後原文（前 ≤1500、後 ≤600 字）與前後鄰既有譯文（前 ≤400、後 ≤300 字）；單位在包首／包尾時沿用包背景。
- 【跨段統一基準】：段別與體例底線、前後鄰單位、**鄰段共用譯詞表**（2–4 字詞，需出現在原文或兩側鄰譯；避開《》／「」整句與純虛詞，最多 12 列，附前後鄰片段）、以及**硬傷所涉原詞在鄰段的用法**（最多 6 列）。
- 【必改硬傷】：該單位全部項目。
- 【初審檢索摘錄】：讀 `<materials>/回覆/<pack>_evid.json`，用 `mk_revise_materials.evidence_block()` 依硬傷引號／依據／書名打分過濾（網搜優先、上限 2200 字），無相關證據則整段省略。

### 2.4 `_src/apply_reaudit.py`

```text
python -X utf8 _src/apply_reaudit.py --book 義鈔 --dry-run
python -X utf8 _src/apply_reaudit.py --book 義鈔 --out 定稿_v2
```

| 參數 | 預設 | 說明 |
|:--|:--|:--|
| `--book` | 必填 | 決定 `定稿/<book_id>.jsonl` |
| `--materials` | `測試/重譯/<book>/_再審` | 再審材料（用來比對材料是否過期） |
| `--plan` | `<materials>/_再審拆回_計畫.json` | FIX 計畫 |
| `--revise` | `測試/重譯/<book>/_再審修訂` | 單段修訂材料（回覆在 `回覆/`） |
| `--out` | `定稿_v2` | 輸出目錄；寫入前擋掉 `定稿/`、`docs/` |
| `--out-name` | `<book_id>.jsonl` | 輸出檔名 |
| `--report` | `<out>/_再審變更對照.md` | 對照報告 |
| `--max-ratio`／`--min-ratio` | `1.8`／`0.55` | 幅度警報上下限 |
| `--strict-qc` | off | QC／幅度任一警示即退回不套用 |
| `--dry-run` | off | 只驗證與統計 |
| `--force` | off | 允許覆寫既有輸出 |

套用規則：

1. 未列 FIX 的單位逐筆原樣輸出（同順序、同欄位）。
2. FIX 單位先驗 **材料 vs 現定稿**（`src_hash`、逐 parts 原文／現譯）；定稿在材料產出後被改就退回，不覆蓋。
3. 回覆須逐段標籤且與 parts 數量／順序一致；不符即退回（不會猜段）。
4. 套用 `norm.normalize()`（逐段、`src=` 該段原文；去尾端換行）。
5. `qc_scan` 同構掃描：引號／括號成對、空括號、異體字、簡體字、網址、數字條列、工具字面、重複標籤、殘留背景／材料標記、引號內半文半白、縮水／膨脹、自加解說括號等。
6. `source == raw`：以 `TXT_句讀校定/<book>.txt` 漢字流比對 unit source；不符即退回。資持記無可用底本 → 標「raw 未驗（無底本）」不阻擋。
7. 幅度＝新譯漢字／原譯漢字；超出上下限只警示（`--strict-qc` 才退回）。
8. 重建 unit `translation` 時保留原拼法：逐段標籤者維持逐段、`【lab】` 前綴者保留前綴與換行、無標籤者以空行接回；`segments[i].translation` 同步更新，`revised=true`。

輸出：`<out>/<book_id>.jsonl`、`<out>/_再審變更對照.md`（套用明細、退回原因、待修、計畫內查無）。

## 3. 與現有欄位／資料不相容處

1. **同一 `translation` 有三種拼法**：`【lab】`＋join（如 `yeshu/00_卷首_0002`）、逐段標籤（如 `yeshu/01a_卷一之一_0011`）、完全無標籤（如 `jieshu/01a_卷一上之一_0007` 的兩段）。
   → 新材料一律以 `segments[]` 為 parts 來源；`apply` 依原字串判斷拼法並保留，不加新風格。
2. **jieshu 的 parts 拼接 ≠ unit source**（快照 643／4,566）：parts 常多出 `【凡例】`／`【目錄】` 前綴或前後位移。材料以 parts 原文為準（那是譯文實際對應的原文）；raw part 定位退化成搜尋／估位，列在 `_原文核驗.md`。
3. **jieshu 的 `raw_start` 同卷順序可疑 1,223／4,566**（例：`03b_卷一下之一_0141` 的 raw 位置落在卷首區）。排序改用 key（卷＋chunk＋序號），raw 只用來切缺口；此書 gap 切檔自動停用（>5% 門檻），否則會切出大量假缺口碎片檔。
4. **資持記沒有可驗底本**：`定稿/zhichi.jsonl` 的 raw 位移與 `TXT_句讀校定/zhichi.txt` 不同制（逐筆比對 0／4,182 相符），`_src/_src_資持記.txt` 亦不同制。故 `--check-raw` 對此書只出「unavailable」，`apply` 不擋；需人工決定是否另建底本。
5. **`定稿/索引.json` 與實際 jsonl 不一致**：索引寫 行事鈔 1,441、戒疏 4,637、業疏 2,580、尼鈔 774、義鈔 207，且無資持記；09:41 實際為 2,142／4,566／2,728／1,100／509／4,182。本流程一律以 jsonl 實際筆數為準，不讀索引。
6. **`mk_review_materials.py` 的 `.json` 欄位不相容**：該腳本用 `units[].orig`／`units[].tr`、`pre`／`post` 單一字串；本流程用 `units[].parts[]`（lab／orig／tr／hash／raw 區間）＋`pre_src`／`pre_tr`／`post_src`／`post_tr`。未硬改來源，兩套並存。
7. **`materials_io.SRC_RE`／`TR_RE` 不適用**：`（原文）[n]` 可抓，但 `（現譯）[n]` 的 `[n]` 不在其 pattern 內，且它假設 `（現譯）` 後只有一段。新流程以 `<key>.json` 為契約，不呼叫 `MI.parse_md()`。
8. **`qc_scan.py` 只有 CLI**（`--materials`＋`--finals` 目錄），沒有可 import 的逐段檢查函式。`apply_reaudit` 匯入其 `BAD_VAR`／`HAN` 常數並在 `_qc()` 重現同一組規則；未改 `qc_scan.py`。
9. **`norm.normalize()` 的行為**：會剝 markdown、移除網址、補尾端 `\n`、依文字內標籤推斷 `_lab`，且把 `【修訂譯文】` 之類改成推斷標籤。本流程逐段、去標籤後才 normalize，再 strip 尾端換行。
10. **沒有既存 20K 格式**：舊 `校閱_10K`／`校閱_20K` 是另一套（byte 計、`【原文】／【譯文】`、`qwen_review.py` 讀 `# 材料開始`）；本流程依 AGENTS §7A 新格式，兩者不相容。
11. **`mk_revise_materials.py` 的契約是 `<r1>/回覆`＋`<audit>/回覆` 的逐單位 `_回.txt`**；本流程以 `_再審拆回_計畫.json` 為契約，不產逐單位 `_回.txt`（若要接舊工具需另寫轉接）。
12. **定稿本身仍有材料殘留**（09:41 快照：業疏 1 筆、資持記 6 筆；09:20 前義鈔曾見 142 筆，09:41 已為 0，期間定稿被更新）：材料逐字照錄並標記，交由再審判定；`apply` 的 QC 會把「殘留材料區塊標記」列為警示。
13. **`mother_corpus._seq_json()` 每次呼叫重讀 6.4MB JSON**：本流程在 `mk_reaudit_materials` 內以一次性快取包裝（只改執行期行為，不改來源檔）；資持記 141 檔若逐段直呼會非常慢。

## 4. 尚未實作或需人工決定的地方

1. **`--group-by` 預設 `vol` 與 AGENTS §7A.2「不跨卷（chunk）」的取捨**：兩者衝突。

   - 依 `chunk`：義鈔 26 檔（8 檔出 19–20.5K）、戒疏 177 檔（**85 檔出界**、最小 md 4,575）、且 jieshu 74 個 chunk 有 5 個 body <8K。
   → 目前預設 `vol`（符合本次指示「不跨卷」），`chunk` 可由參數開啟；請決定是否改以 chunk 為硬邊界並放寬 19K 下限。
2. **20K 整份 md vs「待審原文＋現譯 11.5K–14K」**：快照待審中位 10.9K（資持記）～13.5K（義鈔），義鈔略高於 14K 上限；若要嚴格落區間，需把 target 調到約 19.6K 或改以 body 計量。
3. **尾包偏小**：卷界與單一超長 unit 會留下小檔（快照最小 md：行事鈔 5,278、戒疏 5,500、義鈔 10,188）。目前不做前後包平衡；是否允許尾包 <19K 需決定。
4. **切半後的結果併回**：`--bisect` 只產 `_b1`／`_b2` 材料與計畫紀錄，未自動把子女的 FIX 併回父包計畫。單位 key 不變，可用人工 union；若要自動併，需設計合併步驟。
5. **正文／非正文缺口分類**只做字面啟發（`NONBODY_HINTS`），不是權威分類；戒疏因 raw 不可靠已停用 gap 切檔。非正文缺口是否要跳過切檔需人工確認。
6. **資持記 raw 驗證**：若要求 `source == raw：0 錯`，必須先給出可對應的底本；否則此書只能維持「unavailable」。
7. **`apply` 沒有自動重送**：缺修訂回覆＝待修、格式不符＝退回；都不會自動呼叫 qwen 或重試（符合本輪「不跑 qwen」）。
8. **`--strict-qc` 把幅度也視為阻擋條件**（`flags` 同時含 QC 與幅度）。若要把「幅度」只當警示，需拆兩級旗標。
9. **`_異常.txt` 的生命週期**：回覆重跑成功後，舊 `_異常.txt` 不會自動刪除；`split` 見到回覆即忽略它，但檔案會殘留。是否自動清理需決定。
10. **未附測試檔**：本輪以離線合成回覆驗證（見 §5），沒有把測試資料留在專案內。
11. **qwen 未跑**：`QWEN_*` 環境、`qwen_local.py` 的 `SRC_RE_ALL`（只抓 `（原文）`）與材料格式已對齊，但實際跑批、漏號率、實際 FIX 比例、成本都未驗證。
