### 一、新改動引入的 2 個確定性 Bug（建議立刻修）

#### 1. `materials_io.py` 的 `verdict()` 否定字檢查順序顛倒 ＋ `mk_revise_materials.py` 遇 `ERROR` 會當機
這兩支腳本的新防呆湊在一起會出問題：
* **`verdict()` 誤判 `FIX`**：
  新增的 `_looks_empty(s)` 先檢查：
  ```python
  if any(w in s for w in ('須', '應', '補', '刪', '改', '修', '缺', '漏', '誤', '錯')):
      return False
  return s.startswith(('無', ..., '無必改', '無需修改', '正確無誤')) and len(s) <= 40
  ```
  因為 `'無必改'` 含 `改`、`'無需修改'` 含 `修/改`、`'正確無誤'` 含 `誤`，只要審核模型在 `【必改硬傷】` 寫了 `無必改硬傷`、`無須修改`、`經核無誤`、`無任何錯誤`，就會在前面提前 `return False`，**後面那串 `startswith` 根本執行不到**，進而把 `PASS` 反判成 `FIX`（連帶 `m2` 分支也會誤判）。
  * **修法**：先把 `無需修改／無須修改／無必改／無硬傷／無誤／無錯／正確無誤` 等明確否定空值判斷放在 `any(w in s ...)` **之前**。
* **`mk_revise_materials.py` 會 `KeyError` 當機**：
  `verdict()` 現在可能回傳 `'ERROR'`，但 `mk_revise_materials.py` 第 147 行仍是：
  ```python
  plan = {'FIX': [], 'PASS': []}
  ...
  plan[v].append(key)   # 若 v == 'ERROR'，直接 KeyError 崩潰
  ```
  * **修法**：`plan` 補上 `'ERROR': []`，遇到 `'ERROR'` 時印出警告（或於結束時 `raise SystemExit(1)` 阻斷），不要直接崩潰。

#### 2. `mk_review_materials.py`：《戒疏》雙欄組仍會吃到《業疏》的提示詞
* **位置**：`mk_review_materials.py` 第 222 行 `emit()`：
  ```python
  body_prompt = (get_prompt(False) if (unit == '疏文' and g1 > g0)
                 else prompt_for(unit, book or ''))
  ```
* **原因**：雖然你已在 `book_config.py` 把 `SHUJI_CTX_YS`（業疏／隨機羯磨）與 `SHUJI_CTX_JX`（戒疏／含注戒本）分開，但 `emit()` 在配對的 `疏文+記文` 組別仍呼叫無參數的 `get_prompt(False)`，而 `get_prompt(False)` 呼叫 `_shuji_prompt(['疏文', '記文'])` 時未傳 `book`，預設退回 `業疏`。
* **結果**：用 `mk_review_materials.py` 產生《戒疏》配對組（含一審或 legacy 對照）時，第 2 條依然寫成「《業疏》所釋『文／注』指《隨機羯磨》」（盲翻／裁決／審核／修訂四關主線不受影響）。
* **修法**：改為 `_shuji_prompt(['疏文', '記文'], book or '')` 即可。

### 二、4 個小邊界與細節

#### 3. `pack_final.py` 未攔截「終審缺回覆」，以及 `build_a2.py` 對無標籤打包段的遺漏
* **`pack_final.py`**：當同時傳入 `--revise` 與 `--audit` 時，`elif au:` 只檢查 `os.path.exists(_ap) and MI.verdict(...) in ('FIX', 'ERROR')`。若某份包**終審回覆 `_ap` 根本不存在**（漏跑或失敗），`os.path.exists(_ap)` 為 `False`，程式會直接跳過保護，把未經終審的 `【待審譯文】` 寫進定稿（不像 `build_a2.py` 會記進 `unaudited` 並中止）。建議比照 `build_a2.py`，缺 `_ap` 時記入錯誤並攔截。
* **`build_a2.py`**：單欄打包段（`len(_labs_exp) == 1`）若修訂回覆有 `【修正後的譯文】` 但漏寫開頭的 `【鈔文】`，此時 `_got` 為空集合 `set()`，新加的 `elif _got:` 不會觸發，`_lack` 為 `[]`，仍會輸出少掉 `【鈔文】` 標籤的 `.txt`。建議若 `not _got and len(_labs_exp) == 1`，直接替 `txt` 補上 `'【%s】\n' % next(iter(_labs_exp))`。

#### 4. `qwen_local.py`：兩處提示訊息與 `STOP` 檔小瑕疵
* **`_split_work` 放寬時的誤報訊息**：在 `if not hits and not work:` 分支中：
  1. 若搜得結果，`relaxed = True` 會進到 `payload['note'] = '原指定《%s》查無...' % work`，因為此時 `work` 是 `None`，模型會看到 **`原指定《None》查無`**（應改為 `work or _aw`）。
  2. 若 `_LC.find(_core, None, ...)` 原本就回傳 0 筆（全庫真查無），因為前一行寫死 `_hits_pre = 0` 且下面直接 `if not hits: _self_only = True`，會誤告訴模型「僅本段／本注自身命中，無他處平行文」。應該只有在「`_filter_own` 前有命中、過濾後歸零」時才設 `_self_only = True`。
* **`STOP_GLOBAL` 轉寫本地 `STOP`**：當你放了 `B/STOP`（全局停止）而 `_ds_post()` 拋出 `FatalAPIError('STOP')` 時，`except` 區塊會順手在該批次目錄也寫一個 `SRC/STOP`。若後續你只手動刪了 `B/STOP` 而非跑 `stop_all.py --clear`，該批次會因為殘留 `SRC/STOP` 而起不來；其實此時 `_stop_requested()` 本來就為真，不必再多寫一次 `STOP`。

#### 5. `materials_io.py` 的 `is_keep_a()` 過寬風險
* 新增的這行：
  ```python
  if len(s) <= 120 and ('譯本甲' in s and (...) or s.startswith('沿用')):
  ```
  如果某段沒有帶 `【】` 標籤、長度 ≤120 字的真實白話譯文剛好以「沿用……」開頭（例如：「沿用過去舊有的做法……」，這在律疏討論舊制時有可能出現），`s.startswith('沿用')` 會把它誤認成 `PASS_A_KEEP_A`。加上 `and not re.search(r'【(?:疏文|記文|鈔文|律文|註文|序文)】', s)`，並將無「譯本甲」字樣時的 `s.startswith('沿用')` 限縮在較短長度（如 `<= 30` 字）或不含句中展開內容，就能徹底避免誤判。

#### 6. `qc_scan.py` 的簡繁與全稱比對微調
* **全稱展開誤報**：`《優婆塞戒經》`、`《成實論》`、`《毘尼母經》` 在道宣原文裡有時本來就會寫全稱；`if _full in out:` 沒比對原文，建議改為 `if _full in out and _full not in src:`。
* **簡繁字表落差**：`qc_scan.py` 的 `_bad` 含有 `'并'`（但繁體正字本來就有「并州」「兼并」「歸并」）、`'复'`（`norm.py` 刻意不轉以免傷及合法字）、以及 `'尽'`、`'乐'`、`'当'`（`norm.py` 的 `SIMP` 沒收這 3 字，所以 LLM 若寫出「尽」「乐」「当」，`norm.py` 不會幫轉，然後 `qc_scan` 會報警）。建議在 `norm.py` 補上 `('尽', '盡'), ('乐', '樂'), ('当', '當')`，並從 `qc_scan.py` 的 `_bad` 移除繁體本字 `'并'`（或只針對真正簡體字檢查）。
