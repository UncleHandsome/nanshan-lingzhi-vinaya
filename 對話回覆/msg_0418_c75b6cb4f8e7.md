### 一、`pack_judge.py`（裁前打包）與 `[n]` 錨點的漏網 Bug

1. **模型漏寫 `【標籤】` 時，會「靜默寫出空白」而非「拆回失敗」**
   - `do_split` 中若模型第 3 欄忘記寫 `【疏文】`／`【鈔文】`（`len(secs) < 3`），`lab_map` 會變成 `{'_head': body3}`，接著 `per_group[i]` 會收到 `[('_head', 譯文)]`。
   - 問題在最後寫檔判斷：
     ```python
     body = '\n\n'.join('【%s】\n%s' % (lab, val) for lab, val in segs if lab != '_head')
     if not segs:
         body = '（拆回失敗）'
     ```
     因為 `segs` 非空，`if not segs` 不會觸發；但 `lab != '_head'` 又把內容全濾光，結果**寫出一個完全空白的第 3 欄**，也沒有任何錯誤提示。

2. **`LBL_RE` 與 `materials_io.from_jia()` 的截斷隱患**
   - `pack_judge.py` 的 `LBL_RE` 和 `materials_io.from_jia()` 都用 `(?=\n+■ |\n+【|\Z)` 當結束邊界。
   - 若某段原文或譯文裡剛好有換行後接 `【…】`（例如原文／舊譯帶 `【按】`、`【科】`、`【問】` 或殘留內文小標），正則會在該處直接截斷，丟失後半段內容（`mk_judge_materials.py` 用的是較安全的 `(?=\n+■ |\n+【後文背景|\Z)`）。

3. **打包組的檢查沒接上 `AUDIT_PROMPT`**
   - `mk_audit_materials.py` 雖在打包材料加上 `【分段要求】保留 [1][2]…`，但擺在 `【待審譯文】` 之後，且 **`AUDIT_PROMPT` 完全沒要求核對 `[1][2]…` 條數與編號是否完整**。若裁決不小心併段或漏號，終審很容易直接放過，直到最後 `split_pack.py` 才會發現段數不合。

4. **正文若有 `[數字]` 會切壞 `do_split`**
   - `do_split` 用 `re.split(r'\[\s*(\d+)\s*\]', chunk)` 拆段。只要譯文裡面（或校注、序號）出現 `[1]`、`[2]`，就會誤切成新的一段並覆蓋或錯位。

### 二、`qwen_local.py` 與提示詞配合上的問題

1. **打包組的檢索配額被變相稀釋**
   - `qwen_local.py` 的 `_local_cap` 與 `_quota` 只算 `原文` 總漢字數。`pack_judge` 把 up to 6 個彼此獨立的短段湊成 ≤300 字，整包加起來依然只有 **3 次本地檢索＋2 次網搜**，平均每段不到 0.5 次；若同包內有 4 段各帶不同名相／科判疑點，模型很快就會撞牆。

2. **自搜過濾在有標點文本幾乎失效，且被濾掉會白扣額度**
   - `qwen_local.py` 過濾自身段落時，`own` 做了去標點＋`VAR_MAP` 異體正規化，但比對對象 `_ht` 只做 `re.sub(r'[\s　]', '', ...)`（**保留標點且沒做異體正規化**）。像《業疏》《資持記》本身帶標點，`own[:20] in _ht` 幾乎永遠不成立。
   - 在 `pack_judge` 打包檔中，`own[:20]` 更只抓得到第 1 段的開頭 20 字，第 2–6 段完全不會被過濾。
   - 此外，`if not hits:` 免扣額度寫在自搜過濾**之前**，若搜到 1 筆剛好是自己原文而被濾成 0 筆，模型拿不到結果卻依然會被扣 1 次額度。

3. **Markdown 程式碼圍欄（```` ``` ````）未清洗**
   - 裁決（或修訂）模型偶爾會把第 3 欄譯文包在 ```` ``` ```` 區塊裡輸出。`MI.is_keep_a()` 用 `.strip(' \t\r\n`*。.')` 碰巧能處理 `PASS_A_KEEP_A`，但 **`REVISED` 譯文進到 `col3` 與 `norm.py` 時都不會剝除 ```` ``` ````**，會直接殘留在定稿中。

### 三、提示詞與上下游規格的細部落差

1. **第 2 欄沒提示精要撰寫，容易觸發 1,200 字截斷**
   - `mk_audit_materials.py` 和 `mk_revise_materials.py` 的 `divergence(rt)` 都寫死 `return txt[:1200]`。
   - `JUDGE_PROMPT` 沒規範第 2 欄的精簡度（例如「每條裁決理由限 1～2 句簡述依據」），在長段或 `pack_judge` 6 段一包時，第 2 欄很容易超過 1,200 字，導致後面幾段的分歧紀錄在送給終審／修訂前就被硬生生切斷。

2. **相較 `BASE_PROMPT`／`AUDIT_PROMPT` 仍缺的幾條實戰規則**
   - **引文與著者評論界限**：`JUDGE_PROMPT` 只寫「斷句引文邊界」，沒明寫「勿混同所引經律與著者自語／評論」，遇甲乙一人譯成引文、一人譯成道宣口氣時缺乏判準。
   - **句尾虛字結上／領下**：這是 `BASE_PROMPT`、`BLIND_PROMPT`、`AUDIT_PROMPT` 三處都強調的高頻錯因（如「也／矣／故／若／則」斷錯導致因果轉折反轉），獨缺在 `JUDGE_PROMPT`。
   - **術語前後一致**：`BASE_PROMPT` 與 `AUDIT_PROMPT` 皆把「同一核心術語前後譯法不一」列為必改項，但 `JUDGE_PROMPT` 沒要求在合併甲乙兩譯時統一全段譯名（否則甲譯「僧伽」、乙譯「僧團」，裁決各取一半就會在終審直接被判 `FIX`）。

3. **兩個程式邊界小坑**
   - **`mk_judge_materials.py` 的 `book_of()` 預設值風險**：舊材料若無 `.json` 且資料夾路徑不含書名關鍵字，`book_of()` 會一律預設回傳 `'疏記'`，把《業疏》文注規則錯套給《資持記》或《行事鈔》。
   - **`build_a2.py` 讀 `PASS_A` 只讀前 400 字**：`_jt = io.open(bp, encoding='utf-8').read(400)`（不同於 `MI.verdict` 的 `[:4000]`），萬一模型在 `1. 結論` 前多加了開場說明，就可能超過 400 字而讀不到 `PASS_A`。
   - **提醒檢查 4.6 節的 `pack_audit.py`／`pack_final.py`（文件未列出原始碼）**：7.11 節紀錄只寫修補了 `mk_audit / mk_revise / build_a2` 三處對 `PASS_A_KEEP_A` 回填譯本甲；若 `pack_audit.py` 直接讀 `_裁決` 資料夾打包且還沒補上 `MI.is_keep_a()` ＋ `MI.from_jia()`，同樣會把 `PASS_A_KEEP_A` 字面送進打包審核。
