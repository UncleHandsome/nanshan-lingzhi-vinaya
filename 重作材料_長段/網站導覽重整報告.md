## 0. 結論

1. **首頁側欄收起來後找不到入口的死路已消除。** 全站 48 頁（首頁、搜尋、附錄、未譯、六書 16 頁、資持記 16 頁、合編 12 頁）現在都有同一個 sticky 頂部列，左側固定有「☰ 目錄」。首頁也不例外，而且首頁不再套用上次的收合狀態。
2. **頂部列加高到桌機 58px／手機 56px**（原本桌機沒有全域列，只有主文內約 30px 的 sticky 小工具列；手機列高 54px），桌機 sticky 實測捲到 1,500px 仍在 `top=0`。
3. **主要導覽不再需要反覆點按鈕。** 桌面側欄預設展開；視窗 ≤1100px 自動變抽屜；側欄收合後可靠**左緣 hover／focus 直接露出**（15px 邊緣條，不必先找按鈕），並保留頂部「☰ 目錄」、`[`、`Alt+M`、`Esc`。
4. **手機不再有第二排底部工具列。** 閱讀工具改成頂部列右側「閱讀工具」下拉面板；手機只有「頂部列＋抽屜」。
5. **驗收**：`validate_site.py` **0 errors**；pair **26,712**、search **26,687** 與重整前完全一致；Playwright desktop 1440／mobile 390 **125 項全部通過**，另做 320–1440 寬度掃描無水平溢出。

## 1. 問題與根因

### 1.1 首頁 `docs/index.html` 側欄收起來後沒有地方可以再打開

三個原因疊在一起：

| # | 根因 | 位置 |
|:--|:--|:--|
| A | 首頁由 `render_static.build_index()` 呼叫 `SA.page(..., tools=False)` 產生，因此頁面沒有 `.readtools`，也就沒有放在工具列裡的「☰ 目錄」。 | `_src/render_static.py`、`_src/site_assets.py` |
| B | 桌面唯一的「重新展開」控制 `.sideopen` 被 CSS `display:none !important` 鎖住；後面的 `body.nav-collapsed .sideopen{display:inline-flex}` 沒有 `!important`，永遠蓋不過。等於按鈕存在但**永遠看不見**。 | 舊 `_src/site.css` |
| C | 收合狀態存在 `localStorage`（`dsh-side-collapsed-v1`）且對所有頁面套用；首頁沒有工具列可再開，一進去就是收合狀態。 | 舊 `_src/nav.js` |

結果：使用者只要曾經在書頁按過「⟨」收合，首頁就變成「沒有側欄、也沒有任何可見入口」的頁面。

### 1.2 上方工具列太矮、桌機根本沒有全域工具列

- 舊 `.mobilebar` 只在 `max-width:1100px` 顯示，高度 54px；桌機沒有頂部列。
- 桌機唯一的橫向控制是 `main` 內的 `.readtools`（sticky、padding 很小，實測約 30px），且只存在於有 `tools=True` 的內容頁。
- 手機同時有固定頂欄（54px）與固定在底部的 `.readtools`（第二排），內容被 `padding-bottom:66px` 壓縮，且兩排控制重複。

### 1.3 每次都要點按鈕才能開合

- 只有「☰／⟨」手動開合，沒有 hover、沒有自動切換、沒有邊緣手勢。
- 收合後原本應由 `.sideopen` 接手，但它被 CSS 隱藏（見 1.1B），所以體感上「只能一直點，而且點完還可能打不開」。

## 2. 設計

### 2.1 全站單一 shell：`.topbar`

所有頁面（含首頁）都由 `site_assets.page()` 輸出同一個 `<header class="topbar">`：

```
┌──────────────────────────────────────────────────────────────────────┐
│ ☰ 目錄 │        南山律典 › 行事鈔 · 卷上        │ 閱讀工具  搜尋 │ 56/58px
└──────────────────────────────────────────────────────────────────────┘
```

- **左**：`☰ 目錄`（`#navtoggle`），永遠可見；`aria-expanded` 反映側欄是否可見。
- **中**：麵包屑「南山律典 › 書名略稱 · 卷名」；首頁為「南山律典 › 目錄」，搜尋／附錄／未譯為「南山律典 › 全文搜尋／附錄／未譯清單」。手機隱藏「南山律典 ›」只留「書名 · 卷名」。
- **右**：`閱讀工具`（只有內容頁有）＋`搜尋`。
- 高度：桌機 **58px**、手機 **56px**（≥ 52–56 的要求）；`position: sticky; top:0; z-index:90`。
- 深色模式沿用既有變數，實測頂部列底色 `rgb(30,29,27)`、按鈕前景 `rgb(230,226,218)`。

### 2.2 側欄狀態機（桌面 pinned／peek、手機 drawer）

| 視窗 | 狀態 | 表現 |
|:--|:--|:--|
| ≥1101px | **pinned（預設）** | 280px 固定側欄，`sticky top:58px`，內容在右 |
| ≥1101px | **collapsed** | 側欄寬 0；頂部 ☰ 變色；左緣出現 15px `.edgepeek` 條（含 5×72px 棕色握把） |
| ≥1101px | **peek** | 滑鼠移到左緣或 Tab 聚焦邊緣條 → 側欄以 fixed 浮層（280px、陰影）露出，**不推擠內容**；移開 180ms、按 Esc、點內容區即收起 |
| ≤1100px | **drawer** | 側欄固定在上方列之下（top 56px），預設 `transform:translateX(-105%)`＋`inert`；☰ 開啟、scrim 關閉、Esc 關閉、鎖背景捲動 |
| 任意 | **跨斷點** | resize 時自動切換：手機不保留桌面 pinned；回到桌面時恢復使用者的 pinned 偏好 |

- 偏好存 `localStorage["dsh-nav-side-v2"]`（`open`／`collapsed`）；舊的 `dsh-side-collapsed-v1` 直接忽略，不再沿用。
- **首頁強制 pinned**：`page-home` 一律展開，不讓舊狀態把首頁導覽鎖死。
- **collapsed 一定可逆**：即使其他頁面記住 collapsed，頂部「☰ 目錄」與左緣 `.edgepeek` 都固定可見；實測重新載入後仍可開。

### 2.3 減少點按鈕的實際路徑

| 情境 | 以前 | 現在 |
|:--|:--|:--|
| 一般桌機閱讀 | 側欄可能因舊狀態消失，要找回 | 預設展開，不用任何點擊 |
| 想暫時讓版面變寬 | 按 ⟨ 收合；要再開得找按鈕 | 按一次 ⟨ 或 `[`；要再開：滑鼠移到左緣、按 `[`／`Alt+M`、或頂部 ☰ |
| 視窗縮窄 | 需手動開抽屜 | 自動切成抽屜；☰ 或左緣（手機為 ☰）開啟 |
| 手機閱讀工具 | 底部固定第二排 | 頂部「工具」下拉，平時不佔高度 |

鍵盤：`[` 或 `Alt+M` 開合目錄、`Esc` 關閉（工具面板 → peek → 抽屜 → 篩選，依序）、`/` 聚焦目錄篩選、`Ctrl/⌘ K` 全文搜尋。側欄收合按鈕按下後會把焦點移到頂部 ☰。

### 2.4 閱讀工具改成頂部下拉

- 舊 `.readtools` 從 `<main>` 開頭移除，改成 `<header>` 內絕對定位的 `.toolpanel`（id=`toolpanel`），由「閱讀工具」按鈕開合。
- 內容：顯示模式（原文＋白話／只原文／只白話）、並排、複製本段連結。
- 手機：面板固定在頂部列下方，`left/right:8px`、`max-height:calc(100dvh - 56px - 20px)`、可捲動；不再有底部固定列，`body` 也不再 `padding-bottom:66px`。
- 面板開啟時點外面或按 Esc 關閉；切換模式不會關閉面板。

### 2.5 首頁與「不屬於任何書」的頁面側欄

- 首頁、搜尋、附錄、未譯的側欄改為**全部書目 → 卷**（7 本書的 `<details>`），不再隨便顯示第一本書（行事鈔）的卷／篇。
- 書頁仍維持「書目下拉＋卷／篇手風琴＋所在篇高亮」，行為不變。

### 2.6 無障礙與細節

- 頂部列 `header` landmark、skip link 保留、`main tabindex="-1"` 保留。
- 側欄開合同步 `aria-expanded`、`aria-hidden`、`inert`；抽屜開啟時焦點移到關閉鈕、焦點循環留在抽屜內。
- 所有可操作元素保留 `:focus-visible` 外框。
- 列印時隱藏 `.topbar`、`.edgepeek`、`.toolpanel`、`nav#sidebar`、`.pager`；實測 `display:none`。

## 5. 殘留風險

1. **`inert` 的瀏覽器支援**：側欄收合／抽屜關閉時靠 `inert`＋`aria-hidden` 擋焦點。`inert` 在 2023 年後的 Chrome／Edge／Safari／Firefox 都支援；更舊的瀏覽器會忽略，離屏連結仍可能被 Tab 聚焦（視覺上不會出現）。本專案未支援舊瀏覽器，若需要可再加 `tabindex=-1` 備援。
2. **peek 是覆蓋式浮層**：hover 左緣時側欄會蓋住內容左側（這是「不用推擠版面、不造成長頁 reflow」的取捨），移開即消失；鍵盤與點擊内容區都會收起。若使用者停在邊緣不動，側欄會維持露出直到移開。
3. **收合造成的單次 reflow**：桌機收合會讓正文由「側欄右側」變成整頁寬，戒疏／合編這種 1MB 級長頁會有一次性重排成本；不會在每次 hover 重排（peek 用 fixed 浮層）。
4. **未做 Firefox／Safari 實測**：本次以 Chrome 157 headless 量測；`100dvh`、`inert`、`position:sticky` 在現代版本皆支援，但行動 Safari 的動態網址列高度仍可能讓 `100dvh` 抽屜底部有 1–2px 差異。
5. **手機工具面板是覆蓋式下拉**：開啟時會蓋住正文最上方一小段（預期行為），關閉後即恢復；內容不會被永久壓縮。
6. **全域頁面的側欄不再顯示書目下拉**：搜尋／附錄／未譯／首頁改成「全部書目 → 卷」清單（比原本隨機顯示第一本書合理）；書頁仍維持原本的書目下拉與三層鑽取。
7. **截圖只涵蓋代表頁**：48 頁的 DOM／版本／錨點由 `validate_site.py` 全量檢查；視覺截圖取了 16 張代表頁。若要做像素級回歸，需另建 baseline。
