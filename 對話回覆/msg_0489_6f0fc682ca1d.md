### 1. `qwen_local.py` 跨書放寬搜尋幾乎必炸 `UnboundLocalError`
在 `local_search()`（第 161–180 行）：
```python
if _own and hits:
    _wins = [_own[i:i + 20] for i in range(0, max(1, len(_own) - 19), 20)]
    ...
if not hits and work:
    hits = _LC.find(query, None, rows)
    relaxed = True
    if _own and hits:
        for h in hits:
            if h.get('book') in ('濟緣記', ..., '南山律學辭典'): ...
            if any(w and w in _ht for w in _wins):  # ← 這行會直接炸掉
```
- **問題**：當模型指定 `work` 但首次搜尋回傳 `[]` 時，第一個 `if _own and hits:` 不會進去，**`_wins` 根本沒有被定義**；接著進入 `if not hits and work:` 改搜全庫並撈到結果，只要第一筆結果不在那 8 部科記／辭典白名單裡，執行 `for w in _wins` 就會直接拋出 `UnboundLocalError: cannot access local variable '_wins' where it is not associated with a value`。
- **影響**：文件強調的「指定 `work` 查無自動放寬改搜全庫」功能，在多數跨書查詢時會直接回傳「工具執行錯誤」並白扣額度。
- **附帶小漏洞**：`_wins` 切片步長是 `20`（非重疊切塊），39 字的原文只會取到前 20 字、後 19 字全漏，且跨第 20 字邊界的比對會全部失效（應改小步長如 `10` 並在函式前段先算好 `_wins`）。

### 2. `norm.py` 遇到雙層引號 `「……『……』……」` 會改壞原典後半段
在 `norm.py`（第 33–42 行）：
```python
_in = False
for _i in range(len(_parts)):
    if _parts[_i] in ('「', '『'):
        _in = True
    elif _parts[_i] in ('」', '』'):
        _in = False
    elif not _in:
        _parts[_i] = _parts[_i].translate(VAR_MAP)
```
- **問題**：所有提示詞都規定「引文用 `「」`、引文內再引文用 `『』`」。但這裡用布林旗標 `_in` 而非巢狀深度計數器：只要句中出現 `「……『甲』後半段」`，碰到內層的 `』` 時 `_in` 就會立刻被設回 `False`，導致外層引號裡的**「後半段」古典引文也被 `VAR_MAP` 當成白話正文改寫字形**（例如 `瞋→嗔`、`鉢→缽`）。
- **修法**：改用 `depth` 計數器（遇 `「`/`『` 加 1，遇 `」`/`』` 減 1 並以 `max(0, ...)` 保底，`depth == 0` 才做轉換）。

### 5. 工具 Schema 字數限制與提示詞自相矛盾
- `qwen_local.py` 的 `LOCAL_SCHEMAS` 寫 `'query': '3~10 字純原文核心詞'`；但 `SYSTEM_PROMPT` 又要求「短語查無時，改以空格分隔 2～3 個實詞」。
- 實務上 3 個律學實詞（如 `"沙彌尼 學法女 受大戒"`）加上空格常超過 10 字，Schema 的「3~10 字」容易讓模型為了湊短字數而把查詢詞砍得過碎或硬連成無空格短語。
