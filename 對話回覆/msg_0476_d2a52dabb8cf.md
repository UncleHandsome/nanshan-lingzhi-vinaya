### 一、致命級 Bug（會直接失敗、錯位或靜默遺失譯文）

#### 1. `run_pipeline.py` 的 `packjudge` 階段餵錯材料，會讓 `PASS_A` 整批被丟棄
在 `run_pipeline.py` 的 `elif st == 'packjudge':`：
- 它完全沒呼叫 `mk_judge_materials.py`，而是直接把**一審材料**（`測試/重譯/<書>/_材料`）丟給 `pack_judge.py`；而且也忽略了混合切法 `_材料_hy`／`_hy_盲翻`。
- 但 `pack_judge.py` 期待的是裁決材料（`JUDGE_PROMPT`＋`■ 疏文（譯本甲）／（譯本乙）`）。一審材料裡只有 `BASE_PROMPT` 和 `■ 疏文（現譯）`：
  1. 打包組裡 `v.get('譯本甲')`、`v.get('譯本乙')` 都是空的，送給模型的只有原文。
  2. 未打包的單組直接複製 `_材料/*.md`。拆回併入 `_裁決` 後送去終審 `mk_audit_materials.py`，只要遇到 `PASS_A_KEEP_A`，`MI.from_jia(t)` 找不到 `（譯本甲）` 就會回傳空字串，導致所有 `PASS_A` 被 `col3_safe` 當成異常檔略過。
- **修法**：`packjudge` 前必須先跑 `mk_judge_materials.py` 產出 `_裁決`，再以 `_裁決` 作為 `pack_judge.py --materials` 與 `--mat` 的來源。

#### 2. `pack_judge.py` 拆回邏輯會靜默吞掉修訂、打包相鄰檢查失效
1. **第 71 行雙反斜線正則失效**：
   ```python
   _na = re.search(r'(\\d+)$', it['key'])
   ```
   raw string 裡寫 `\\d` 只會匹配字面上的 `\d`，所以 `_na`/`_nb` 永遠是 `None`，`_gap` 永遠是 `False`。中間就算隔了被略過的 >500 字長段或雙欄段，前後兩段仍會被當成相鄰而硬包在一起，造成前段失去後文、後段失去前文。
2. **第 144–153 行 `if i not in _by_i:` 會誤把 `REVISED` 覆寫回 `PASS_A_KEEP_A`**：
   ```python
   _m = re.match(r'\s*\[\s*(\d+)\s*\]', _ln)
   ```
   只要裁決模型在第 2 欄寫成 `- [1]`、`* [1]`、`1. [1]`，或是把兩段合併寫成 `[1][2][疏]`，`[2]` 就會不在 `_by_i` 裡，程式直接把該段覆寫成 `PASS_A_KEEP_A`，**所有修訂都被靜默捨棄**。
3. **第 154 行 `_d` 算了沒用**：組裝單段回覆時把整包的 `div`（包含別段的裁決）全部塞進每一段，讓下游審核平白多了無關的假分歧參考。

#### 3. `run_pipeline.py` 的 `long` 階段傳錯 `--r1`，長段修訂會產出 0 份
在 `elif st == 'long':`：
```python
call(['_src/mk_revise_materials.py', '--r1', '測試/' + root + '/_長段/_終審',
      '--audit', '測試/' + root + '/_長段/_終審', ...])
```
`mk_revise_materials.py` 會去 `--r1` 底下的 `回覆/` 找 `修正後的譯文` 欄，但 `_長段/_終審/回覆/` 裡放的是**終審報告**（沒有第 3 欄譯文），`col3_safe()` 必回傳 `None`，全部長段都會被印出 `⚠ 修訂回覆異常，略過` 而無法修訂。

#### 4. `qwen_local.py` 跑滿工具輪數上限（8 輪）必崩潰
`for _round in range(MAX_TOOL_ROUNDS):` 結束後的保底送出（第 473–474 行）：
```python
_payload['tools'] = TOOLS
_payload['tool_choice'] = 'none'
r = qwen_post({
    'model': MODEL,
    'messages': messages,
    ...
})
```
1. `_payload` 從未定義（迴圈內變數名為 `payload`），只要任何一組跑滿 8 輪工具呼叫，立刻拋出 `NameError: name '_payload' is not defined` 失敗。
2. 緊接著的 `qwen_post({...})` 也沒把 `tools` 與 `tool_choice: 'none'` 帶進去；而若 `messages` 歷史已有 `tool_calls` 卻不帶 `tools`，部分相容 API 會直接回 400。

#### 5. `build_a2.py` 在 `PASS_A` 回填為空字串時會靜默產出空白檔
當 `MI.is_keep_a(txt)` 為真而呼叫 `MI.from_jia(...)` 時，若因格式差異（例如前述 `packjudge` 餵錯材料、或標題字眼不同）找不到 `（譯本甲）`，`from_jia` 會回傳空字串 `""`。但第 138 行判斷的是 `if txt is None:`（`"" is not None` 為真），導致程式把空檔寫進 `_定稿/{key}.txt` 還計入 `pass_ += 1`，沒有任何報錯。

### 二、中高風險 Bug（正規化改壞文字、檢索機制與文件相反、誤判）

#### 1. `qwen_local.py` 的檢索機制有三處與文件規格相反／未實作
1. **雙反斜線讓「自搜過濾」變成「濾掉原典、放過自己」**：
   第 166／176 行的 `_ht = re.sub(r'[\\W_]+', '', ...)` 多了一條反斜線，變成只刪字面 `\`、`W`、`_`，保留所有標點與換行；而 `own_text` 用的是 `r'[\W_]+'`（已去標點）。
   - **結果**：帶標點的自家著作（`業疏`、`戒疏` 等）因標點阻斷比對而**沒被過濾**；反而是無標點的律藏（`YUAN/四分律`、`隨機羯磨` 等，且不在科記白名單內），只要本段原文引用了 20 字以上，就會命中 `_wins` 而被**整筆濾掉**——剛好完全做反。
   - 另外第 397 行 `_looks_pasted` 的 `r'^\\s*【...】\\s*'` 也有同樣的雙反斜線問題，開頭有空白時會漏剝標籤。
2. **「相同查詢直接沿用結果、不計額度」從未生效**：
   `local_search` 有 `if key in memo:` 的讀取分支，但全函式沒有任何地方寫入 `memo[key]` 與 `memo[('R',) + key]`，永遠不會命中快取。
3. **「查無結果前 2 次免扣額度」未實作且邏輯錯置**：
   `_local_budget` 在查詢前已先把 `stats['locals'] += 1`；事後寫的是 `if not hits and _raw_n and stats is not None:` 才減 1。但真正查無時 `_raw_n == 0`，條件為假，照扣不誤；只有在「原本有搜到、被 `_own` 過濾光」時才退還（而且若走進 `relaxed` 跨書放寬才搜到又被濾光，因 `_raw_n` 仍是 0 也不會退還），程式裡也完全沒有「前 2 次」的計數器。

#### 2. `norm.py` 定稿正規化會改壞科文書名、佛學專詞與標籤
1. **`_lab` 是死碼，`【修訂譯文】` 仍一律變成 `【鈔文】`**：
   第 54–59 行掃描文本既有標籤算出 `_lab`，但第 60–61 行迴圈照舊執行寫死的 `LABEL_FIX`（`'【修訂譯文】': '【鈔文】'`），從未用到 `_lab`。`業疏`/`戒疏`/`資持記` 若模型誤寫自創標籤會被強制改成 `【鈔文】`。
2. **「科」字書名全部被降級成篇名號 `〈〉`**：
   ```python
   s = re.sub(r'《([^《》〈〉]{1,12}(?:篇|品|章|節|門|科|犍度))》', r'〈\1〉', s)
   ```
   書庫裡的 `《業疏科》`、`《戒疏科》`、`《行事鈔科》`、`《義鈔科》`、`《尼鈔科》` 全部以「科」結尾且 ≤12 字，全都會被改寫成 `〈業疏科〉` 等。
3. **`VAR_MAP` 強制 `瞋 -> 嗔`（及 `纔 -> 才`）**：
   佛典與《南山律學辭典》中「瞋恚」「貪瞋癡」標準正字皆為 `瞋`（目部），強制轉成 `嗔` 反而改壞佛教專詞；`URL_RE`（`https?://\S+`）若碰到網址緊接右括號、引號或句號（如 `（https://...）`），會把 `）」「。` 一併刪掉。
4. **問答前綴漏轉常見古式**：只正規化 `提問／回答／答曰`，律疏極常見的 `問曰：`、`答云：` 未處理。

#### 3. `materials_io.py` 的 `verdict()` 容易把 `PASS` 誤判為 `FIX`
`verdict()` 在結論判為 `PASS` 後，會再檢查 `【必改硬傷】` 是否真為「無」：
```python
seg = h.group(1)
seg = re.sub(r'^[（(【][^）)】]{0,14}[）)】]', '', seg)
seg = seg.strip(' 　\t\r\n*：:-')
```
若審核模型依提示輸出 Markdown 粗體或帶括號說明：
- `3. **【必改硬傷】**（無則寫「無」）：無` → 開頭是 `**`，`re.sub` 因開頭不是括號而跳過，`.strip('*')` 後剩 `（無則寫「無」）：無`，不以 `無` 開頭 → **誤判成 `FIX`**。
- `3. **【必改硬傷】**：（無）\n4. **【可斟酌微瑕】**` → `re.sub` 剝掉 `（無）` 後接到 `4. ...` → **一樣誤判成 `FIX`**。
這會讓原本全段無誤的稿件白送一輪修訂（甚至可能被無工具修訂改壞）。

#### 4. `mk_judge_materials.py` 的兩處漏失

### 三、流程與提示詞的一致性問題

1. **4.10 混合切法的「跳過預填」條件容易失效**
   `qwen_local.py` 要同時滿足「`_回.txt` 存在、大小 >10、` _usage.json` 存在、且材料 `.md` 的修改時間不比 `_回.txt` 晚 >1 秒」才會 `skip`。若先預填舊回覆、之後才重產 `_材料_hy`／`_hy_盲翻`，或只複製 `_回.txt` 而未帶 `_usage.json`，6,551 組預填結果會被判定為過期或未完成而全部重翻。
2. **`REVISE_PROMPT` 典籍簡稱拼錯且漏項**
   第 2.6 節與 `mk_revise_materials.py` 寫作 `伽論＝《薩部毘尼摩得勒伽》`（漏了「婆多」二字，正確為《薩婆多部毘尼摩得勒伽》），且漏列 `明了論`。
3. **單書／單邊段的 Prompt 注入不對等**
   - `mk_split_blind.py` 對《業疏》《戒疏》長段寫死 `scope='疏文與記文'`（實際長段一次只翻單欄），且對《資持記》漏了把 `cfg.get('note', '')`（鈔／疏／文／律指代對照）放進 `book_ctx`。
   - `mk_blind_materials.py` 在單欄書（《尼鈔》《行事鈔》《義鈔》）會把 `_ctx` 清空，也不像《資持記》有注入 `cfg['note']`；`mk_review_materials.py` 的 `prompt_for()` 亦然，使《尼鈔》一審提示詞不像早期 `get_prompt(True)` 有專項提醒。
   - `mk_audit_materials.py` 若缺 `.json`（例如未產生或被略過），`materials_io.parse_md()` 不會從 `（出處：《業疏》...）` 解析 `book` 欄位，會退回 `book_of()` 而拿到 `'疏記'`，使 `if book in ('業疏', '戒疏')` 失效、漏掉雙欄互核指令 `_dual`。
4. **補字規範跨階段打架**
   `BASE_PROMPT` 仍寫「以 `〔補字〕` **或段末簡註**標明」，但 `BLIND_PROMPT`、`REVISE_PROMPT` 與 `qc_scan.py` 都嚴禁在譯文出現任何校勘按語或段末說明。
5. **全書拼回鏈尚有斷點**
   - `run_pipeline.py` 的 `final` 只打包一般段進 `_定稿`，沒有與 `_長段/_定稿`（註：切分檔名用 0-based `idx`，拼回檔名用 1-based `idx+1`）、以及 `mk_review_materials.py` 跳過的 `≤5 字卷題` 做總合併與自動跑 `qc_scan.py`。
   - `run_all_books.py` 的 `wait_batch` 只比對 `done >= total`，不檢查 `.stage_done` / `.stage_partial`，一旦有少數檔案 400 審查未過或截斷，就會無意義死等 30 小時逾時。
   - `mk_review_materials.py` 只要發現某一卷 `len(a) != len(o)` 就直接 `return None` 整卷略過；若同一卷有增減段但總數湊巧相等，也沒自動攔截錯位。
6. **工程維護與文件漂移**
   - `col3`／`_strip_head_paren` 在 5 個檔案各自拷貝了一份且正則微異（例如 `mk_judge_materials.py` 沒剝開頭括號、其他四個有；有的 `(?:3|三)?` 可省略可能誤截第 2 欄裡的「修正後的譯文：」字樣），建議統一抽進 `materials_io.py`。
   - `qwen_local.py` 的 `_raw_len` 打包加成（`_pn`）會把裁決材料裡的「原文／譯本甲／譯本乙」三欄的 `[1][2]…` 重複算 3 次，2 段打包就會直接吃滿 6 次上限；`local_search` 預設 `rows=4`（文件 4.4 寫 3）。
   - `qc_scan.py` 說明寫「引號白話」但程式裡 #1 檢查已被刪除；文件標題與第八節仍寫「18 部」，4.1 與系統 prompt 已是 33 部（且少了被多個腳本 import 的 `book_config.py` 與已備妥的 `run_long_audit.py`）。
