### 1. `LOCAL_SCHEMAS`（`qwen_local.py`）：工具定義在誘導模型「盲猜 37 部書名」
- **問題**：
  `local_search` 的 `description` 開頭寫 `（37 部；work 可寫簡稱或全稱）`，`work` 參數寫 `（限 37 部內）`；但**整份系統提示詞與工具說明裡，從頭到尾沒有列出這 37 部書的完整書單**（第 3 條只列了 9 個簡稱）。
  這正好是你們 7.8 實測「28% 本地查詢（4,662 次）查無，主因是模型亂填 `work`」的提示詞根源——工具定義本身在鼓勵它填一個它不知道全名單的參數。
- **改法**：把 `LOCAL_SCHEMAS` 改得更保守，只列出核心幾部可安全指定的書，其餘強制留空：
  ```python
  'description': '檢索本地南山律典與律藏書庫（共 37 部）。預設不填 work 直接全庫搜尋；一次回傳命中處前後各 240 字（含 linehead）。',
  # work 參數：
  'description': '預設務必留空（全庫檢索已涵蓋 37 部並分層取樣）。僅當全庫命中過多，且確知要查對《四分律》《行事鈔》《資持記》《業疏》《戒疏》《尼鈔》《隨機羯磨》《含注戒本》《南山律學辭典》之一時才填；查詞義、平行文、他部律論或僅聞簡稱時一律留空。',
  ```

### 2. `pack_judge.py` 的 `【併批裁決要求】` 與 `JUDGE_PROMPT` 結尾 `{out_format}` 正面打架
- **問題**：
  `pack_judge.py` 用 `pack[0]['text'].split('【本次待審單元')[0]` 取 `head`，裡面原封不動保留了 `JUDGE_PROMPT` 結尾的「`照原樣以原標籤開頭……` ＋ `【疏文】……\n【記文】……`」；但緊接著 `【併批裁決要求】` 又寫「`以 [n] 為一級節點，其下再寫 【疏文】…【記文】…`」。模型不知道該先寫 `【疏文】` 還是先寫 `[n]`，才逼出 `pack_judge.py` 第 183 行那個複雜的互換正則。
- **改法**：在 `pack_judge.py` `do_pack()` 組 `head` 時，把結尾的「`REVISED：完整輸出……`」到 `---` 之間那塊 `{out_format}` 替換掉，讓格式指令跟 `【併批裁決要求】` 完全一致：
  ```python
  # 在 pack_judge.py 產出 head 後
  head = re.sub(
      r'REVISED：完整輸出[^\n]*\n[\s\S]*?(?=\n---)',
      'REVISED：依【併批裁決要求】只列有改動段，每段以 `[n]` 起頭、其下再依原標籤輸出（未列段沿用甲）。\n',
      head,
  )
  ```

### 3. `AUDIT_PROMPT`（`mk_audit_materials.py`）的三個細部漏網
1. **第 3 條「體例保留項」漏了 `被訓釋原詞` 與 `某甲`**：
   `STYLE_SPEC` 有寫「除**被訓釋原詞**、人地書名、戒名、**儀軌稱謂（某甲）**……」，但 `AUDIT_PROMPT` 第 3 條只寫了 `專名、度量、篇題、「某某反」與未定校勘〔…〕`。建議補成：
   `依體例保留之被訓釋原詞、專名、儀軌稱謂「某甲」、度量、篇題、「某某反」與未定校勘〔…〕`
2. **`[n]` 段號位置前後矛盾**：
   `【必改硬傷】` 範本寫 `[疏/記/鈔/律/註/序，打包段附[n]]`（`[n]` 在標籤後），但打包的 `【分段要求】` 寫 `條目前請加註段號 [n]`（`[n]` 在最前）。建議把範本直接統一成 `[打包段附[n]][疏/記/鈔/律/註/序]`（例如 `[1][疏]`），和 `JUDGE_PROMPT` 對齊。
3. **長段終審「句句走到」容易爆輸出或截斷**：
   `【逐句簡核】` 要求「`顯明無誤之句可簡記相符，但須句句走到`」，在一般 100–300 字段落很好，但碰到 `run_long_audit` 拼回後的 800–1,500 字長段，兩步都要逐句重走極易觸發 `finish_reason == 'length'`。可微調為：
   `（顯明無誤之句可按意群簡記相符，長段無須逐字重抄，惟關鍵句與疑點須逐句走到）`

### 4. `NO_TOOLS_SYSTEM`（400 保底模式）缺「禁止憑記憶臆測出處」
- **問題**：
  當 `JUDGE` 或 `AUDIT` 碰到 API HTTP 400 觸發 `_fallback_no_tools` 時，系統提示會切換成 `NO_TOOLS_SYSTEM`。原本 `SYSTEM_PROMPT` 第 5 條的「`嚴禁未經檢索就憑記憶臆測經文出處或行號`」在 `NO_TOOLS_SYSTEM` 裡**不見了**，只留了一句「`若有引用原典依據，僅於說明欄註記`」——剛好在沒有工具可查時，容易誘導模型靠背誦幻覺出卷次或假經文。
- **改法**：在 `NO_TOOLS_SYSTEM` 補上一句：
  `無工具可查證時，嚴禁憑記憶臆測未見於材料中的經律出處、卷次或行號；`

### 5. 打包組上下文提醒 ＋ 「科判短語」界線 ＋ 小符號碰撞
1. **打包組（`pack_judge.py` / `pack_audit.py`）**：
   打包把 2–6 個連續短段放在一起時，只保留首段的前文與末段的後文，中間段彼此就是最直接的上下文。在 `pack_judge.py` 的 `RULE` 和 `pack_audit.py` 的 `【分段要求】` 補一句：
   `包內 [1]..[n] 原屬相鄰上下文，判讀代詞與承接關係時可相互參照，輸出／檢核仍須依各段原編號獨立對應。`
2. **「科判短語除外」界線（`STYLE_SPEC`、`AUDIT_PROMPT`）**：
   古籍常出現「科分三：初XX，次YY……」或「科名後緊接一句短釋」的段落。將 `純科判綱目` / `（科判短語除外）` 微調為 `（僅純分科標目短語除外；凡含散說闡釋之句仍須主賓明確）`，可減少模型把半散說段也翻成無主詞電報體。
3. **`STYLE_SPEC` 的符號碰撞**：
   `「第X篇：……」〔末不加句號〕` 建議改為圓括號 `（末不加句號）`，避免與緊接著講校勘異文專用的方括號 `〔…〕` 混用。
4. **`mk_punctuate.py` 的 `PROMPT` 第 1 條**：
   加上 `（包含異體字、通假字、既有校勘符號〔…〕與缺字方框 □）`，和它自己 `verify` 嚴格比對 `□` 數量的邏輯完全對齊。

### 6. 附帶修訂一下前一則 Phase A4 的動態標籤小細節
上一則 Phase A4 處理 `mk_revise_materials.py` 打包組 `{out_format}` 時，因為 `pack_audit.py` 也會拿去打包 `尼鈔`／`行事鈔`／`資持記`（這時每個 `[n]` 裡面是 `【鈔文】` 或 `【記文】`，不一定都是 `【疏文】`），所以改成從 `_labs` 動態組出比較保險：
```python
if md.get('packed'):
    _ordered_labs = list(dict.fromkeys(u.get('lab') for u in (md.get('units') or []) if u.get('lab')))
    if md.get('members'):
        _inner = '\n'.join('【%s】……' % l for l in (_ordered_labs or [cfg['unit']]))
        fmt = '[1]\n%s\n[2]\n%s\n（依各條原有標籤結構與原編號逐條完整輸出）' % (_inner, _inner)
    else:
        _only_lab = (_ordered_labs[0] if _ordered_labs else cfg['unit'])
        fmt = '【%s】\n[1] ……\n[2] ……（標籤僅寫開頭一次，依原編號逐條完整輸出）' % _only_lab
else:
    fmt = BC.fmt_for(book, md.get('units'))
```
