### 1. `make_hybrid.py` 遇到「舊組與新組部分重疊」時會覆寫舊檔＋重複出段
看 `make_hybrid.py` 判斷新組要不要加入的條件：
```python
if idx and all(k in cv for k in idx):
    continue
new.append(g)
```
假設舊切法覆蓋了第 20 行（`【疏】`），但漏了第 21 行（`【記】`）；而新切法產出一組 `g` 涵蓋 `[20, 21]`：
1. 因為 21 不在 `cv` 裡，`all(...)` 是 `False`，所以新組 `g` 被保留，同時舊組也已經被複製進 `_材料_hy`——**第 20 行在 `_材料_hy` 裡會出現兩次**。
2. 更隱蔽的是：因為舊組檔名是 `chunk_0021.md`，而新組的 `s0 + 1` 也是 `0021`，緊接著執行 `M.emit(g, ..., out, ...)` 時會**先寫出同名 `chunk_0021.md` 把剛複製好的舊組 `.md` 覆蓋掉**，下一行再把它 `os.rename` 成 `n0001_chunk_0021.md`！最後結果是 `_材料_hy` 裡的舊組 `.md` 不見了，但 `_hy_盲翻/回覆` 裡卻還留著它的孤兒 `_回.txt`。

### 2. `pack_audit.py` ＋ `pack_final.py` 拿去打包《業疏》《戒疏》雙欄組時會 100% 拆回失敗
這兩支腳本打包《尼鈔》《行事鈔》等單欄書沒問題，但拿去打包《業疏》《戒疏》的「疏＋記」雙欄短組時會衝突：
- `pack_audit.py` 產出 `.md` 時是按 `[1] 【疏文】…【記文】…`、`[2] 【疏文】…【記文】…` 排列；但寫入 `.json` 時把所有成員的 `units` 都塞了進去。
- 跑 `mk_revise_materials.py` 時，`BC.fmt_for(book, md.get('units'))` 會要求修訂模型按「先 `【疏文】`、後 `【記文】`」的格式輸出。
- 只要修訂模型照指示寫成「`【疏文】\n[1]...\n[2]...` 接著 `【記文】\n[1]...\n[2]...`」，`pack_final.py` 的 `split_marked()`（`re.split(r'\[\s*(\d+)\s*\]', text)`）就會切出 **2 × N 個片段**，跟 `len(members)`（N 個）不合，直接整包失敗輸出成 `_未拆.txt`。

### 3. `local_corpus.py` 的 `_split_work()` 會劫持「以書名開頭的跨書引文查詢」
就算模型乖乖聽 System prompt「查跨書用語時 `work` 留空」，只要模型在 `query` 開頭寫到書名（例如搜 `"資持記云 隨行"`、`"業疏云 戒體"` 或 `"四分律中說"`，想查《行宗記》《辭典》是怎麼引述它的）：
- `_split_work()` 只要看到 `q.startswith(nm)` 且長度大於 `len(nm) + 1`，就會**不問青紅皂白把開頭書名拆成 `work`**，只拿剩下的 `"云 隨行"` 去《資持記》裡面找（書名本身不會出現在內文裡，必查無！）。
- 而且因為呼叫方原本的 `work` 是 `None`，外面 `local_search` 的 `if not hits and work:` 全庫救援也不會啟動，直接白白查無收場。

### 4. `build_a2.py` 的 `col3()` 回退若在第 2 欄寫到 `【疏文】` 會把裁決理由當定稿
前幾輪提過 `col3` 主正則漏了 `譯文` 後的 `**`。當某一份裁決回覆寫成 `3. **修正後譯文**：`（少一個「的」字）時：
1. 主正則 `m` 失敗（卡在 `**`）。
2. `rfind('修正後的譯文')` 也失敗（少了「的」字）。
3. 程式退到第 3 層保底：`k = rt.find('分歧與裁決')`，然後從第 2 欄開始找第一個 `【疏文|記文|鈔文...】`。
   但第 2 欄的「分歧與裁決」常常會寫 `"甲於【疏文】誤譯為……"`，結果 `col3` 就直接從第 2 欄裡的 `【疏文】` 開始截取，把整段裁決討論寫進最終譯文。

### 5. `materials_io.py` 的 `verdict()` 若模型沒打 `【】`，會被第 1 欄「逐句簡核」誤導
`verdict()` 先找 `【結論】`，找不到才找無方括號的 `結論[^A-Za-z]{0,40}(PASS_A|PASS|FIX)`。
如果審核員第 2 欄漏了 `【】`（寫成 `2. **結論**：FIX`），而第 1 欄 `【逐句簡核】` 內文剛好出現過 `"綜合結論尚難即斷 PASS 或 FIX"` 之類的句子，從全文頭掃描的備援正則就會**優先抓到第 1 欄的 `PASS`**，而不是第 2 欄的 `FIX`。把備援正則限定在行首結構（例如 `(?m)^[#*\s\d.、]*結論`）或改用最後一次出現位置就能避免。

### 6. 兩個最後的收尾小縫隙
1. **`build_a2.py` 沒有像 `qc_scan.py` 攔截變形的 `PASS_A_KEEP_A`**：`MI.is_keep_a()` 只認開頭 `startswith('PASS_A_KEEP_A')`。若模型前面多寫幾個字（如 `同甲：PASS_A_KEEP_A`），`is_keep_a()` 回傳 `False`，`build_a2.py` 會直接把這串英文寫進定稿 `.txt` 並計為成功（只有事後跑 `qc_scan.py` 才會報警）。
2. **`qwen_local.py` 成功覆寫後不會清理先前的異常殘檔**：若某組在 Run 1 失敗寫出 `_截斷.txt`、`_重貼原文.txt` 或 `_400審查.txt`，之後重跑成功寫出 `_回.txt` 時，這些舊殘檔仍留在 `回覆/` 裡不會刪除，事後用 `dir` 或腳本巡檢異常檔數時容易產生誤判。
