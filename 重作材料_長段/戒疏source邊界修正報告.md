## 2. 為什麼 `raw_start`／`raw_end` 沒有變動

這一點與指令的字面「往前 1 字」不同，必須先說清楚，否則會修錯：

```text
raw_start/raw_end  = 漢字流（TXT_句讀校定/jieshu.txt 去標點後）的位移
display_start/end  = 句讀底本原始字串（含標點）的字元位移
```

這批截斷缺的是 `「`、`【`、`。`、`」` 這類**標點**，不是漢字。  
若把 `raw_start` 真的往前 1 個漢字：

- `02a_卷一上之二_0112` 會多吃進前一個漢字「云」；
- `05d_卷二上之一_0085` 會多吃進前一個漢字「類」。

如此 `source` 的漢字就會多於譯文，反而製造新的「無據增補」，正是本次要避免的事。

所以本輪只把**顯示切片**的邊界擴大到相鄰句讀，漢字區間不動；每筆都 assert：

```text
han(新 source) == raw_h[raw_start:raw_end]
```

全量 4,432 筆中，需要動漢字座標的筆數為 **0**。

## 3. 掃描規則與分類

以 `TXT_句讀校定/jieshu.txt` 為句讀底本（全文與 `TXT/02_四分律含注戒本疏.txt` 相同，漢字 410,515 字）。  
逐筆檢查：

1. `source` 漢字必須等於目前 `raw_start:raw_end` 的漢字（4566 筆全過）。
2. `source` 必須等於「第一個漢字到最後一個漢字」的原始切片（確認是 trim 造成的邊界問題）。
3. 左邊界若緊鄰 opening 標記（`「『【（《〔`）就補回。
4. 右邊界若緊鄰 closing／句末標記（`」』】）》。！？，、；：》`）就補回。
5. 補完 assert 漢字不變、顯示區間不與前後列重疊。

### 3.0 根因

`_src/trim_jieshu_overlaps.py` 曾把 `source` 設成：

```text
raw[mp[a] : mp[b-1]+1]
```

也就是只取「第一個漢字到最後一個漢字」，兩端緊鄰的標點全部被切掉。  
所以 4,432 筆不是 4,432 個獨立錯字，而是同一個系統性 trim 的結果；本輪一次修掉。
