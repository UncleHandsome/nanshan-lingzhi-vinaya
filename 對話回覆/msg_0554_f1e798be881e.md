   - 舊版只寫 `.md` 不寫 `.json`，且把 `【舊譯參考】` 放在 `【後文背景】` 之後。下游 `mk_audit_materials.py` 找不到 `.json` 而退回 `MI.parse_md()` 時，`POST_RE` 會一路吞到 `\Z`，把整段舊譯塞進終審的【後文背景】。此外，若原段無後文時省略 `【後文背景】`，`qwen_local.py` 的 `SRC_RE_ALL` 也會跨入 `■ …（舊譯）` 虛增原文長度與污染 `own_text`。

```python
# -*- coding: utf-8 -*-
"""單輪草譯材料產生器（接軌 JSON／fmt_for／打包／_hy 混合切法）。

用法：
  python -X utf8 _src/mk_draft_materials.py --src 測試/重譯/資持記/_材料 --out 測試/重譯/資持記/_草譯
  python -X utf8 _src/mk_draft_materials.py --src 測試/重譯/資持記/_材料_hy --out 測試/重譯/資持記/_草譯 --skip-blind 測試/重譯/資持記/_hy_盲翻/回覆

import io
import os
import re
import sys

B = r'C:\Users\lionc\OneDrive\桌面\XW\三大部'
sys.path.insert(0, os.path.join(B, '_src'))
import book_config as BC   # noqa: E402
import materials_io as MI  # noqa: E402

DRAFT_PROMPT = """你是南山律宗白話譯校編輯，負責將《四分律》與南山著作（{scope}）譯為自然流暢的現代正體書面白話。
下面附有【原文】、前後背景（僅供確認指代與律脈，切勿譯入正文{shuji_ban}），以及文末的【舊譯參考】。

請依序以三欄輸出，**切勿一開始就順著【舊譯參考】的句式修補**：

1. **獨立全譯（甲）**（暫置文末【舊譯參考】，僅依【原文】與前後背景獨立拆解並完整譯出，標籤格式同第 3 欄；僅於確有疑義處並聯檢索，顯明文意勿重複搜查）：
   - **忠實**：不漏條件、實質夾注、音訓與實詞；不增原文所無的細目、背景或考訂。省略之主賓與條件直接融入句中；背景截斷而未見所指時，寧用中性泛稱，不臆補。

2. **分歧與裁決**（將第 1 欄「全譯＝甲」與文末「舊譯＝乙」逐句核對）：
   - 依第 1 欄原則比對實質分歧，忽略乙的解說括號與純修辭換詞；**遇甲乙理解有異處，勿因自撰甲譯已順暢而偏袒甲，須回歸原文與檢索覆核，擇善採乙或重修**。每條限寫於同一行內，勿斷行：`[欄別] 原文「……」｜甲作「……」vs 乙作「……」｜裁決（甲優／乙優／重修）：……`（欄別寫 `[疏]`/`[記]` 等單字，勿寫全稱標籤）。

3. **修正後的譯文**（以第 1 欄為底本，嚴格貫徹第 2 欄裁決；未列分歧之句照第 1 欄原字照錄，勿趁抄錄暗改字詞；採乙義或重修處須轉寫為第 1 欄之簡明純白話體例，勿直抄乙之解說括號、文言複述或殘留雙譯疊詞。**無論有無分歧皆須於此欄完整輸出正文譯文，不可省略或僅寫代稱**；須照原樣以原標籤開頭，嚴禁自創標籤或夾帶出處網址）：
{out_format}"""


def main():

    ap.add_argument('--src', required=True)
    ap.add_argument('--out', required=True)
    ap.add_argument('--skip-blind', default='', help='已存在盲翻回覆目錄（如 _hy_盲翻/回覆），有有效回覆者跳過')

    out = os.path.join(B, args.out.replace('/', os.sep))

    os.makedirs(out, exist_ok=True)
    rep = os.path.join(out, '回覆')

            and any(f.endswith('_回.txt') for f in os.listdir(rep))

            os.remove(os.path.join(out, f))

    n = skip_old = skip_blind = 0
    for fn in sorted(os.listdir(src)):
        if not fn.endswith('.md'):
            continue
        key = fn[:-3]
        if skip_dir:
            bp = os.path.join(skip_dir, key + '_回.txt')

                    sr, ban = '', ''

                    bctx, sr, ban = '', '', ''
            else:
                sr, ban = '', ''

            scope=scope,
            book_ctx=bctx,
            shuji_rule=sr,
            shuji_ban=ban,
            out_format=BC.fmt_for(book, units),
        )

        ex_txt = md.get('ex', '')
        pre_txt = md.get('pre', '')
        post_txt = md.get('post', '')

        L = [prompt, '', '---', '', '（出處：《%s》%s）' % (book or '未知', ex_txt), '']

                  '不可改為 `1. 2.`、合併或增減條數；第 2 欄條目前請加註段號 `[n]`；'
                  '正文子條目序數用一、二、（一）（二），嚴禁額外使用 `[數字]`。', '']

        io.open(os.path.join(out, fn), 'w', encoding='utf-8').write('\n'.join(L))
        MI.write_json(out, key, {
            'key': key,
            'chunk': md.get('chunk') or key.rsplit('_', 1)[0],
            's0': md.get('s0'), 's1': md.get('s1'),
            'g0': md.get('g0'), 'g1': md.get('g1'),
            'ex': ex_txt,
            'pre': pre_txt,
            'post': post_txt,
            'book': book,
            'packed': bool(md.get('packed')),
            'segments': md.get('segments') or [],
            'units': [{'lab': u['lab'], 'orig': u.get('orig', '')} for u in units],
        })
        n += 1

    print('已產生 %d 份單輪草譯材料（跳過無舊譯 %d、已有盲翻 %d）→ %s'
          % (n, skip_old, skip_blind, args.out))


if __name__ == '__main__':
    main()
```

原因和具體做法如下：

---

### 一、為什麼草譯需要多一點，但不能加錯工具？

1. **100–300 字是單輪草譯最吃緊的區間**
   - 雙輪流程中，100–300 字的段落（正是《資持記》《行事鈔》大宗）在盲翻拿 **3 次**、裁決又拿 **3 次**，合計 **6 次**本地檢索；
   - 單輪草譯把兩步合併後，若沿用預設動態配額，100–300 字只有 **3 次**本地檢索（含前 2 次查無免扣），往往第 1 欄查了 2 次專名或科判，第 2 欄遇到甲乙矛盾要仲裁時就只剩 1 次可用。
2. **加「本地」划算，加「網搜／抓取」會吃掉省下的成本**
   - **本地 33 部書庫**：每次回傳僅約 `rows=3, pad=240` 字，無外站費用與限流風險。
   - **網搜／抓取**：單次 `web_fetch` 最高回傳 3,600 字，且依 `7.6 L7 實測`，每次多出工具回合都會把整段對話歷史與 `xhigh` 思考重送一遍（當時用滿 5 次的 16 檔就吃掉了全批 **74%** 的輸入 Token）。若把 `web_search`/`web_fetch` 也放大，很容易把單輪草譯好不容易省下的 **25%–29%** 費用吐回去。

---

### 二、建議加多少最剛好？

建議維持「依原文長度分級」，只給單輪草譯整體 **`+1` 到 `+2` 次本地額度**（上限封頂 `7` 次，避免像 L3 開到 12 次那樣造成思考與輸出膨脹）：

| 原文長度 | 原動態本地上限 | 草譯 `+2` 後上限 | 網搜／抓取建議 |
|:--|:--:|:--:|:--|
| `≤30` 字 | 1 | **3**（或 `+1` 給 2） | 維持 `1 / 1` |
| `31–99` 字 | 2 | **4** | 維持 `1 / 1` |
| `100–300` 字（主力） | 3 | **5** | 維持 `2 / 1` |
| `>300` 字 | 5 | **7**（封頂） | 維持 `2 / 1` |

---

### 三、怎麼設定最乾淨？（不影響盲翻／裁決／審核）

* **不建議直接設 `$env:QWEN_MAX_LOCAL='5'`**
  因為 `qwen_local.py` 目前只要讀到 `QWEN_MAX_LOCAL`，就會**整個覆蓋動態級距**，連 15 字的短題目都會拿到 5 次額度。

* **建議改法：在 `qwen_local.py` 加 2 行 `QWEN_LOCAL_BONUS`**
  把 `qwen_local.py` 第 537–547 行改成：
  ```python
  _ms, _mf = _quota(text)
  stats_cap = _local_cap(text)
  _bonus = int(os.environ.get('QWEN_LOCAL_BONUS', '0') or '0')
  ...
  stats_cap = min(6 + _bonus, stats_cap + _bonus + max(0, _pn - 1))
  ```
  *(若想把最高天花板鎖死在 7 次不讓打包長段衝過頭，寫 `min(7 if _bonus else 6, ...)` 即可。)*

* **執行時帶入**：
  ```powershell
  $env:QWEN_LOCAL_BONUS='2'   # 只在跑 _草譯 時設定；其他階段不設（預設 0）
  ```

### 四、試跑時順手確認的一件事

20 組試跑結束後，用 `cost_report.py` 比對 **`QWEN_LOCAL_BONUS='2'`** 與 **雙輪（盲翻＋裁決）** 的總輸入 Token：
- 只要系統 prompt 的「僅於確有疑義處並聯檢索」有發揮作用，多數段落還是只會用到 1～3 次，真正複雜的段落才用到 4～5 次，總輸入仍應穩穩低於雙輪 20% 以上；
- 若發現多數檔案都去把 `5`～`7` 次撐滿、導致平均輸入逼近雙輪水準，把 `$env:QWEN_LOCAL_BONUS` 調降回 `'1'` 即可。
