# 白話譯文嚴格校閱計畫

> 目的：以兩份範例報告（〈訃請設則篇〉、羯磨篇）揭示的判準，對全書白話譯文做一次「法義級」校閱，而不是只挑錯字與漏譯。
> 撰寫日期：2026-11-07

---

## 一、結論摘要

| 項目 | 數值 |
|:--|--:|
| 對照段落總數 | 27,528 段 |
| 譯文字數 | 約 361 萬字元（244 個正式譯文檔） |
| 校閱批次 | 30 篇（會本 docx 為批次邊界） |
| 建議工期 | 先做 2 篇校準（約 2 天），再按密度排 8–10 批 |
| 最大風險 | **原文／譯文段落對齊不可靠**（見第三節），不先處理會把「對錯段」誤判成「譯錯」 |

一句話：**先修對齊，再談譯文；先做規則篩，再人工精校。**

## 二、校閱對象與計量

### 2.1 唯一來源

依 `交接/譯文修改規則.md`：所有修正**一律先改** `AI語譯/out/<書>/<chunk>.txt`，再重建會本 docx 與網站。**不得直接改 docx 或 docs/*.html**，否則 zhichi 與會本會不一致。

### 2.2 規模分佈

| 書 | 譯文檔 | 譯文字數 | 對照段 | 說明 |
|:--|--:|--:|--:|:--|
| 戒疏（jieshu） | 69 | 1,088,216 | 9,499 | 量最大，術語密度最高 |
| 合編（hebian） | — | — | 6,185 | 鈔＋記的句級重切，與下兩列**重疊** |
| 業疏（yeshu） | 45 | 679,673 | 5,183 | |
| 資持記（zhichi） | 73 | 1,015,421 | 4,177 | |
| 行事鈔（xingshichao） | 35 | 522,922 | 1,489 | |
| 尼鈔（nicao） | 13 | 188,491 | 777 | |
| 尼義鈔（yichao） | 9 | 118,356 | 218 | |
| **合計** | **244** | **3,613,079** | **27,528** | |

**注意**：`hebian` 是 `xingshichao`＋`zhichi` 的句級重切版，內容重疊。校閱若按網頁逐頁做，同一段譯文會被校三次。**因此校閱必須在源頭 chunk 層進行**，網站只作驗證與定位用。

### 2.3 定位方式

每段在網站上有穩定錨點：`docs/<書>/<卷>.html#sN`（`sN` 為該頁第 N 個對照段）。
→ 每條校閱意見都必須附這個連結，做到**可點擊複驗**。
→ 前提是**不得增刪段數**，否則 `sN` 全部位移（見第九節風險）。

## 三、開工前必須先解決：對齊審計

實測 171 個原文 chunk 與其譯文的段落數：

| 書 | 段落數完全相符 | 不符 | 缺譯 |
|:--|--:|--:|--:|
| 行事鈔 | 0 / 35 | 35 | 0 |
| 戒疏 | 0 / 69 | 69 | 0 |
| 業疏 | 0 / 45 | 45 | 0 |
| 比丘尼鈔 | 0 / 13 | 13 | 0 |
| 拾毗尼義鈔 | 0 / 9 | 9 | 0 |

**沒有任何一個 chunk 是嚴格 1:1。** 兩種型態：

1. **固定少 3–5 段**（例：87→82、96→91、104→99）：多為卷首題名、撰號等 header 未譯，屬正常，對齊時略過即可。
2. **譯文段數暴增**（例：`01b_卷上之一` 90→142）：譯者把長段自行切開，違反「一段原文對一段譯文」規則。這一類會讓後續所有段號錯位。

建置時 `mk_pian_split.py` 有 `split_tr()` 這類補救邏輯，所以網站上看起來是對的；但**源頭已經不對齊**，直接拿 chunk 逐段比對會產生大量假陽性。

### 產出物：對齊語料（Phase 0）

`_work/aligned/<書>__<chunk>.jsonl`，每行：

```json
{"id":"zhichi/上一上.html#s12","src":"...","tr":"...","align":"exact|shift:-5|split:3","conf":0.98}
```

- `align` 標記對齊方式，`conf` 為信心值。
- 信心值低於 0.9 的段落進入「人工確認對齊」佇列，不進入譯文校閱。
- 這份語料同時是後續規則篩選與報告定位的基礎。

## 四、缺陷分類與嚴重度

沿用兩份範例的分類，補上兩類：

| 代號 | 類型 | 判準 | 嚴重度 |
|:--|:--|:--|:--|
| **A** | 科判省略語誤讀 | 「X下」「初X」「約X」「此約」「X中」被當成實詞 | P0–P1 |
| **B** | 律宗專名誤譯 | 知法、義加、唱相、相從、示問者、尼三、觸煮、共輿/共舁 | P0 |
| **C** | 主詞／施受倒置 | 若嫌犯墮、示問者、能遣／所遣 | P0 |
| **D** | 一詞多義 | 法、相、約、進止、言議、相可 | P1 |
| **E** | 制度程序誤解 | 羯磨四步、結界唱相、受衣、說戒 | P0 |
| **F** | 段落對應／標點 | 漏括號、錯引號、段序錯置 | P2 |
| **G** | 漏譯／增譯 | 整句未譯、自行腦補 | P1 |

嚴重度定義：

- **P0**：法義錯誤，讀者依譯文理解會得到相反或錯誤的結論。**必須清零。**
- **P1**：術語或語意偏差，不至於反義，但會誤導。
- **P2**：文字、標點、格式。

範例報告中的 5 處硬傷全屬 **P0**（知法、義加不成、相從唱相、示問者、尼三同遣），7 處微瑕多屬 **P1**。

## 五、五階段工序

### Phase 0：對齊與基線（1–2 天）

1. 產出第三節的對齊語料。
2. 建**術語基線表** `_work/glossary.tsv`，來源三路：
   - `docs/appendix.html` 現有 200 條名相；
   - 從記文抽「X 即 Y」「X 者，Y 也」定義句（可程式抽取，估計 300–600 條）；
   - CBETA 佛學術語對照（丁福保、佛光大辭典）補齊。
3. 每條術語給出：正譯、禁用譯法、出處。

> 這張表是後面所有判定的**共同尺規**，沒有它，兩個校者會給出不同答案。

### Phase 1：機器預篩（2–3 天，可與 Phase 0 並行）

用規則庫（第六節）掃全語料，輸出 `_work/candidates.tsv`：疑似有問題的段落，附命中規則。
目標：**把 27,528 段收斂到 2,000–3,000 段**進入人工複核，而不是全讀。

### Phase 2：逐篇精校（主體工作）

- 批次邊界＝會本 30 篇；每批 3–5 篇。
- 每段判定四選一：**正確 / P0 / P1 / P2**，只有非「正確」才寫報告。
- 每條意見必須含：原文、原譯、問題辨析、建議譯文。
- **紀律**：能用記文自證的才算 P0；純屬語感差異的降為 P1 或不報。

### Phase 3：對抗複核

第二輪用不同提示與不同視角重掃同一批，只問一句：**「這段譯文有沒有把原文的意思說反、說窄、或張冠李戴？」**
- 兩輪都判 P0 的，直接成立；
- 只有一輪判 P0 的，進仲裁佇列，由人工終判。

> 範例報告的價值正在這裡：它抓到的不是「譯得不好」，而是「譯反了」。單輪容易漏，兩輪視角不同才穩。

### Phase 4：落地與回歸

1. 改 `AI語譯/out/...` → 重建 `mk_pian_split.py` → `site2.py`。
2. 回歸：48 頁 / 27,528 對照段 / 341 篇名**數量不變**；非目標段零差異。
3. 每批一份 `交接/校閱_YYYYMMDD_第N批.md`，格式沿用 `待修正_*.md`。

## 六、規則庫（可直接實作）

### 6.1 科判語（A 類，命中率最高）

```
(^|[，。；])([^，。；]{1,8})(下|中|末)[，、]
^(初|次|三|四|五)[，、]?
(此|今|故|然)?約[^，。]{1,6}[，、]
```

> 判準：譯文若把「不得下」譯成「不可…」、把「若共下」譯成「共同…」、把「餘門得者」譯成「其餘各門」，即為 A 類。

### 6.2 高風險詞表（B/C/D 類）

| 詞 | 常見誤譯 | 正譯方向 |
|:--|:--|:--|
| 知法 | 告知名相之法 | 認罪伏法 |
| 義加不成 | 增減則不成 | 依律理追加判定不成 |
| 唱相 | 宣告行相 | 唱宣界相 |
| 相從 | 順著…順序 | 隨附、附帶 |
| 示問者 | 開示應問之辭 | 標明發問的人是誰 |
| 尼三 | 比丘尼等三種小眾 | 尼三眾（尼、式叉、沙彌尼） |
| 觸煮 | 生熟互煮 | 手自烹煮 |
| 共輿／共舁 | 同乘車輿 | 共同搬抬 |
| 進止 | 進退威儀 | 任用或摒除 |
| 言議 | 商議 | 言儀、表白之辭 |
| 相可 | 行相合格 | 彼此印可 |
| 約 | 依據 | 就…而言（科判） |

### 6.3 譯文異常訊號

- 出現泛化詞：「佛法名相」「各種法門」「修行境界」——多為譯者心虛時的填充。
- 譯文／原文字數比 < 0.7 或 > 3.0。
- 原文含「即」「者」「謂」等定義句式，譯文卻無對應判斷句。
- 同一術語在相鄰 50 段內出現兩種譯法（一致性掃描）。

### 6.4 對齊訊號

- 段落數差 ≠ 固定 header 數 → 進人工對齊佇列。
- 譯文段首出現「接著」「此外」但原文段首無對應連接詞 → 疑似錯位。

## 七、報告格式（對齊範例）

每條：

```markdown
#### 12.「知法」被誤譯為「告知名相之法」

- **位置**：資持記 卷下之三 › 第X篇 › 段 記042（[開啟](docs/zhichi/下三.html#s88)）
- **原文**：【鈔】應作舉、憶念、證正、知法。【記】知法即所犯伏罪，法即是罪。
- **原譯**：此時應當進行檢舉、令其憶念、證成正實、告知名相之法。
- **判定**：P0／B 類（專名誤譯）
- **辨析**：此為治罰羯磨的法定四步…（引記文自證）
- **建議**：此時應當進行檢舉、令其憶念、證成罪實、令其認罪伏法。
```

篇末附彙總表（序號／類型／嚴重度／一句話說明），與範例一致。

## 九、驗收標準（Definition of Done）

一批算完成，需同時滿足：

1. 該批所有段落都已判定（正確／P0／P1／P2），無「未看」。
2. P0 清零，且每條都有記文或律本自證。
3. 同一術語在該批內**只有一種譯法**。
4. 重建後：段數不變、非目標段零差異、`audit_site.py` 0 問題。
5. 報告可點擊複驗（每條都有 `#sN` 連結）。

全書完成時另加：隨機抽 5% 段落做盲審，新增 P0 比例 < 2%。

## 十、風險與對策

| 風險 | 後果 | 對策 |
|:--|:--|:--|
| 改譯時合併／拆分段落 | `#sN` 全部位移，舊報告連結失效 | **硬規則：一段對一段，禁增刪**；必要時另建映射表 |
| 過度依賴機器預篩 | 漏掉不在詞表內的錯 | 每批保留 10% 隨機段落全讀，作為召回率抽檢 |
| 把「譯得不好」當「譯錯」 | 報告膨脹、改動失控 | P0 必須引原文自證；說不出「錯在哪」的一律降級或不報 |
| 術語表未定稿就開工 | 前後批標準不一 | Phase 0 的術語表先凍結 v1，之後只增不改 |
| 動了 docx 沒改源頭 | 網站與會本不一致 | 一律改 `AI語譯/out`，重建後 `git status` 檢查 docs 是否同步 |

## 十一、下一步（可立即執行）

1. **跑對齊審計**：產出 `_work/aligned/*.jsonl`，標出信心 < 0.9 的段落。——這是所有後續工作的地基。
2. **抽 200 段做召回率測試**：用第六節規則庫掃，人工核對命中與漏網，據此調整詞表。
3. **用兩篇範例校準提示詞**：把範例報告的 12 條結論當答案卷，調整校閱提示，直到能複現其中 ≥ 10 條。

三件事做完（估 2–3 天），再決定是否全書推進。
