## 一、提示詞會不會太 case by case？

**是的，有部分規則明顯是從 11 組／20 組錯題倒推出來的補丁；但也有部分看似繁瑣的規則其實是律典必備的「領域防呆」，不該全刪。**

建議用「**一般原則 vs. 特定詞例**」來區分去留：

1. **過度 case by case（建議精簡／抽象化）**：
   - **`BLIND_PROMPT` 原則 2 的括號窮舉**：`（白前白後、已未受、竟未竟、出界未出界、過中未過）` 屬於具體測試段出現過的字面，改為「`作法時序與界限詞（如白前白後、已未竟、出界過中等）`」即可。
   - **「身體或行為要件直譯」與 400 風控的隱性衝突**：`涉及戒相、身體或行為要件之實詞須精準直譯，勿改為籠統委婉語` 雖是防模型過度委婉，但律典涉婬戒／身行條文極易觸發 Qwen 內容審查（`400 data_inspection_failed`）。建議改為「**照律名與行為要件平實直譯，不自行淡化或渲染**」，避免模型為了「夠直白」而輸出過於露骨的現代詞彙反遭攔截。
   - **`SYSTEM_PROMPT` 第 5 條放錯位置**：`反切音訓若無確據，保留「某某反」原訓釋字面即可` 是**翻譯規則**，不該放在「檢索原則」裡。目前這樣寫會導致 `revise`（`QWEN_NO_TOOLS=1` 切換成 `NO_TOOLS_SYSTEM`）時整個失效。

2. **高價值領域防呆（看似瑣碎但應保留）**：
   - **`SYSTEM_PROMPT` 第 3 條典籍簡稱**（`伽論≠瑜伽師地論`、`婆沙≠大毘婆沙論` 等）：這是 LLM 最常錯展開的高風險區，強烈建議保留，而且**必須連同 `NO_TOOLS_SYSTEM` 一起保留**。
   - **「文／注／律」的書別指涉**（如《業疏》文注指《隨機羯磨》、《資持記》鈔指《行事鈔》）：這是南山三大部的結構骨幹，留著非常重要，但**同一份 prompt 只講一次就好**（目前講了兩次，見下節）。

## 二、自相矛盾、破損與重複之處

### 1. `BASE_PROMPT`（一審）字面已經因刪改而破損
在 `mk_review_materials.py`（及文件 §2.2）：
- 尼鈔版 `get_prompt(True)` 組出來第一句結尾多了一個孤立的 **`「含」`** 字（`……負責校訂【鈔文】的【現譯】。含`）。
- 疏記版 `get_prompt(False)` 組出來變成文法不通的殘句：
  `……亦須以【疏文】前提檢核【記文】科判動詞。含偷搬【記文】解釋進【疏文】、或【記文】原文無該欄則略去；或「銜接【記文】實詞須附原字」`
- 另外，§1 表格寫 `BASE_PROMPT` 是「四原則＋三欄輸出」，但實際程式碼裡只有原則 `1、2、4`（缺 `3`），輸出也只有單欄譯文。

### 2. `book_config.py` + `mk_blind_materials.py` 疊床架屋、自我重複
在 `mk_blind_materials.py` 裡，程式把 `cfg['note']`、`cfg['ctx'][0]`、`cfg['ctx'][1]` 和 `cfg['shuji_ban']` **全部串在同一個 `BLIND_PROMPT` 裡**。對《業疏》／《戒疏》而言，這會導致同一份提示詞內：
- 「`《業疏》「文／注」指《隨機羯磨》，《戒疏》「文／注」指《含注戒本》`」**連續出現兩次**；
- 「`【疏】【記】須義理相契`」**連續出現兩次**；
- 「`勿將記文專論搬進疏文`」**出現兩次**；
- 而且翻《業疏》時一直跟它講《戒疏》怎麼用、翻《資持記》時又同時塞《濟緣記》《行宗記》規則，增加無謂干擾。

### 3. 「疏記互核（保留銜接實詞）」與「不得增補／不得偷搬記文」互相拉扯
- `BLIND_PROMPT` 同時要求「不增原文所無細目」與「疏文略語與典故須依記文確認指涉並保留銜接實詞」，尺度原本就很微妙。
- 但 `AUDIT_PROMPT` **沒寫「為消歧義而保留銜接實詞不屬偷搬」**，因此容易重演 §7.3「審核誤判『水與水該刪』」。
- 更微妙的是：文件 §7.3 說已改用「勿無故偷搬專論」，但實際上看 `mk_audit_materials.py` 程式碼，頂端的 `NOTE_SHUJI` **根本是未使用的死變數**，程式第 143 行實際讀的是 `book_config.py` 的 `SHUJI_NOTE`——那裡面**完全沒有**「勿無故偷搬專論」這句話。

### 4. `SYSTEM_PROMPT` 工具說明與環境變數打架
- **斷網時自相矛盾**：當 `QWEN_NO_WEB=1` 時，第 2 條前面寫「`**僅限使用 local_search 檢索本地典籍**`」，但緊接著下面還是寫死 `web_search 1～2 次、web_fetch 1 次；用完即不得再呼叫`。
- **拆詞規格打架**：`local_search` 工具 schema 寫 `3~10 字純原文核心詞`，`SYSTEM_PROMPT` 寫 `以空格分隔 2～3 個實詞`，而 `qwen_local.py` 又會把任何含 1 字詞的查詢直接退回報錯。
- **額度數字寫死產生誤導**：`SYSTEM_PROMPT` 寫「上限可達 6」，但 §4.7 與 `qwen_local.py` 對單段原文的上限其實是 `1 / 2 / 3 / 5`（只有打包組才會再往上加到 6）。其實每次回傳都已附 `remaining`，提示詞不必寫死具體上限數字。

### 5. 長段切片（`mk_split_blind.py`）過度重複且與終審脫節
- 「嚴禁譯入前後背景」在單份長段材料裡**重複了 4～5 次**（Prompt 開頭、原則 1、`LONG_TAIL`、`（本單元為長文第 X/Y 部分…）`、以及前後文背景框標題）。
- `mk_split_blind.py` 對《業疏》《戒疏》長段一律把 `scope` 填成 `疏文與記文`，但單一長段實際上永遠只會有其中一欄（`【疏文】` 或 `【記文】`）。
- `mk_audit_materials.py` 裡的 `_long` 提示（檢查 `（本段前文）／（本段後文）`）在 `run_long_audit.py` 管線中是**死碼**，因為 `run_long_audit.py` 是先 `merge_long.py` 拼回整段後才建終審材料（且未帶任何前後文）。

### 6. `AUDIT_PROMPT`、`JUDGE_PROMPT` 與 `REVISE_PROMPT` 的規則落差與格式問題
- **`AUDIT_PROMPT` 第 2 點文意錯置**：`2. 【結論】：PASS 或 FIX（判 FIX 須列至少 1 項硬傷；判 PASS 則寫「無」）。`——「判 PASS 則寫『無』」是指第 3 欄而非第 2 欄，寫在結論欄裡容易誤導。
- **體例規則斷裂**：`BLIND_PROMPT` 嚴格規定「不用圓括號加解說、不寫校勘按語、不換公制、科判標題保持短語、保留反切某某反」，但 `JUDGE_PROMPT` 與 `REVISE_PROMPT` **幾乎沒重申括號／按語／反切規範**，導致裁決「重修」或「修訂」改寫句子時容易把括號注釋或按語引進來。
- **多處編號混亂**：
  - `SYSTEM_PROMPT`：`1, 2, 3, 5, 6`（缺 4）
  - `BASE_PROMPT`：`1, 2, 4`（缺 3）
  - `JUDGE_PROMPT`：`1, 3`（缺 2）
  - `pack_judge.py` 的 `RULE`：`1, 4, 2, 3`（順序錯亂；且提示寫「先按【疏文】【記文】【鈔文】集中」，但 `do_pack` 只打包 `len(bl)==1` 的單欄段落，根本不會出現多標籤集中問題）。

## 三、可以精簡與重構的方向

可以把提示詞拆成「**系統層共守通則**」＋「**單層書別提示（去重）**」＋「**極簡任務指令**」，大約可省掉 25–35% 的固定提示詞字數，同時消除重複打架：

1. **將「律典翻譯共守體例」統一收進系統層（包含 `NO_TOOLS_SYSTEM`）**
   - 把**典籍簡稱表**（伽論／婆沙等）、**反切保留「某某反」**、**體例四禁**（禁圓括號解說、禁校勘按語、保留 `〔X〕`／`〔疑作X〕`、度量保留原稱）抽成共用通則，讓 `blind / judge / audit / revise` 全部繼承。
   - `SYSTEM_PROMPT` 的「檢索原則」只管工具：依環境變數動態組裝（`NO_WEB=1` 就完全拿掉 `web_search/web_fetch` 描述），次數只說「**以工具回傳的 `remaining` 為準**」，不再寫死 `1～2 次` 或 `上限可達 6`。

2. **清理 `book_config.py` 的重複注入**
   - 讓 `業疏` 只讀《隨機羯磨》說明、`戒疏` 只讀《含注戒本》說明，不再互掛對方的書名。
   - 把 `SHUJI_NOTE`、`SHUJI_CTX`、`shuji_ban` 整合成單一無重複的短句，且只在「同組確實同時包含【疏文】與【記文】」時才啟用雙向互核與禁止搬移專論的說明；同時在 `AUDIT_PROMPT` 明確加上一句「**疏文為消歧義而保留的必要銜接實詞，不視為偷搬記文**」。

3. **精簡長段與打包提示**
   - 長段保留背景標題與結尾括注各一處禁譯即可，刪去 `LONG_TAIL` 中重複的前後文禁令。
   - `pack_judge.py` 的 `RULE` 改回正序 `1, 2, 3`，刪掉多餘的跨標籤集中說明（因為只打包單欄）。

4. **精簡後的各任務核心提示詞結構參考**（以 `BLIND` 與 `JUDGE` 為例）：
   - **`BLIND_PROMPT`**：角色＋書別規則（單一不重複）→ 三原則（1. 忠實不增減；2. 律義與文法：開遮、主客、時序界限、引文邊界；3. 簡明書面白話、標題短語、要件平實直譯）→ 標籤格式。
   - **`JUDGE_PROMPT`**：保留「以甲為主底本、最小改動」，補上一句「重修語句亦須遵守體例（不加解說括號與按語、保留原度量與音訓）」，修補 `1. 2.` 編號即可。

## 四、程式碼與管線上的其他問題

在比對第六節程式碼時，也發現幾個**直接影響品質或會讓部分段落悄悄出錯／遺漏的 Bug**：

### 1. `local_corpus.py` 的 `per_book=2` 限制 Bug（影響單書查詢）
`local_corpus.py` 第 175、191–192 行：
```python
def find(query, work=None, limit=6, pad=240, per_book=2):
    ...
    if per_book is None:
        per_book = rows if work else 2
```
- 預設是 `per_book=2`，所以 `if per_book is None:` **永遠進不去**（即使進去了，裡面寫的變數 `rows` 也未定義，會直接 `NameError`）。
- 後果：只要模型指定 `work="四分律"` 且 `rows=4`，`used["四分律"] >= 2` 就會被卡死，永遠最多只拿得到 **2 筆**結果。應將預設改為 `per_book=None`，並在函式內設 `per_book = limit if work else 2`。
- 另 `ALIASES` 建議補上單獨的 `('含注戒本', '戒疏')`（目前只有 `'四分律含注戒本'`），否則提示詞不斷強調「《戒疏》文注指《含注戒本》」，模型照查 `work="含注戒本"` 會先 miss 再觸發全庫放寬重搜。

### 2. `make_hybrid.py` 用子字串比對是否覆蓋，可能靜默漏段
`make_hybrid.py` 第 55–60 行：
```python
big = ''.join(bodies)
for k, seg in enumerate(a):
    ns = norm(seg)
    if ns and ns in big:
        idx.append(k)
```
如果某一卷的舊組裡已經有某段長文，剛好包含了一個短短 3～6 字的句子或科目名（例如「問曰。」「一、總明。」），同一卷裡其他獨立出現的同名短段都會因為 `ns in big` 成立而被標記為「已覆蓋」，導致新切出來的組**直接被跳過不建檔**。應改用材料標題裡的 `PROV` 段號區間（`s0..g1`）或精確整段比對來判定覆蓋。

### 3. 長段管線（`mk_split_blind.py` → `run_long_audit.py` → `run_pipeline.py`）的斷層
- **`mk_split_blind.py`**：`資持記` 分枝組 `_bctx` 少了一個分號（會直接黏接「…《四分律》辨古今異義」）；`尼鈔／行事鈔／義鈔` 漏了加上 `cfg['note']`（`mk_blind_materials.py` 有加）。
- **`run_long_audit.py`**：建立的 `_終審材料` **完全沒有附帶【前文背景】與【後文背景】**，但 `AUDIT_PROMPT` 第一句就要求「先逐句對照原文與前後背景核對」。建議把原段落前後文補進 `_終審材料`。
- **`run_pipeline.py` 與 `run_all_books.py`**：長段跑完 `_終修` 後，**沒有呼叫 `build_a2.py` 合成長段的最終定稿**（`merge_long.py` 寫出的 `_長段/_定稿` 是終審**前**的結果）。

### 4. `pack_judge.py` 拆回失敗未計入 `bad`
`do_split` 第 180–191 行若遇到模型漏編號或漏標籤，會直接把 `'（拆回失敗：缺段）'` 或 `'（拆回失敗：缺標籤）'` 寫入 `ok_key_回.txt` 並算作 `ok += 1`。若未即時攔截，這行錯誤字樣會被當成譯文繼續流進終審與定稿。應改計入 `bad` 並改寫至失敗記錄檔（或保留原個別檔案待補跑），不要覆寫成看似成功的 `_回.txt`。

### 5. `qwen_local.py` 的 `_looks_pasted` 與 `_src_unit` 誤殺風險
- `_src_unit(src_text)` 的結束邊界正則少了 `【待審譯文|裁決分歧參考|目前譯文|分段要求`（`SRC_RE_ALL` 有補上但 `_src_unit` 漏了）。在 `revise` 階段（`RAW_SAVE=1`）會把 `【目前譯文】` 也算進 `len(src_unit)`，使短句超過 40 字門檻。
- 此外，盲翻與修訂遇到「如《四分律》所說：『比丘若……』」或長經題、佛號開頭時，譯文開頭前 12 個漢字極易與原文完全重疊，導致 `_looks_pasted` 誤判成「重貼原文」並寫出 `.stage_partial` 卡停管線。建議門檻放寬為至少 18–20 漢字重疊，或僅在「整體字數重疊率也很高」時才判定重貼原文。

### 6. 其他小問題清單（供順手清理）
- **`mk_judge_materials.py`**：`_same(_a, _b)` 在標準用法 `--b out` 時因 `_b` 固定為 `None` 而不生效；且 `div` / `_r1s` / `_b` 在 `mk_revise_materials.py` 第 145–147 行是未使用的殘留碼。另 `mk_revise_materials.py` 讀 `r1_rep` 時缺檔案存在檢查，若少一個裁決回覆檔會整支中斷。
- **`mk_audit_materials.py`**：萃取裁決分歧時，`re.match(r'(.*?｜裁決[^：:]{0,15}[：:])(.*)', _s)` 若模型把 `乙優` 寫在冒號後面（`｜裁決：乙優，…`），`_tag` 會誤判為 `重修`。
- **`qc_scan.py`**：簡體字黑名單包含 `'后'` 與 `'里'`，會誤報律典常見正體詞「王后／皇后」與度量詞「五百里／鄰里」。
- **`norm.py`**：`_depth` 採跨行累加計算引號 `「」`，若遇到律典常見的「多段連續引文（每段頭加 `「`，僅末段尾加 `」`）」，`_depth` 會卡在 `>=1`，使該組後半部（例如同組記文）跳過異體字與簡體正規化。建議改為逐段重設或偵測行首 `「` 不對稱時重置。

**建議優先處理順序**：

2. 把 `book_config.py` 重複串接拆乾淨、抽離共用通則（讓 `NO_TOOLS_SYSTEM` 也吃得到典籍簡稱與體例），並拿掉 `SYSTEM_PROMPT` 裡跟開關衝突的工具／額度描述。
3. 補上 `make_hybrid.py` 的精確段號覆蓋檢查，以及長段管線最後的 `build_a2.py` 彙整步驟。
