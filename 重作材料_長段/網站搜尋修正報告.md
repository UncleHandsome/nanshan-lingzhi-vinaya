## 2. 根因

### 2.1 主因：索引與頁面由不同資料源、不同時期產生

- 舊索引由 `_src/site2.py` 用 `TXT_分卷`＋`AI語譯/out` 產生，anchor 是 site2 內部的 `s<body 元素序號>`。
- 六書頁面後來改由 `_src/render_canonical_cb.py` 從 `定稿/*.jsonl` 重建，pair 變成
  `<div class="pair …"><div class="o …">…</div><div class="t">…</div></div>`，
  **pair 完全沒有 id**，只剩篇名 `<h2 class="sec" id="pN">`。
- 因此索引裡的 anchor 有 27,505 筆是 `sN`，在新頁面上一個都不存在；六書那 41 筆「可用」全部是條目 anchor 本來就是篇名 `pN` 的少數情況（pN 共 243 筆，其餘多數連篇號都對不上）。
- 合編頁由 `_src/site_hebian.py` 產生，pair 有 `id="sN"`，所以 6,192 筆全中——這正是「只有合編能跳」的原因。

### 2.2 索引文字也與頁面不一致

- 舊索引的 `o` 沒有段別前綴，例如 `南山三大部之一…`；頁面是 `【鈔文】南山三大部之一…`，所以六書文字吻合率幾乎 0。
- 條目數與頁面 pair 數不一致：戒疏索引 9,691 筆 vs 頁面 7,614 對（多 2,077 筆頁面上不存在的條目）、尼鈔 807 vs 1,100（少 293 對）、義鈔 234 vs 509。
- 後果：有些結果點了頁面上根本沒有那段；有些頁面段落永遠搜不到。

### 2.3 著陸後沒有捲動與高亮

- `docs/nav.js` 的 `jumpToHash()` 只做 `document.getElementById(id)`；找不到就直接 `return`，沒有 `scrollIntoView`、沒有高亮。
- 而且 `jumpToHash()` 只在 `nav.json` fetch 成功後才被呼叫；`nav.json` 失敗（或 `file://`）時連篇名錨點都不會定位。

### 2.4 不是編碼／路由問題

- 頁面 `<meta charset="utf-8">`、索引 JSON 皆 UTF-8；檔名（`卷上.html`…）與索引 `v` 完全對得上，44 頁 0 缺失。

## 3. 修法

### 3.1 新索引生成器：`_src/build_search_index.py`（新增）

- **唯一來源改成實際輸出頁面** `docs/<book>/<vol>.html`，索引條目和頁面 pair 一對一。
- 錨點規則：
  1. pair 本身有 id（合編 `sN`）→ 直接用該 id；
  2. 沒有 id（六書）→ `pair-<ordinal>`，ordinal 是 `main` 內第幾個 `.pair`（0 起算，**含沒有原文的圖示 pair**）。
- 以 div 配對方式解析（不用貪婪 regex），`<br>` 轉換行、去標籤、還原 HTML 實體，`o`／`t` 與頁面一字不差。
- 每筆條目：`v`（卷）、`o`（原文）、`t`（白話）、`i`（anchor）、`n`（第 N 段，1 起算）。
- 內建 `verify()`：逐筆檢查頁面存在、anchor 可解析、段落文字相同、`n` 正確。
- CLI：`--only 書`、`--check`、`--quiet`；原子替換、可重複執行（idempotent）。

### 3.2 `docs/search.js`

- 連結集中到 `hitHref()`，anchor 直接取自索引。
- 結果列顯示「卷上　·　第 187 段　跳到該段 →」，讓使用者知道會跳到哪一段。
- 保留原本的漸進載入、競態保護、鍵盤操作。

### 3.3 `docs/nav.js`

- 新增 `resolveAnchor()`：先找 `getElementById`；`pair-N` 則解析成 `main .pair[N]`。
- `jumpToHash()` 支援 pair 錨點，鎖定後加上 `.searchhit`；`hashchange`、側欄點擊、`load` 都走同一條路。
- 一載入就先跳一次，**不必等 `nav.json`**；`nav.json` 失敗仍可定位。
- 保留原本「反覆校正到連續兩次一致」的 settle 邏輯（長頁字體載入後位置會變）。

### 3.4 `docs/style.css`

- `.pair.searchhit`／`h2.sec.searchhit`：3px 外框＋兩次背景閃爍；`prefers-reduced-motion` 時只留底色。
- `mark.kw`：段內關鍵字用亮黃底＋深色字＋2px 外框；`.pair.searchhit mark.kw` 再亮一階；深色模式另有配色。

### 3.5 生成器接線（避免再脫節）

- `_src/site2.py`：刪掉自己拼搜尋索引的區塊，頁面寫完後改呼叫 `BSI.build(site=SITE)`。
- `_src/site_hebian.py`：合編頁寫完後呼叫 `BSI.build(site=SITE, only=['hebian'], quiet=True)`。
- 同步來源檔 `_src/search.js`、`_src/nav.js`、`_src/site.css`（`site2.py` 會把這三份複製到 `docs/`）。
- **沒有動任何 `docs/**/*.html`**，也沒有動 `定稿/`、`AI語譯/`、`TXT*`。

### 3.6 驗收工具

- `_src/validate_site.py`：新增搜尋索引檢查（呼叫 `BSI.verify()`），有問題 rc=1；`--no-search` 可略過。
- `_src/check_search_links.py`（新增）：模擬 `search.js` 的比對／排序，逐筆驗證 anchor、段號、段落文字、關鍵詞是否真的在該段。

### 3.7 追加：著陸後段內關鍵字高亮

- `docs/search.js`：結果 href 改成 `卷.html?q=<query>#anchor`（query 在 hash 之前），`quickhit` 與 `hit` 都帶。
- `docs/nav.js`：著陸後讀 `?q=`，以空白拆成多個 exact term，`escRe()` 跳脫 regex；只在目標 `.pair`／`h2.sec` 內用 `TreeWalker` 走文字節點，把命中字串包成 `<mark class="kw">`。
  進場先清掉全頁舊 `mark.kw`（還原文字節點並 `normalize()`），換錨點不會重複疊 mark；只包既有字元，不新增／刪除文字。
- `docs/style.css`：`mark.kw` 明顯亮黃底，與 `.searchhit` 外框並存。

## 8. 仍無法處理／已知限制

七書都已建索引、0 失效，沒有「整本放棄」的書。但以下限制需要知道：

1. **六書的 `pair-N` 是結構錨點，不是頁面既有 id。**
   頁面 pair 目前真的沒有 id；依指示不手改書頁 HTML，所以由 `nav.js` 把 `pair-N` 解析成第 N 個 `.pair`。
   影響：訪客若停用 JS，或瀏覽器仍使用快取中的舊 `nav.js?v=14`，仍會停在頁首、也不會有段內關鍵字高亮。GitHub Pages 對 assets 約 10 分鐘快取，部署後第一次請硬重新整理（Ctrl+F5）。
   要徹底做到「免 JS 也能跳」，需頁面生成器下一次重建時替 pair 輸出 `id="pair-N"`；本次未動頁面，索引已用同一套 ordinal，屆時直接沿用。
2. **資持記 25 筆科判圖**（`<pre class="ko">`，方框線條排版，沒有 `.o` 原文區塊）不進索引；頁面仍完整保留，且其 ordinal 仍計入錨點，不影響後續段落定位。
3. **資持記 5 卷在 `nav.json` 沒有篇名清單**（上一上、中一下、中二、中三上、中三下），搜尋頁的「篇目捷徑」對這幾卷列不出篇；這是目錄資料缺口，不屬搜尋索引，未動 `nav.json`。
4. **舊索引有、頁面沒有的條目已移除**：戒疏少 2,077 筆、業疏少 209 筆、資持記少 50 筆（多為舊 build 的重複或材料端條目）；這些結果原本點了也到不了。反向地，行事鈔＋551、尼鈔＋293、義鈔＋275 是頁面上本來就有、舊索引漏掉的段落，現在搜得到了。
5. 索引綁定「目前頁面」。日後只要重建任何書頁，**必須重跑** `python -X utf8 _src/build_search_index.py`（`validate_site.py` 會直接抓出 anchor 失效）。已接線：`site2.py`／`site_hebian.py` 重建頁面後會自動重跑。
