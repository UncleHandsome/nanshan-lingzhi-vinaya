先說清楚一件事：本次檢查時，`display_source` 已經不是「全部空或無標點」；先前流程已把 98 段低句讀補過。真正的殘留問題是：

1. `TXT_分卷/05_拾毗尼義鈔_標點對齊` 仍有大量 100–500 字原文區間沒有句讀（舊 `mk_punctuate --min 500` 跳過）。
2. 定稿有 **92 段** `display_source` 的尾端標點被截掉（例如 key 105 結尾少 `。」`），因漢字序列仍相同，`validate_site.py` 的 1% 密度門檻抓不到。
3. row 層 `display_source` 有 134 列仍是 raw，與 segment 層不一致。
4. 抽樣 10 段用 `source`（raw），所以看起來零句讀。

本次把這四件事一併修掉。

## 1. 原本跳過幾段

`mk_punctuate.py` 舊版 `--min` 預設 500，且判斷式是 `if len(line) <= args.min: continue`，所以 500 字（含）以下全部跳過。

以 `TXT_分卷/05_拾毗尼義鈔` 9 個分卷檔、去檔頭 5 行後的非空行計：

| 行長（字元） | 行數 | 舊程式 |
|:--|--:|:--|
| >500 | 27 | 有做 |
| 101–500 | 97 | **跳過** |
| ≤100 | 110 | 跳過 |
| 合計 | 234 | 只做 27 行，跳過 207 行 |

- 100–500 字（含界）共 98 行；其中 97 行是 101–500 的正常段落，另 1 行剛好 100 字（key 108，先前已另有句讀）。
- 在定稿層：509 段中，100–500 漢字的有 **182 段**；這 182 段對應到 `_標點對齊` 裡 **97 個無句讀 span**（其餘落在已標點的長行內）。
- 修正前 `display_source` 的 182 段雖然都有標點，但有 **92 段尾端標點被截**，等於句末不完整。

## 2. 程式修正（`_src/mk_punctuate.py`）

- `--min` 預設由 **500 改為 0**，非空行全部可處理。
- 新增 `--max`（0＝不限）、`--work`、`--out`、`--dry-run`、`--allow-empty`。
- `--verify` 若 0 段可套用，預設**不寫入**，避免把既有句讀覆蓋成 raw。
- `--verify` 若輸出檔已存在且漢字序列與 raw 相同，以既有句讀為底，只替換本次驗證透過的行。
- 缺回覆改為只印總結，不逐段洗版。

實跑結果：

```text
python -X utf8 _src/mk_punctuate.py --book 義鈔 --dry-run
義鈔：--min 0 --max 0 會選 234 段（其中 100–500 字 98 段；跳過 0 段）

python -X utf8 _src/mk_punctuate.py --book 義鈔 --min 100 --max 500 --dry-run
義鈔：--min 100 --max 500 會選 97 段（其中 100–500 字 97 段；跳過 137 段）

python -X utf8 _src/mk_punctuate.py --book 義鈔 --min 100 --max 500 --work "測試\標點\義鈔_短段"
義鈔：97 段待標點（100–500 字 97 段；跳過 137 段）
```

材料實際產出在 `測試/標點/義鈔_短段/_材料/`（97 個 `.md`＋`meta.json`）。  
另用同一批 97 段材料做離線 `--verify` 測試（回覆取定稿已驗證的 `display_source`，只測程式流程）：

```text
已標點 97／97 段（缺回覆 0、字詞不符 0）
```

再用 `_標點對齊` 的複本測「既有句讀不會被覆蓋」：verify 前後標點總數都是 **12,361**，沒有被重建成 raw。  
這證明新程式對 100–500 字短段是端到端可跑的，且可安全地只替換缺句讀的行，不是只改預設值。
