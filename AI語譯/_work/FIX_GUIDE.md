# 校對意見套用指南（給執行修訂的代理）

本專案：南山三大部（道宣律師）律典白話語譯。目錄 `C:\Users\lionc\OneDrive\桌面\XW\三大部`。

## 一、檔案格式

- 譯文檔：`AI語譯\out\<書>\<分塊>.txt`，UTF-8。
- 檔案內每個「非空段落」= 原文的一個段落（segment），段落之間以「一個空行」分隔。
  即：`paras = [x for x in text.split('\n\n') if x.strip()]`，第 i 個段落對應段號 `seg = i+1`。
- **段數絕對不可改變**：不得合併、拆分、刪除、新增段落；不得多留空白行。
- 文末可能有單一換行，正常。
- 部分段落開頭有 `【疏文】`、`【註文】`、`【律文】`、`【記文】`、`【疏】`、`【記】` 標籤：**保留原標籤不動**（後續有統一程序），修訂時只改標籤之後的內容。

## 二、校對意見檔

- 位置：`AI語譯\review_low_all\<書>__<分塊>.json`，陣列，每項：
  - `seg`：段號（1 起，字串或整數）
  - `kind`：誤譯／漏譯／增譯／術語錯誤／語病／分段不合／校勘
  - `issue`：問題說明
  - `quote`：原文或譯文摘句（供定位）
  - `fix`：建議改法（可能是完整句子、詞語替換、或僅是說明）
- 一個分塊檔可有多條意見，`seg` 可能重複。

## 二之一、重要：多數意見可能已套用

譯文檔常在 review JSON 產生**之後**又改過（檔案 mtime 較新）。因此：

1. 先逐條比對「現有譯文 vs 建議改法（fix）」；若現文已符合意見，**不要重改**，記為 `already`。
2. 只有現文仍不符者才動手改。
3. 全部處理完（含 already）才把 JSON 移到 review_done。
4. 判斷標準：以意義為準，不要求字面相同。

## 三、修訂原則

1. **以意見為線索，不盲從**：`fix` 若明顯較差、答非所問、只是「請重譯」而無內容、或本身理解錯誤，可自行改寫或保留原文，並在報告中註明 `rejected`。
2. **只改有問題的段落**，其餘段落一字不動。
3. **譯文風格**：現代繁體中文白話，語體與上下文一致；律學術語用通行譯名（波羅夷、僧殘、波逸提＝單墮、突吉羅、偷蘭遮、羯磨、犍度…）。
4. **不得**新增 `【…】` 標籤、不得加入「譯者按」「（待考）」等雜訊、不得抄錄原文冒充白話。
5. **不得**改動原文（`TXT_分卷`）任何檔案。
6. 段落若在檔中不唯一（同文重複），用 `quote` 定位，必要時多看前後段確認。

## 四、操作步驟（務必照做）

1. 先記錄段數：
   `python _src\paracount.py "AI語譯\out\<書>\<分塊>.txt"`
2. 用 read 讀該譯文檔與對應 review JSON；逐條處理，用 edit 逐段替換（`old_string` 用該段完整文字）。
3. 改完再跑一次 `paracount.py`，**paras 數字必須與第 1 步完全相同**；不同就修正到相同。
4. 該分塊全部處理完後，把 review JSON 移到已處理區（建立目錄若無）：
   `Move-Item "AI語譯\review_low_all\<書>__<分塊>.json" "AI語譯\review_done\<書>__<分塊>.json"`
   若不確定是否全部處理完，就不要搬。
5. 不要動其他檔案、不要重排整份文件、不要寫入 BOM。

## 五、回報格式（最後一段輸出）

只輸出一個 JSON 物件（不要加說明文字）：

```json
{"chunks":[{"file":"02_戒疏__18b_卷四上之三","paras_before":141,"paras_after":141,"applied":3,"already":5,"rejected":0,"notes":["seg62 採納","seg108 意見不成立，保留"]}],
 "problems":["若某檔無法處理，寫在此"]}
```

`applied` = 實際有修改的段數（同一段多條意見只算 1），`already` = 現文已符合、未動手，`rejected` = 判斷不採納的意見數。
