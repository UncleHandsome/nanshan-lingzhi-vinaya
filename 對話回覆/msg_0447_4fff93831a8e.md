## 一、會靜默弄壞資料或流程的嚴重 Bug

### 1. `pack_judge.py` 拆回時把「整包 `p0001`」當成單組複製過去，且污染分歧參考
* **檔名比對錯位（產出重複垃圾檔）**：在 `do_split()` 尾段：
  ```python
  for f in sorted(os.listdir(out)):
      if not f.endswith('.md') or f in index:
          continue
  ```
  `f` 是 `'p0001.md'`，但 `index` 的鍵是 `'p0001'`（不含 `.md`），所以 `f in index` **永遠是 `False`**。結果每個打包檔 `p0001.md` 與 `p0001_回.txt` 都會被當成「未打包的單組」複製進 `_拆回/`，導致下游審核、修訂、定稿全部重複跑一次 `p0001` 並產出多餘的 `p0001.txt`。
* **分歧參考跨組污染**：`do_split()` 把打包檔完整的 `div`（含 `[1]～[6]` 全部組的分歧）直接塞進每一組拆回來的 `_回.txt` 第 2 欄。之後進 `mk_audit_materials.py` 時，第 `[3]` 組的 `【裁決分歧參考】` 會帶著其他 5 段的原文與甲乙譯文，而 `AUDIT_PROMPT` 又要求「須逐項驗明所採一方是否確與原文相容」，極易混淆審核模型。

### 2. `mk_split_blind.py` 的 `LONG_TAIL` 根本沒塞進提示詞
在 `mk_split_blind.py` 開頭定義了很關鍵的長段銜接規則 `LONG_TAIL`（勿補主詞、勿強加句號、勿重複譯出本段前文/後文），也在迴圈裡傳給了 `.format(..., tail_rule=LONG_TAIL, shuji_ban=...)`——**但該檔案裡的 `BLIND_PROMPT` 字串中根本沒有寫 `{tail_rule}` 和 `{shuji_ban}` 兩個佔位符**！
Python 的 `.format()` 會靜默忽略多餘參數，等於長段切分跑盲翻時完全沒收到銜接指示（而且這支腳本裡的 `BLIND_PROMPT` 也還是舊版，缺了反切音訓、他宗破執、簡稱對照、`〔疑作X〕` 等新版規則）。

### 3. `run_pipeline.py` 的三處接縫錯位
* **`.stage_partial` 檢查永遠失效**：在 `run_agent()` 中，判斷失敗旗標寫的是：
  ```python
  d = os.path.join(B, batch.replace('/', os.sep)) if not os.path.isabs(batch) else batch
  if os.path.exists(os.path.join(d, '.stage_partial')):
  ```
  但 `qwen_local.py` 的批次目錄在 `B/測試/<batch>`，且 `.stage_partial` 是寫在 `回覆/` 子目錄裡（`測試/<batch>/回覆/.stage_partial`）。兩邊都對不上，導致哪怕上一關有檔案截斷或 400 擋掉，`run_pipeline.py` 還是會照常往下推到修訂與定稿。
* **重跑成功不會清掉舊的 `.stage_partial`**：`qwen_local.py` 在 `fail == 0` 時只寫入 `.stage_done`，沒刪掉先前留下的 `.stage_partial`。
* **混合切法（`_hy`）前後階段路徑不對稱**：`review` 懂得讀 `_材料_hy`、`judge` 的 `--a` 懂得讀 `_hy_盲翻/回覆`，但 `judge` 的 `--src` 卻寫死 `_材料`（不是 `_材料_hy`），`final` 的 `--blind` 也寫死 `_盲翻`（不是 `_hy_盲翻`），跑混合切法時會漏掉 `n0001+` 的新組。

### 4. `norm.py` 會誤改佛學專詞、篇名號與記文標籤
* **`VAR_MAP` 把「迴」轉成「回」**：這會把**「輪迴」改成「輪回」、「迴向」改成「回向」**，在律典與佛教文獻中屬於明確錯字。
* **`_book_title` 誤傷非典型結尾的篇品名**：正則只放行 `篇|品|章|節|門|科|犍度` 七字結尾，其餘 `〈…〉` 一律強轉為 `《…》`。像南山三大部常見的 `〈發戒境〉`、`〈出戒體〉`、`〈持犯方軌〉`、`〈序〉` 都會被強制變成書名號《》，同時又沒有處理誤寫成 `《受戒篇》` 的情況。
* **`LABEL_FIX` 會把 `【記文（修訂）】` 蓋成 `【疏文】`**：
  ```python
  for _cand in ('疏文', '記文', '律文', '註文', '序文'):
      if '【%s】' % _cand in _txt ...:
          _lab = _cand
          break
  for _a in LABEL_FIX:
      _txt = _txt.replace(_a, '【%s】' % _lab)
  ```
  一旦同段有 `【疏文】` 和 `【記文（修訂）】`，迴圈在 `'疏文'` 就 `break`，整段所有 `LABEL_FIX`（包含 `【記文（修訂）】`）都會被替換成 `【疏文】`！另外單欄的《業疏》若偶發寫出 `【修正後譯文】`，因全文找不到 `【疏文】`，也會被預設值硬改成 `【鈔文】`。
* **`norm.py` 死碼與簡體字漏網**：`VAR_MAP` 先把 `时` 轉成 `時`、`为` 轉成 `為`，後面 `replace('时候', '時候')` 根本不會命中；同時大量常見簡體（如 `这` 以外的 `实/际/会/发/还/没/达/证/对` 等）只靠零星幾字很難清乾淨。

## 二、檢索層（`local_corpus.py` 與 `qwen_local.py`）的隱性問題

### 5. `local_corpus.py` 查詢開頭撞到別名時會「反客為主」
`_split_work(query)` 在 `find()` 裡無條件執行：
```python
for alias, target in ALIASES:
    if q.startswith(alias) and len(q) > len(alias) + 1:
        return target, q[len(alias):].strip()
```
只要模型想在《業疏》《資持記》裡查某句**引論引文**（例如開頭寫 `"婆沙云何"`、`"成論三宗"`、`"善生戒經"`、`"伽論所明"`），`find()` 會自動把「婆沙／成論／善生／伽論」**從關鍵詞剝掉**，並把 `work` 鎖死到《薩婆多毘尼毘婆沙》或《成實論》裡面搜「云何／三宗」；就算在 `qwen_local.py` 查無觸發 `relaxed` 把 `work` 放寬為 `None` 重叫一次 `find()`，`_split_work` 還是會再鎖回去一次！

### 6. `web_search` 的正規化會把「於」改成「于」
`qwen_local.py` 的 `_VAR_MAP` 含有 `於 -> 于`（比照 `local_corpus.py`），但 `web_search` 送往 DeepSeek API 前也跑了 `.translate(_VAR_MAP)`。CBETA 與維基文庫幾乎全用「於」（如「於僧中」「於此」），把查詢詞裡的「於」改成「于」反而會讓外網搜尋漏掉大量正典命中。

### 7. 多詞鄰近 `kwic` 視窗只鎖定第一個詞、且誤記快取
* `local_corpus.py` 的 `kwic` 切片中心固定算在 `terms[0]`（`anchor`）上。當行文較長或 `terms[0]` 屬於高頻詞（如「比丘」）時，一則容易抓到前兩行（`idx-2`）的 `terms[0]`，二則前後 240 字視窗常常把真正的罕見關鍵詞 `terms[1]` 切在視窗外。
* `qwen_local.py` 的 `ds_cache` 沒有過期時間（TTL），一旦網路搜尋暫時回傳空陣列 `[]`，這個空結果會永久寫死進 SQLite 快取。
* `qwen_local.py` 統計打包段數 `_pn = len(re.findall(r'(?m)^\s*\[\d+\]', text))` 會把「原文」「譯本甲」「譯本乙」裡的 `[1][2]` 全部加總（膨脹 2～3 倍）。

## 三、文字擷取、定稿組裝與規範落差

### 8. `build_a2.py` 對修訂回覆的兩處脆弱點
* **極短段被誤殺為異常**：`if not txt or len(txt) < 8: txt = None`。三大部與鈔記有大量 1～3 字篇題或科題（`min_shu = 1`），加上 `【疏文】\n` 只有 6～7 個字，一旦進入修訂就會因 `< 8` 字被判定失敗而退回未修訂版。
* **駁回說明外洩進定稿**：`REVISE_PROMPT` 要求模型可「駁回該項」，卻未提供「純譯文＋理由分離」的機制，只說「勿輸出清單」。模型若在譯文**末尾**附帶一句 `（按：硬傷第 2 項因……予以駁回）`，`build_a2.py` 與 `norm.py` 都不會清除譯文尾巴的按語，會直接進入 `_定稿/*.txt`。反之若模型把 `【疏文】` 標籤漏掉，`col3()` 會直接丟出 `ValueError` 放棄整份修訂。

### 9. `AUDIT_PROMPT` 與 `BLIND_PROMPT` 在「科判標題短語」上的衝突
`BLIND_PROMPT` 第 1 條特地規定：「若原文屬科判標題、條目綱要或極簡承接語，保留名詞性或精簡短語即可，勿為湊完整句而擴寫」；但 `AUDIT_PROMPT` 完全沒有寫入這條豁免。審核模型遇到純名詞性的科判標題時，容易依第 6 條「動詞缺主賓／文言未譯」判 `FIX`，逼修訂階段把它擴寫成完整散文，隨後又觸發 `qc_scan.py` 的「短文膨脹」警報。

### 10. 工具腳本與正規表示式未同步更新
* `_looks_pasted()`（`qwen_local.py`）和 `_clean()`（`merge_long.py`）裡仍留著 7.11 說要修的雙斜線錯誤：`r'^\\s*【...】\\s*'`（在 raw string 中變成匹配字面 `\s`）。
* `qc_scan.py` 的 `load_material()` 與 `materials_io.py` 的 `SRC_RE`/`TR_RE` 沒有同步更新 `SRC_RE_ALL` 的邊界前瞻（缺 `【待審譯文】|【裁決分歧參考】|【目前譯文】|【分段要求】` 與 `(?:\[\d+\])?`），若拿 `_裁決` 或 `_終審` 材料餵給 `qc_scan.py`，會把待審譯文與分歧參考一併吃進原文長度計算，導致膨脹檢測失真。
* `mk_review_materials.py` 的 `prompt_for(unit, book)` 當 `unit == '記文'` 時把 `ctx` 設為空字串，這會讓單欄《資持記》的提醒（鈔指《行事鈔》、疏指《業疏》…）在該支腳本路徑下遺失。
* `run_all_books.py` 跑完長段盲翻就直接 `merge_long.py` 產出 `_長段/_定稿`，完全繞過裁決、審核與修訂，長段品質會和一般段出現明顯落差（與 7.14 待辦相符，但腳本本身已寫死接 `_定稿`，後續別忘記補跑長段審修後再覆蓋）。
