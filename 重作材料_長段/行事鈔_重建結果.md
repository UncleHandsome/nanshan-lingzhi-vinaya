## 二、結論：缺口無法歸零，原因是新譯本身就缺 29.5% 的原文

**`_終審`／`_終修/回覆`／`_定稿` 三個新譯來源合起來，只覆蓋 225,037 漢字中的 158,708 字**（70.53%）。剩下 66,329 字在整個新譯流程裡**沒有任何譯文**，缺的不是零星漏段，而是整段整段的內容，例如：

- 第 109 號單位的原文只有「第二就制教中分兩。」8 字，其後 1,180 字全部落在它的【後文背景】裡（背景只有原文、沒有譯文），該段從未進入終審。
- 96 段缺口裡最小的一段也有 397 字，中位 552 字，最大 2,021 字。

因此本次**不補**（依指示：頁面舊譯不得用來補缺口），只把有位置、無重疊、無重複做完，把缺口原樣列出（見第七節），供下一輪補譯。

> 前一版曾用 `docs/xingshichao` 的頁面 pair 把缺口補到 0；因頁面是舊譯，該版已作廢，未保留。

## 三、來源與取用規則

只使用：

- `測試/重譯/行事鈔/_終審/<key>.md`（1,441 檔）
- `測試/重譯/行事鈔/_終修/回覆/<key>_回.txt`

**未使用**：`_材料`、`_盲翻`、`_裁決`、`_長段`、`_全書.txt`、`AI語譯/out`、`docs` 頁面譯文。

原文抽取規則（依義鈔範本）：

1. 只在 `■ …（原文）` 標記**之後**取正文。
2. 截斷於：下一個 `■ …（`、`【待審譯文】`、`【裁決`、`【後文背景`、`\n---`。
3. **沒有**整段抓 `【原文】`（`_終審` 檔頭的提示詞本身就含「【原文】」字樣，直接抓會抓到提示詞）。
4. 全書 `（現譯）` 區塊 0 個。

譯文取用規則：

```text
定稿 存在且與待審不同 / 或無回覆  → 用定稿
否則 回覆 存在                    → 用回覆
否則 用定稿（此時定稿 == 待審）
```

此規則下 23 個單位改用回覆（149、161、397、450、612、899、902、976、978、1030、1109、1141、1184、1214、1259、1302、1324、1341、1376、1384、1397、1440 等），已逐筆檢視，皆為完整修訂文，無截斷。

## 四、定位方式

1. 把 `TXT/01_…行事鈔.txt` 正規化成「純漢字序列」`H`（225,037 字），並記 han→原文索引對照。
2. 以**上一單位終點為游標**，用漢字前綴 `20 → 12 → 8 → 4` 字在 `H[cursor:]` 內找起點；找到後 `cursor = 起點 + 該單位漢字長度`。
   - 游標只前進，**結構上不可能產生重疊**。
   - 全書 1,478 個單位全部命中，未定位 0。
3. `raw_end = raw_start + len(正規化原文)`，區間長度完全由原文決定，**沒有拉大**。
4. vol / chunk 由原文卷題（`四分律刪繁補闕行事鈔卷上之一` … 卷下之四，共 12 個）的位置推算；12 個 chunk 全數有單位，`vol` 與 `chunk` 100% 相符。

**交叉驗證**：1,441 個終審單位的區間，起點與終點 **100% 落在 `docs` pair 的邊界上**（`骨幹未對齊pair邊界 = 0`）。這證明定位結果與網頁既有的段落切分完全一致，不是硬拉出來的。
