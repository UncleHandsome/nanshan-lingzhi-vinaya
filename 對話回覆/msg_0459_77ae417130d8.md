## 一、會「沉默掉資料或誤判」的高風險程式 Bug

### 1. `mk_judge_materials.py`：盲翻譯文若出現「修正」二字，【疏文】會被整段切掉
在 `mk_judge_materials.py` 的 `col3(rt)`（同樣的寫法也在 `mk_audit_materials.py`、`mk_revise_materials.py`）：
```python
_k = rt.rfind('修正')
_from = _k if _k >= 0 else len(rt)
mm = re.compile(r'【(?:疏文|記文|鈔文|律文|註文|序文)】').search(rt, _from)
if mm:
    return re.sub(..., rt[mm.start():]...)
```
- `mk_judge_materials.py` 對 `--a` 與 `--b` **無條件呼叫 `col3_soft()`**，但盲翻稿（`QWEN_RAW_SAVE=1`）是純譯文，根本沒有第 1/2/3 欄標題！
- 律典白話譯文裡非常容易出現「**修正**行為／**修正**正法／**修正**戒行」等詞。一旦雙欄（疏文＋記文）盲翻稿的【疏文】裡出現「修正」二字，`col3()` 就會從那兩個字往後找到【記文】，**把整段【疏文】無聲截斷丟棄**，只回傳【記文】；接著 `_pick(a_map, '疏文')` 又默默拿 `non_ji_old`（現譯）頂替進去。
- **解法**：`col3_soft` 應只用在三欄報告（一審／裁決／修訂），或確認文本真有 `結論`／`分歧與裁決`／`修正後的譯文` 標題時才切第 3 欄，絕對不要拿 `rfind('修正')` 當兜底。

### 2. `mk_judge_materials.py`：甲乙同文捷徑（`_same`）會害下游產出「空白譯文」
在 `mk_judge_materials.py`：
```python
if _a and _b and _same(_a, _b):
    shutil.copy2(os.path.join(src, fn), os.path.join(out, fn))
    ...
    io.open(_w, 'w', ...).write('...PASS_A_KEEP_A\n')
```
- 這裡直接把 `src/fn` 複製到裁決輸出目錄，但 `src/fn` 裡的標籤是 `■ 疏文（現譯）`（或只有原文），**並沒有 `■ 疏文（譯本甲）`**。
- 下游 `mk_audit_materials.py` 和 `build_a2.py` 看到 `PASS_A_KEEP_A`，就會呼叫 `MI.from_jia(t)` 去抓 `■ ...（譯本甲）`，結果抓到**空字串 `""`**（不是 `None`，不會報錯略過），導致**終審拿到空的【待審譯文】、定稿寫出空白檔**。

### 3. `pack_judge.py`：拆回時 `f in index` 永遠為 `False`，整包未拆檔直接外洩
在 `pack_judge.py` 的 `do_split()` 最後：
```python
for f in sorted(os.listdir(out)):
    if not f.endswith('.md') or f in index:
        continue
```
- `index` 的鍵是不含副檔名的 `'p0001'`，而 `f` 是 `'p0001.md'`，所以 **`f in index` 永遠是 `False`**！
- 結果 `p0001.md` 和 `p0001_回.txt` 也會一起被複製進 `_拆回/`（和拆開的原始檔並存），下游審核與定稿會把整包和單組重複各跑一次。應該改為 `f[:-3] in index`。

### 4. `materials_io.py`：`verdict()` 遇到小括號提示或「（無）／暫無」會把 `PASS` 硬轉成 `FIX`
```python
h = re.search(r'【必改硬傷】\s*(.{0,60})', rt, re.S)
if h and not h.group(1).strip().lstrip('*：: -').startswith('無'):
    return 'FIX'
```
- 由於 `AUDIT_PROMPT` 模板寫著 `3. **【必改硬傷】**（無則寫「無」）：`，只要模型輸出時照抄了括號提示（`【必改硬傷】（無則寫「無」）：無`），或者寫成 `（無）`、`暫無`、`沒有`，`lstrip('*：: -')` 後第一個字不是 `無`，**即使 `【結論】` 明寫 `PASS`，也會被強制判成 `FIX`**，白跑修訂流程。

### 5. `run_pipeline.py` 的路徑與狀態旗標 Bug（自動管線停不住）
- **`run_agent()` 漏了 `測試/` 和 `回覆/`**：檢查 `.stage_partial` 時寫成 `d = os.path.join(B, batch)`，但 `qwen_local.py` 是寫在 `三大部/測試/<batch>/回覆/.stage_partial`，結果永遠檢查不到部分失敗，缺檔照樣往下推到定稿。
- **`qwen_local.py` 未清除舊狀態旗標**：重跑續跑時只寫入新旗標（`.stage_done` 或 `.stage_partial`），沒刪掉前一次殘留的對立旗標，之後 `wait_done()` 看到舊的 `.stage_done` 就會誤判完成。
- **混合切法目錄不一致**：`review` 會判斷 `_材料_hy`，但同一支腳本裡的 `judge` 寫死 `--src _材料`、`final` 寫死 `--blind _盲翻`，跑 `_hy` 批次時會對錯目錄。

## 二、定稿正規化（`norm.py`）與檢索（`local_corpus.py`）的誤殺問題

### 6. `norm.py` 會把佛教常見字「迴」改錯，並把章節名誤轉成書名號
1. **`VAR_MAP` 把所有 `迴 → 回`**：
   佛典高頻專名與詞彙如**「迴向、輪迴、迴避、迴心、巡迴」**，在台灣正體律學文獻均用「**迴**」，全部轉成「回向、輪回、回避」反而是錯字。
2. **`_book_title()` 誤改不帶「篇／品」後綴的章節名**：
   ```python
   if body.endswith(('篇', '品', '章', '節', '門', '科', '犍度')) or follow:
       return '〈' + body + '〉' + follow
   return '《' + body + '》'
   ```
   三大部與記文大量篇門章節標題本身並不帶「篇／品」字尾（例如 `〈宗體〉`、`〈持犯〉`、`〈隨戒釋相〉`、`〈懺六聚法〉`、`〈序〉`、`〈釋名〉`），這條正則會把它們通通強制改成《宗體》《隨戒釋相》，反而破壞書名號與篇名號的區分（`norm.py` 不該猜沒在書單裡的 `〈...〉` 是不是書，只轉換已知書名清單比較安全）。

### 7. `local_corpus.py`：`_split_work()` 誤削查詢詞，且排錯別名順序
1. **已指定 `work` 時仍從 `query` 硬砍書名**：
   `auto_work, core = _split_work(query)` 在 `find()` 一開始就改寫 `core`。如果模型指定 `work='業疏'` 去查業疏裡引述的**「成論師」「善見云」「涅槃疏」**，`_split_work` 會把開頭的 `成論／善見／涅槃` 砍掉，讓原本想搜「成論師」變成只搜「師」（而且就算放寬回全庫，詞已經被砍壞了）。只有 `work is None` 時才應該拆前綴。
2. **`ALIASES` 順序錯誤**：
   `('善生', '優婆塞戒經')` 排在 `('善生經', '優婆塞戒經')` 前面，查 `善生經云何` 會先命中 `善生`，留下 `經云何` 當關鍵詞去搜，導致查無。

### 8. `qwen_local.py` 與 `qc_scan.py` 的打包／雙欄小漏洞
- **自搜過濾對「打包段」與「雙欄後半段」失效**：`own_text` 去掉 `[\W_]+` 後，打包段的 `[1] 原文...` 會變成 `'1原文...'`，開頭多了一個 `'1'`，導致 `own[:20]` 永遠匹配不到書庫原文；且 `own[:20]` 只取第一段前 20 字，長段後半或雙欄的【記文】自己搜到自己時依然濾不掉。
- **`SRC_RE` 未兼容 `pack_judge` 與審核格式**：`materials_io.py` 與 `qc_scan.py` 的 `SRC_RE` 都漏了 `(?:\[\d+\])?`；且 `qc_scan.py` 若掃描審核（單欄）材料，正則會一路吃過 `【裁決分歧參考】` 和 `【待審譯文】` 直到 `【後文背景】`，把待審譯文字數也算進原文長度 `sh`。
- **`_strip_head_paren` 可能誤刪譯文開頭的合法括號**：`qwen_local.py`、`mk_audit`、`mk_revise`、`build_a2` 四處都無條件把第 3 欄開頭第一組 `（...）` 砍掉。萬一模型某次沒寫 `【疏文】` 標籤（或切出後首字是合法括號），開頭補出的主詞如 `（受戒者）來到壇前……` 或條目 `（一）……` 會被直接刪掉。建議只剝包含後設說明關鍵字（如 `完整`、`譯文`、`修訂`、`保持`）的括號。

## 三、跨關卡提示詞與流程銜接問題

### 9. `REVISE_PROMPT` 叫修訂員「可採回譯本甲或乙」，但材料裡沒給甲和乙
- `REVISE_PROMPT` 明確寫：`若原本譯本甲或乙已更精準，可採回原譯法`（第 7.4 節也說「修訂須對照甲」）。
- 但實際看 `mk_revise_materials.py`，組裝出的材料**只有【原文】、【目前譯文】、【裁決分歧（僅供參考）】**，並沒有附上完整的【譯本甲】和【譯本乙】（裁決若判 `PASS_A` 甚至沒有分歧摘要；即使有，也只有片語摘錄）。修訂員在「無工具模式（`NO_TOOLS=1`）」下想採回甲或乙也無從採起。

### 10. `mk_judge_materials.py` 的 CLI 參數說明與實際管線相反
- 文件第 1 節（`甲＝B，乙＝A0`）、第 5 節範例（`--a <B回覆> --b out`）與 `run_pipeline.py` 都是**甲放盲翻 `B`、乙放現譯 `out`**（因為 `PASS_A` 要沿用盲翻）。
- 但 `mk_judge_materials.py` 自己的 `argparse` help 寫的是：`--a: out（用現譯）或回覆目錄`、`--b: 盲翻回覆目錄`，剛好寫反了。人工單獨重跑某一步時極易傳反，導致 `PASS_A` 全部沿用舊現譯。

### 11. `pack_judge.py` 併包未檢查段號連續性
- `do_pack` 只檢查同卷（`chunk`）與字數上限，沒有檢查相鄰兩份材料之間有沒有「因為 >500 字被抽去 `mk_split_blind`」而跳號。一旦中間跳過了一段 600 字的長文，打包後的 `[2]` 看不到那段 600 字長文作為前文背景，承前指代就容易斷裂。

### 12. `mk_review_materials.py` 對「一短一長配對」的拆散現象
- 業疏／戒疏 Loop 1 要求配對組必須同時滿足 `40 <= 疏 <= 500` 且 `40 <= 記 <= 500`。若碰到一段 **30 字短【疏】＋200 字【記】**，Loop 1 會放過它，接著 Loop 2 把【疏】和【記】**各自拆成兩個不相干的單欄組**，反而破壞了原本「疏記雙欄對讀」的結構（其實 `min_shu` 放寬或對「已有記文緊隨的短疏」允許進雙欄組會更自然）。
