### 一、流程與解析的隱藏 Bug（可能靜默丟資料或誤判）

#### 1. `pack_judge.py` 拆回時有兩處漏網之魚
* **每個單段都會吃到「整包」的分歧紀錄**：第 161 行明明已經辛辛苦苦篩出了只屬於第 `i` 段的 `_d = '\n'.join(_by_i[i])`，但第 169 行寫檔時卻忘記用 `_d`，而是把整包的 **`div`** 塞了進去。結果是：同一包裡的 6 段在送進後續審核時，每一段都會看到其餘 5 段的裁決分歧紀錄（且若超過 2000 字還會截斷）。
* **編號寫在標籤前面會直接「拆回失敗：缺段」**：`RULE` 要求標籤只寫一次、底下再列 `[1]`、`[2]`。萬一模型偶爾寫成 `[1] 【鈔文】……\n[2] 【鈔文】……`，`do_split` 先用 `【鈔文】` 切開時，`[1]` 會掉進 `_head`，跟 `【鈔文】` 的正文分離，導致第 1 段變成空內容、直接輸出 `（拆回失敗：缺段）`。

#### 2. `mk_judge_materials.py` 在一方漏譯時會「拿乙本冒充甲本」
在 `mk_judge_materials.py` 第 224–230 行的 `_pick(m, lab)`：
```python
return next((v for k, v in m.items() if k != '記文'), non_ji_old)
```
如果待審單元包含【疏文】＋【記文】，而盲翻（譯本甲）因為漏看或格式異常**完全漏譯了疏文**（只輸出 `【記文】`），`m` 裡面找不到非記文的欄位，`_pick` 就會退回 `non_ji_old`——也就是**靜默把舊現譯（譯本乙）的疏文塞進「譯本甲」的位置**。裁決看到甲乙完全一樣，就會判定無誤放過這段漏譯。

#### 3. `col3()` 正則的 `(?:3|三)?` 可選號把第 2 欄攔腰截斷
`mk_audit_materials.py`、`mk_revise_materials.py` 與 `build_a2.py` 三處的 `col3()` 都寫了這段正則：
```python
r'(?:^|\n)\s*[#*\s]*(?:第\s*)?(?:3|三)?\s*(?:欄\s*[｜|：:]|[.、．：:]|\*\*)*\s*(?:修正後|修訂後|定稿|最終)(?:的)?譯文[：:\s]*\n?'
```
因為 `(?:3|三)?` 加了問號變成**可選**，又因為使用的是從頭搜尋的 `re.search`（而非 `rfind`），只要模型在第 1 欄（逐句核對）或第 2 欄（分歧與裁決）裡，剛好有一行以「`修正後譯文應為……`」或「`……\n修正後的譯文如下`」開頭，程式就會把那裡誤認為第 3 欄起點，連同後面剩下的報告一起送進定稿。

#### 4. `materials_io.py` 的 `verdict()` 遇到 Markdown 粗體會把 `PASS` 誤判為 `FIX`
在 `verdict()`（第 84–90 行），若結論寫 `PASS` 仍會檢查 `【必改硬傷】` 是否有實質內容：
```python
h = re.search(r'【必改硬傷】\s*(.{0,80})', rt, re.S)
# 先剝開頭括號註記，再 strip('*：:- ')
```
問題在於模型常順著 `AUDIT_PROMPT` 標題格式輸出：**`3. **【必改硬傷】**（無則寫「無」）：無`**。
1. `h.group(1)` 會抓到 **`**（無則寫「無」）：無`**（開頭是 `**`，不是 `（`）。
2. `re.sub(r'^[（(【]...', '', seg)` 因為開頭是 `**` 而**沒剝掉括號**。
3. 接著 `seg.strip('*：:- ')` 才剝掉 `**`，剩下 **`（無則寫「無」）：無`**——它不是以 `無` 開頭，於是被直接升級判成 **`FIX`**！
（另外若模型寫 `經核無硬傷` 或 `皆無`，同樣不以 `無` 開頭，也會誤判成 `FIX`。）

#### 5. `qwen_local.py` 的 `_split_col3` 與 `_strip_head_paren` 的兩個切字風險
* **第 3 欄若寫在同一行會漏切**：`qwen_local.py` 第 339 行 `_split_col3` 是找 `修正後的譯文` 後的第一個 `\n`。如果模型寫成 `3. **修正後的譯文**：【鈔文】……`（沒換行），`col3` 會跳到**第二段**才開始算，第一段的重複標籤剝除與「重貼原文檢查 `_looks_pasted`」都會漏掉它。
* **誤刪譯文開頭的合法括號**：`qwen_local.py`、審核、修訂、定稿都有 `_strip_head_paren()`，目的是去掉模型多寫的 `（純白話譯文）` 之類的提示。但如果模型偶爾忘了寫 `【鈔文】` 標籤，而該段譯文的第一句剛好是合法的圓括號開頭（例如 `(承前文)……` 或 `(音某)……`），`_strip_head_paren` 會不問內容直接把第一組圓括號整塊刪掉。

### 二、本地檢索與正規化的暗坑

#### 6. `local_corpus.py` 兩個影響「查得到但漏掉」的設計限制
* **`_split_work` 暗中鎖死書名，讓跨書兜底失效**：`local_corpus.py` 的 `_split_work(query)` 只要看到查詢字串開頭是書名（例如模型照指示不填 `work`，但 query 寫了 `"四分律 僧殘"`），就會在內部把 `work` 鎖死成 `四分律`。但外層 `qwen_local.py` 的 `local_search` 看到的參數 `work` 依然是 `None`，因此就算 `四分律` 裡沒命中（該引文其實是《業疏》轉述），**`if not hits and work:` 不會觸發，不會改搜全庫**。
* **行視窗不均＋分層截斷**：`原文/` 來自 CBETA 折行本（每行僅約 20～40 字），`find()` 預設前後各 2 行（共 5 行）只有約 100～150 字；但 `TXT/` 南山著作是整段一行，5 行可達上千字。在 CBETA 典籍裡只要兩個實詞距離超過 150 字就會漏搜。此外 `rows=3` 時，只要 **Layer 0（辭典＋科記）** 的 `南山律學辭典`（載入順序第一）命中 1 筆，再加 Layer 1（南山正文）1 筆、Layer 2（律藏）1 筆，**3 筆名額立刻滿了**，同在 Layer 0 的《濟緣記》《行宗記》《業疏科》會被擠到第 4 筆而根本沒回傳。

#### 7. `norm.py` 與 `qc_scan.py` 的專名／書名誤殺
* **自家 5 部「科文」書名會被改成篇名號**：`norm.py` 第 53 行：
  ```python
  s = re.sub(r'《([^《》〈〉]{1,12}(?:篇|品|章|節|門|科|犍度))》', r'〈\1〉', s)
  ```
  只要譯文出現 **`《業疏科》`、`《戒疏科》`、`《行事鈔科》`、`《義鈔科》`、`《尼鈔科》`**（因為結尾是「科」字），會被全部改成篇名號 `〈業疏科〉`。
* **`KNOWN_BOOKS` 漏了 12 部書**：`norm.py` 裡的 `KNOWN_BOOKS` 只有 21 部（缺少《律二十二明了論》《薩婆多毘尼毘婆沙》《四分比丘尼戒本》《大比丘三千威儀》等），這 12 部若模型誤寫成 `〈〉`，不會被轉正回 `《》`。
* **異體字表可能誤傷律宗術語**：`norm.py` 的 `VAR_MAP` 把引號外的 `麤 → 粗`、`覩 → 睹`。律宗裡「麤重」「麤罪（偷蘭遮）」「覩史陀天」通常保留「麤／覩」字；直接轉成「粗罪」「睹史陀」反而顯得不專業（而若譯文是白話「粗糙」，現代 LLM 本就會寫「粗」）。
* **`qc_scan.py` 誤報引號內的 `鉢`**：`norm.py` 特意保留 `「……」` 原文引句裡的異體字不轉（所以 `「持鉢」` 保留 `鉢`），但 `qc_scan.py` 的 `BAD_VAR = {'鉢': '缽'}` 掃的是全文，會把合理保留的引文誤報為異體字異常。

### 三、提示詞與腳本細節的錯位

#### 8. 未配對的單邊 `【記文】` 與無 JSON 回退時的 `book_of()` 差異
* **單邊記文缺上下文註記**：在 `mk_review_materials.py` 的 `prompt_for()` 裡，只有 `unit in ('疏文', '律文', '註文', '序文')` 才會塞入 `ctx`（《業疏》「文／注」指《隨機羯磨》等）；遇到業疏／戒疏的**單邊未配對【記文】**時，`ctx` 被清空了。相對地 `mk_blind_materials.py` 卻有保留這段給單邊【記文】。
* **`資持記` 多出一個空分號**：`mk_blind_materials.py` 第 100–103 行先因為 `資持記` 不是業疏/戒疏把 `_ctx` 清空，又做了 `cfg.get('note', '') + '；' + _ctx`，結果在提示詞句子尾巴多出一個懸空的 `；`。
* **`book_of()` 預設值與判斷條件打架**：若沒有 `.json` 而回退用路徑判斷，`book_of()` 會回傳 `'疏記'`（而非 `'業疏'` 或 `'戒疏'`），導致 `mk_audit_materials` 的 `if book in ('業疏', '戒疏')` 條件（啟用疏記雙向互核）與 `mk_blind_materials` 的 `book not in ('業疏', '戒疏')` 條件判斷失靈。

#### 9. 兩處小腳本細節導致冗餘或格式污染
* **出處重複書名**：`mk_audit_materials.py` 和 `mk_revise_materials.py` 從上層材料抓出的 `ex.group(1)` 本身已經包含 `《業疏》` 了，組字時又包了一層 `（出處：《%s》%s）`，導致材料檔頭會印出 **`（出處：《業疏》《業疏》01a_……）`**。
* **修訂材料重複貼譯文且可能截斷**：`mk_revise_materials.py` 在裁決判 `PASS_A_KEEP_A` 時，【目前譯文】已經填入譯本甲，但第 188 行又再貼一次 `【譯本甲（僅供參考）】`，等於同一段譯文送兩遍（且提取 `_a_` / `_b_` 時用 `(?=\n+■ |\n+【|\Z)`，萬一譯本甲／乙裡面換行後出現任何 `【`，就會被半途截斷）。

#### 10. `web_fetch` 容錯與工具規則的微小不一致
* `qwen_local.py` 的 `local_search` 與 `web_search` 都加了 `**kwargs` 吸收模型幻覺出的多餘參數，唯獨 `web_fetch(url, keyword=None, stats=None)` 沒加 `**kwargs`，模型只要多傳一個參數（例如 `query=` 或 `limit=`）就會噴 `TypeError` 白白浪費一輪對話與整個 context 的輸入費用。
* `SYSTEM_PROMPT` 寫「`檢索次數以每次回傳的 remaining 為準……；web_search 1～2 次、web_fetch 1 次`」，但程式裡只有 `local_search` 回傳 `remaining`（`web_search` / `web_fetch` 沒有回傳 `remaining`）。

#### 11. 長段管線（`long` stage）尚未完全接通
在 `run_pipeline.py` 的 `long` 分支裡：
* `merge_long.py` 把小段拼回母段後放在 `_長段/_定稿/*.txt`（沒有 `回覆/*_回.txt` 結構）。
* 但 `run_pipeline.py` 第 141 行卻將 `--r1` 指向 `_長段/_終審`（審核報告沒有「修正後的譯文」），會讓 `mk_revise_materials.py` 全部略過；而 `mk_audit_materials.py` 用 `'_長段' in src` 判斷是否掛上 `_long` 提示詞（容忍缺主詞與無句號）——若 `run_long_audit.py` 審的是已經拼回的母段，掛上這個規則反而會讓模型放過原本切段拼回時殘留的斷裂或句號問題。
