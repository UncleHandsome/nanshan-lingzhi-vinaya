### 1. `mk_supplement.py` 與 `make_hybrid.py` 的 `PROV` 正則會被新版 `《書名》` 整個搞失效
`mk_review_materials.py` 現在寫出的出處格式是：
`（出處：《業疏》01a_卷一之一，第 21–22 段）`（前面多了 `《書名》`）。
但 `mk_supplement.py` 與 `make_hybrid.py` 裡抓檔名的正則都寫：
```python
PROV = re.compile(r'（出處：([^，]+)，第 (\d+)(?:–(\d+))? 段')
```
抓出來的 `ch` 會變成 **`《業疏》01a_卷一之一`**，而 `g['chunk']` 是 **`01a_卷一之一`**：
- **`mk_supplement.py`**：因為 `(ch, a, b)` 永遠對不上 `g['chunk']`，會誤以為整部書「完全沒翻過」，把全部組別重新輸出成 `_材料_補`。
- **`make_hybrid.py`**：若拿新版 `mk_review_materials.py` 產出的 `_材料` 去跑混合切法，`M.load_pair(spec, '《業疏》01a_卷一之一')` 會找不到檔案、回傳空陣列，進而觸發 `if not o['idx']: continue`，**把所有既有舊組與回覆全部丟棄**。

### 2. `pack_audit.py` 會直接丟掉「原本就已打包（`packed=True`）」的組別
在 `pack_audit.py` 第 45 行：
```python
for fn in sorted(os.listdir(jd)):
    ...
    md = MI.load(jd, key) or {}
    if md.get('packed'):
        continue
```
`pack_audit.py` 原意是不把「已經打包過的」跟別組再二次打包，但寫成 `continue` 之後變成**整組被跳過、完全不輸出進 `_打包審核` 也不寫進 `索引_pack.json`**！如果拿它跑有開啟短段打包的批次（例如新版《尼鈔》476 組裡面有 119 組本身是 `packed=True`），這 119 組會直接從審核與定稿裡蒸發（應該要改為單獨一包 `packs.append([it])` 放行，而不是 `continue`）。

### 3. `mk_split_blind.py` 遇未閉合引號時，會「不看標點」直接從字詞中間劈開
在 `split_sentences(text, max_len)` 中：
- 只要原文有一個漏標的 `」` 或跨段引文（`_depth > 0`），句尾切分條件 `ch in SENT_END and _depth == 0` 就會全程失效，累積成超過 `720` 字（`max_len * 1.8`）的巨塊。
- 接著程式進入：
  ```python
  while len(p) > max_len * 1.8:
      out.append(p[:max_len])
      p = p[max_len:]
  ```
  這個迴圈**直接用固定索引 `[:400]` 硬切**，完全沒有像下方 `if len(out) < 2` 那樣先找 `，、；` 斷點，極容易把一個佛學專名從中間腰斬成兩半送去盲翻。

### 4. `mk_review_materials.py` 的兩個規則漏網
1. **一審（`BASE_PROMPT`）跑《尼鈔》《行事鈔》《義鈔》時，完全沒拿到部別 `note`**：
   `prompt_for(unit, book)` 只在 `unit in ('疏文', '記文', '律文', '註文', '序文')` 才塞 `ctx`，只在 `unit == '記文'` 才塞 `note`。當 `unit == '鈔文'` 時，兩個判斷都進不去，導致《尼鈔》一審完全沒有提示比丘尼律制。
2. **`業疏`/`戒疏` 短配對被拆散＋順序重排**：
   `min_shu=40, min_ji=40` 會讓只要其中一邊 `<40` 字的【疏】【記】配對被 `paired` 迴圈略過，改由 `unpaired` 迴圈拆成兩組單欄（失去【疏】【記】雙向互核）。另外，先收全部 `paired` 再收全部 `unpaired`，會讓 `索引.json` 與 `--limit`／`--groups` 的順序跟原本經文順序打亂。

### 5. `mk_audit_materials.py` 三個死碼與誤判
1. **書名文本救援邏輯永遠不會觸發**：
   ```python
   book = md0.get('book') or book_of(os.path.join(src, fn))
   if book in ('', '疏記'):
       _bm = re.search(r'（出處：《([^》]+)》', t)
   ```
   因為 `book_config.book_of()` 找不到關鍵字時預設直接回傳 `'業疏'`（永遠不會回傳 `''` 或 `'疏記'`），下面那段從內文撈 `《...》` 的邏輯其實永遠不會執行（`mk_blind`／`mk_revise` 也有同樣問題，若路徑沒帶書名又沒 `.json`，會默默全部當成《業疏》）。
2. **`_brief` 把冒號後的 `乙優` 誤標為 `重修`**：
   裁決摘要濃縮邏輯用 `'甲優' in _head else ('乙' if '乙優' in _head else '重修')`，只檢查冒號**前面**（`_head`）。若裁決模型寫成 `｜裁決：乙優，因……`（把 `乙優` 寫在冒號後面），傳給終審員的提示就會變成錯誤的 `採重修`。
3. **`_long` 判斷形同死碼**：
   程式檢查 `'（本段前文）' in t or '（本段後文）' in t` 才附加長段語氣連貫提示，但 `run_long_audit.py` 審的是已經 `merge_long` 拼完的整段，內容早已沒有那兩個標記，所以該提示在長段終審並不會觸發。

### 6. `mk_judge_materials.py` 單邊記文被誤標標籤時會整段丟失盲翻
在 `_pick(m, lab)` 中：
- 非記文欄（如 `律文`）若模型錯寫成 `【疏文】`，`_pick` 還懂得 fallback 去抓 `k != '記文'` 的那塊。
- 但若是《業疏》《戒疏》未配對的單邊 `【記文】` 組，模型萬一錯輸出成 `【疏文】`，`if lab == '記文': return m.get('記文', '')` 會**直接回傳空字串 `''`**，把整段盲翻譯文直接清空送去裁決。

### 8. `qwen_local.py` 的三個小漏洞
1. **`_VAR_MAP` 比 `local_corpus.py` 少了 17 個佛典常見異體字**：
   `qwen_local.py` 只有 10 個字（`煑竪虗汙竝説爲於着衆`），少了 `local_corpus.py` 有的 `鉢、裏、却、麤、纔、呪、眞、敎、菓、羣、牀、徧` 等字。這會讓 `web_search` / `web_fetch` 的 `_extract_window()` 在查 CBETA 原文時，因為「網頁用 `鉢/裏/却`、查詢用 `缽/裡/卻`」而錯失最佳命中視窗。
2. **存了 `src_hash` 卻沒用它做過期檢查**：
   `_usage.json` 裡明明計算並存了 `src_hash`，但 `run(f)` 判斷材料有沒有重產仍只看 `os.path.getmtime(src) > os.path.getmtime(dst) + 1`。因為整個工作目錄放在 **`OneDrive\桌面\...`** 下，跨機同步或 OneDrive 重整時間戳記時很容易誤判成 stale 重跑（或同秒覆寫沒察覺）。
3. **8 輪撞滿時在 `tool` 訊息後接 `user` 訊息**：
   第 473 行在 8 輪工具後直接把 `{'role': 'user', 'content': '已達工具檢索輪數上限...'}` 接在 `role: 'tool'` 之後並設 `tool_choice='none'`；另外如果中間某輪模型因 `reasoning_content` 太長直接撞 `finish_reason='length'`，此時 `tool_calls` 為空但 `content` 也可能是空的。

### 9. `norm.py` 的書名號轉換邏輯漏洞與 Markdown 漏清
1. **`〈業疏〉科`／`〈四分律〉節` 永遠轉不回 `《》`**：
   `_book_title` 寫 `if follow or body not in KNOWN_BOOKS: return '〈' + body + '〉' + follow`。只要書名後面緊接 `門/節/科/序`（例如 `〈四分律〉序`），即使它在 `KNOWN_BOOKS` 裡也拒轉為 `《四分律》`；同時 `KNOWN_BOOKS` 也漏了庫內已有的《行事鈔科》《業疏科》《戒疏科》《含注戒本》《南山律學辭典》。
2. **反引號與 Markdown 網址殘渣**：
   `_strip_md` 清了 `**` 和 `#` 標題，但沒清反引號 `` ` ``（模型常寫成 `` `〔補字〕` `` 或 `` `無犯` ``）與列表符 `- `；此外若模型輸出 `[出處](https://...)`，`URL_RE` 只刪網址後會留下孤零零的 `[出處]()`。

### 10. `materials_io.py` 的 `PRE_RE` 會吞掉 `pack_audit.py` 的分段要求
`pack_audit.py` 在多段打包時，把 `【分段要求】...` 放在 `【前文背景】` 和 `【原文】` **之間**；而 `materials_io.PRE_RE` 一路匹配到 `(?:【本次待審單元】|【本次待譯單元】|【原文】)`，一旦觸發 `.md` 回退解析（例如後續階段沒寫 `.json`），`pre` 會把整段 `【分段要求】` 吃進去。
