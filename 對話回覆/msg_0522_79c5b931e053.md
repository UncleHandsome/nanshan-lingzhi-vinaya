### 1. `local_corpus.py` 最根本的檢索偏差：「±2 行」在 33 部書裡長度差了 20 倍！
看你第 4.1 節的行數統計就會發現，33 部書的斷行格式並不統一：
- **CBETA 固定寬度斷行本**（每行 ~25–40 字）：如《瑜伽師地論》（65,936 行）、《十誦律》（40,109 行）、《行宗記》（28,189 行）、《濟緣記》（18,728 行）。
- **一段一行本**（每行可達 300–1,500 字）：如《四分律》（僅 5,373 行）、《行事鈔》（1,591 行）、《義鈔》（258 行）、《隨機羯磨》（271 行）。

`find()` 的多詞共現視窗與回傳上下文件都寫死 **`idx - 2` 到 `idx + 3`（共 5 行）**：
- 在《行宗記》《濟緣記》《十誦律》裡，5 行只有 **120～180 字**。只要兩個實詞隔了兩三句（例如 200 字外），`all(t in win for t in others)` 就會**全部漏搜**！
- 反過來在《四分律》《行事鈔》裡，5 行可能高達 **2,000～3,000 字**，兩個毫無關係、隔了四個自然段的詞也會被判定成「共現命中」。
- 另外，`_add_file()` 載入 `TXT/資持記/*.txt` 時每個檔案開頭都重設 `juan = '卷首'`，若子檔檔頭沒重複寫「卷第幾」，該卷的 `juan` 標籤就會錯標為 `卷首`。

---

### 2. `local_corpus.py` 的 `_split_work` 遇到未收錄的「複合書名」會鎖死成必敗查詢
在 `qwen_local.py` 裡，只有當模型有填 `work` 且查無時，才會放寬為全庫重查（`relaxed=True`）。
但如果模型**沒填 `work`**、直接在 `query` 開頭寫書名（例如 `"行事鈔資持記 戒體"` 或 `"戒疏行宗記 隨行"`）：
- `_split_work()` 只比對 `BOOKS | EXTRA.keys()`，因為沒有 `'行事鈔資持記'`，它會優先匹配長前綴 **`'行事鈔'`**，把查詢強行拆成 `work='行事鈔'`, `core='資持記 戒體'`！
- 接著去《行事鈔》裡找根本不可能出現的 `'資持記'` 三個字，結果必為 `0 筆`；而 `local_search` 外層看到的 `work` 是 `None`，所以 **`if not hits and work:` 放寬全庫的救援機制完全不會啟動**。

### 3. `qwen_local.py` 的「空回覆／內容過濾」與「標點雙詞被拆光」問題
1. **`finish_reason == 'content_filter'` 或空內容會直接當成 `ok` 存檔**：
   `_save_result()` 只檢查 `finish_reason == 'length'`。若 API 回傳 HTTP 200 但因安全審查觸發 `content_filter`（或意外吐出空白／僅幾字的 `content`），程式照樣回傳 `'ok'` 並寫出空白的 `_回.txt`（該次執行就會計為成功，直到下游 `build_a2` 或下一次續跑檢查 `getsize > 10` 才發現）。建議在 `_save_result` 直接檢查 `not out.strip()` 或 `finish_reason not in (None, 'stop')`。
2. **帶標點的單字雙詞查詢會「靜默少詞」或「變成連字詞」**：
   `local_search` 的 `_toks` 檢查是算含標點的字串長度。若模型傳 `query="「戒」 「律」"`（每個 token 長度 3，通過檢查），進到 `_LC.find` 後 `_plain` 把 `「」` 剝掉變成 `['戒', '律']`，兩個都 `< 2` 被濾光變成空列表，最後 fallback 成 `terms = ['戒律']`——原本要搜「同時出現戒與律」變成了搜連字詞「戒律」。同理 `"一、 僧殘"` 會把 `'一、'` 剝掉變成只搜 `'僧殘'`。
3. **DeepSeek 空結果也快取 30 天**：
   `_cached_or_fetch` 只要收到 `dict` 就寫進 SQLite 快取 30 天。若某次 DeepSeek 搜到 `{'results': []}`（包含網域全被白名單濾掉或短暫索引空回），未來 30 天同關鍵詞重跑都會直接沿用空結果。

### 4. `qwen_local.py` 的停止訊號無法中斷重試退避（`Ctrl+C` 卡 90 秒）
在 `qwen_post` 與 `_ds_post` 的 `for attempt in range(6):` 重試迴圈裡，`time.sleep(wait_sec)` 最長可睡 90 秒，而且沒檢查全域 `stop.is_set()` 或 `STOP` 檔。當你執行 `stop_all.py` 或按 `Ctrl+C` 停止批次時，若有執行緒正在經歷 429/5xx 重試或卡在 `timeout=2400` 的連線裡，它還是會睡完並把剩餘 5 次 API 重試打完才退出。

### 5. `pack_judge.py` 的三個狀態殘留與標籤漏洞
1. **重跑 `packjudge` 不會清除舊的殘留檔案**：
   你幾乎所有的 `mk_*_materials.py` 和 `pack_audit.py` 都會在開頭先刪除 `out` 裡的舊 `.md`/`.json`，但 **`pack_judge.py` 的 `do_pack` 和 `do_split` 都沒有清舊檔**！只要你調整過批次內容重新打包，舊的 `pXXXX.md` 和 `_拆回/回覆/*` 會直接殘留，並被 `run_pipeline.py` 一併複製進 `_裁決` 污染新批次。
2. **模型用單字標籤 `【疏】`／`【鈔】` 時 `do_split` 直接失敗**：
   `mk_judge_materials.split_units` 會把 `【疏】` 轉成 `【疏文】`，但 `pack_judge.py` 的 `LABS = '疏文|記文|鈔文|律文|註文|序文'` 沒先做這步轉換。一旦打包裁決的模型偷懶寫成 `【鈔】`，`secs` 切不出來就會直接整段寫成 `（拆回失敗：缺標籤）`。
3. **拆回異常不會擋住 `run_pipeline.py`**：
   當某包在 `do_split` 發生例外寫出 `pXXXX_拆回異常.txt` 時，該包裡原本那 6 組的 `回覆/*_回.txt` 不會產生，但 `pack_judge.py` 回傳碼仍是 `0`。接著 `run_pipeline.py` 會繼續把整套 `audit`、`revise`、`final` 全跑完，直到最後看 `_未審核清單.log` 才會發現漏了一批。

### 6. `run_pipeline.py` 的靜默搶用舊混合目錄陷阱
看 `run_pipeline.py` 的路徑判斷：
```python
def _mat(root):
    hy = root + '/_材料_hy'
    return hy if os.path.isdir(batch_dir(hy)) else root + '/_材料'
def _blind(root):
    hy = root + '/_hy_盲翻'
    return hy if os.path.isdir(batch_dir(hy + '/回覆')) else root + '/_盲翻'
```
如果你之前跑過一次混合切法留下了 `_材料_hy` 或 `_hy_盲翻`，後來重產了全新的 `_材料`／`_盲翻` 卻忘了手動刪掉 `_hy` 目錄，**`run_pipeline.py` 會完全無視你剛更新的 `_材料` 與 `_盲翻`**，默默拿舊的 `_hy` 去跑裁決與定稿。

### 7. `qc_scan.py` 的兩個偵測盲點
1. **單欄組重複標籤反而漏抓**：`qc_scan.py` 檢查 `out.count('【') > 2` 才報「殘留欄位標籤」。對只有一欄的《尼鈔》《行事鈔》《資持記》而言，就算錯誤地印了兩次 `【鈔文】`（`count == 2`），掃描依然會放行成 `✅`。
2. **多種配對符號未檢查**：只查了 `「」` 數量是否相等，沒檢查最容易被模型或切割器弄破的 `『』`、`（）`、`〔〕`、`《》` 是否成對閉合。
