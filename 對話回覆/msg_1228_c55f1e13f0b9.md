翻譯在 `_終審` 裡是 1:1 的，問題出在**頁面重建時把背景文字當成原文**。

以 `613.md` 為例：

```text
【原文】
第五通塞者……

【待審譯文】
【鈔文】第五、通塞：手受……

【後文背景】
第六重受者……
○訃請篇第二十五
第一簡請此律請有二種……
```

這單元本來是：

```text
原文：第五通塞
白話：第五通塞
```

1:1 正確。

但 `第一簡請` 是在 **【後文背景】**，不是 `【原文】`，也沒有自己的譯文。

頁面重建時卻把：

```text
第一簡請……（背景）
```

拿去配：

```text
第五通塞……（這單元的譯文）
```

所以變成：

```text
原文：下一段的簡請
白話：上一段的通塞
```

出問題的環節是：

1. `_終審`：正確，一對一
2. 頁面重建：把背景／下一段文字也抓成 source
3. 配對時：直接拿該單元唯一的 `【待審譯文】` 來配
4. 沒有檢查「這個 source 是否真的在 `【原文】` 裡」

所以不是翻譯不 1:1，是**頁面 builder 把背景文字拉進來，卻沒有對應譯文**。

正確做法：

- 只從 `【原文】` 取 source
- 只從 `【待審譯文】` 取 translation
- 背景文字只能當上下文，不能變成 pair
- 若背景要成正文，必須先有自己的 `【原文】`／譯文

這正是尼鈔錯配的根因。
