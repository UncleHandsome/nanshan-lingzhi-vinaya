### 一、工具呼叫與檢索層的隱藏問題

1. **`qwen_local.py` 達輪數上限時，送出的請求少了 `tools` 欄位**（第 584–596 行）
   ```python
   payload['tools'] = TOOLS
   payload['tool_choice'] = 'none'
   r = qwen_post({
       'model': MODEL,
       'messages': messages,
       ... # 沒帶入 payload，tools 與 tool_choice 被漏掉了
   })
   ```
   改了 `payload` 卻在 `qwen_post({...})` 重建新字典。前面幾輪對話的 `messages` 裡已經有 `tool_calls` 與 `tool` 回傳訊息，拿掉 `tools` 參數在許多 OpenAI 相容閘道會直接回傳 HTTP 400。

2. **`local_search` 單字查詢先扣額度才報錯、且自搜過濾過度敏感**
   - **先扣款後驗票**：第 127 行先呼叫 `_local_budget(stats)` 扣掉 1 次額度，第 132 行才檢查 `all(len(x) < 2)` 並回傳錯誤，沒有把額度退還。
   - **短段自搜誤殺**：`_own` 把整段待審原文拿去滑窗切 `_wins`。若待審單元是短句／科題（例如只有 4～8 字的 `釋名門`），`_wins` 就只剩這幾個字，結果把《業疏》《戒疏》《行事鈔》裡所有含該詞的正常互文全過濾掉了（建議限制 `len(w) >= 12` 才過濾）。
   - **字表不一致**：`qwen_local.py` 的 `_VAR_MAP` 只有 10 字，而 `local_corpus.py` 有 27 字（缺了 `鉢／羣／裏／呪／眞` 等），會讓自搜過濾漏網。

3. **`local_corpus.py` 跨行搜尋會把命中的「前一行」當成本行**（第 210–216 行）
   - 為了支援跨行詞組，程式檢查 `anchor in (r['plain'] + _nxt['plain'])`，但沒有排除 `anchor in _nxt['plain']`。
   - **後果**：當某詞其實完整出現在第 `idx + 1` 行時，第 `idx` 行（前一行）也會通過檢查，導致回傳的 `linehead` 與 `juan`（卷次）指向前一行，且 `idx + 1` 行會被 `idx - _last <= 2` 跳過。

### 二、審核判定、拆回與正則盲區

4. **`materials_io.verdict()` 遇到「肯定語氣寫沒錯」會誤判為 `FIX`**（第 70–77 行）
   - 當【結論】寫 `PASS`，但【必改硬傷】欄位若模型寫成「`本段未發現必改硬傷`」「`未見實質錯誤`」「`均無硬傷`」，因為開頭不是清單列的 `'無', '暫無', '沒有', '皆無'...`，會被強制翻盤成 `FIX`，白跑一趟修訂並增加改壞風險。
   - 另外第 68 行的 lookahead `\n\s*\d+[.、．]` 會在硬傷以 `1. ...` 條列時於起始處截斷（雖然若結論寫對 `FIX` 在前一行已先返回，但遇到模型寫 `PASS`＋條列硬傷的矛盾回覆時，反而會因為切到空字串而放過）。

5. **Markdown 標題有空白時，`col3()` 主正則會失手**（`mk_audit`／`mk_revise`／`build_a2`）
   - 正則 `(?:欄\s*[｜|：:]|[.、．：:]|\*\*)*\s*` 的 `\s*` 放在星號群組外面。遇到常見的 `### 3. **修正後的譯文**`（`.` 和 `**` 中間有空格），主正則會匹配失敗並退回 `rfind('修正後的譯文')`——萬一模型標題寫的是 `修訂後的譯文`，`rfind` 就會找不到（或誤抓第 2 欄文字）。

6. **`qc_scan.py` 品管掃描的三個盲區**
   - **簡體字只檢查 4 個字**（`'达','没','时','精准'`），但 `norm.py` 轉了 16 個簡體字（`众问这为应经说义体归无...`），若殘留在引號內或漏網會抓不到。
   - **按語檢查被 `補` 豁免**：`〔(?![補疑])...` 只要開頭是 `補`（如 `〔補：據他本補此二字〕`），就算裡面含 `據／按／考／校` 也不會報警。
   - **重複標籤判斷失真**：`out.count('【') > 2` 對單欄書（`鈔文` 重複出現兩次 `【鈔文】`，總數為 2）會放行；反之若《業疏》原文內恰有 `【某】` 方括號，總數為 3 又會誤報。應改成檢查「同一欄位標籤在行首出現次數 > 1」。

7. **`mk_judge_materials.py` 全域替換標籤有誤切正文風險**（第 101–103 行）
   - `split_units()` 用 `body.replace('【疏】', '【疏文】')` 全文替換後再 `re.split`。若譯文內文恰好引錄了 `【疏】` 等字樣，會直接被劈成兩欄。建議改用行首錨定 `re.sub(r'(?m)^\s*【([疏記鈔律註序])】', ...)`。
   - 同檔第 244 行 `_pick()` 在找不到對應非記文標籤時會拿第一個非記文值頂替，若一個單元同時含 `律文` 與 `註文`（目前僅單邊短段會出現），缺譯一方會誤抄另一方的譯文。
