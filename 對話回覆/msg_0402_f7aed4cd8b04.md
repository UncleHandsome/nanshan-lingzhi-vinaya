## 一、提示詞修正（只改通則與結構，不寫任何個案字眼）

### 1. `AUDIT_PROMPT`（2.5 節）：改「先簡核、後定論」＋兩條精準通則

這版對照真正暴露的不是某幾個詞，而是三個結構性問題：
1. **精簡版**把 `PASS` 壓到只有一行，模型會偷懶跳過逐句比對；
2. **回退版**雖然會寫覆核要點，但因為**先輸出 `【結論】：PASS`、後寫要點**，容易為了替自己剛寫出的 `PASS` 圓場而事後合理化（或腦補譯文中不存在的詞）；
3. 現有條文對「詞面歧義」與「文言未譯降列微瑕」的界線不夠明確。

**具體改法（只改這 4 點，不舉個案）：**

- **輸出順序倒過來，把「核驗」放在「結論」之前**：
  ```text
  1. 【逐句簡核】（限精要條列，不作長篇鋪陳）：逐句直接引對【待審譯文】實際字面與主客關係、界限條件及查證結論；不得沿用【裁決分歧參考】之判斷而不覆核原典。
  2. 【結論】：`PASS` 或 `FIX`（嚴格依第 1 欄核對結果判定）
  3. 【必改硬傷】（無則寫「無」）
  4. 【可斟酌微瑕】（無則寫「無」）
  ```
  > 這樣既保有回退版的查證深度，又消除「先押 PASS 再合理化」的偏誤，同時 `【逐句簡核】` 不會混進下游要讀取的 `【必改硬傷】` 區段。

- **在檢核底線第 2 條補入「字面界限歧義」通則**：
  > 「譯文表層語義若因漢語常用結構（如含本數之範圍詞、否定作用域偏移等）與原文排他／限定界限相抵牾，即使譯者本意無誤，仍屬實質歧義，須判 FIX。」

- **在檢核底線第 5 條／微瑕邊界補入「文言殘留」紅線**：
  > 「非固定專名之文言實詞或短語逕留未譯（致今語生澀或同詞前後譯法不一），屬文言直抄硬傷，一律判 FIX，不得列為微瑕。」

- **防腦補一句**：
  > 「須直接引對【待審譯文】實際字面核驗，不得依文脈腦補譯文中並無的詞語。」

## 二、程式碼修正（按嚴重度排序）

### P0：跑全量前必修（否則直接造成資料遺失、跨卷錯位或流程失效）

1. **`_src/mk_judge_materials.py`（6.8）的 `split_units()` 吞段 Bug**
   - **問題**：第 104 行開頭多了一行 `re.sub(r'^\s*【(?:疏文|記文|鈔文|律文|註文|序文)】\s*', '', ...)`。
     - 成對組（疏＋記）：剝掉開頭 `【疏文】` 後只切出 `【記文】`，導致盲翻的【疏文】整段消失，`_pick` 退回抓舊白話去跟舊白話對決。
     - 單邊 `【記文】`／《資持記》：剝掉 `【記文】` 後整段被歸進 `out['疏文']`，導致 `_pick(m, '記文')` 全部回傳空字串 `''`。
   - **修法**：移除開頭那行 `re.sub`，直接 `re.split`；並加 `default_lab` 參數（取原文第一個 unit 的標籤），只有整段都沒標籤時才掛進 `default_lab`。

2. **`_src/pack_judge.py`（6.7）的 4 處 Bug**
   - **補寫 `chunk` 防跨卷混併**：`mk_review_materials.py`（6.4）與 `mk_judge_materials.py`（6.8）的 JSON 都沒寫 `'chunk'`，導致 `pack_judge` 裡 `md.get('chunk')` 永遠是 `''`，會跨越卷界把不同卷的末段和首段打包在一起。請在 6.4／6.8 JSON 補寫 `'chunk'`（與 `'s0'`, `'g1'`），`pack_judge` 也用 `key.rsplit('_', 1)[0]` 保底。
   - **禁止二次打包**：`pack_judge` 須跳過 `md.get('packed') == True` 的組（維持單組），否則外層 `[1][2]` 會和內層既有的 `[1][2]` 編號衝突。
   - **成對「疏＋記」打包拆回覆蓋**：目前 `JUDGE_PROMPT` 寫「同一欄標籤只在開頭寫一次」，若模型輸出 `【疏文】[1][2]\n【記文】[1][2]`，`do_split` 的 `re.split(r'\[\s*(\d+)\s*\]', body3)` 會讓【記文】把【疏文】覆蓋掉。須二選一：打包時改寫格式要求為「每組編號內自帶標籤：`[1]\n【疏文】…\n【記文】…`」，或在 `do_split` 先依欄標籤分流再拆 `[n]`。
   - **單組補複製 `.json`＋拆回對接**：`len(pack) < 2` 時同步複製 `.json`；`do_split` 後需將回覆對接回原未打包目錄的 `.md`/`.json`（或自動複製對應單組材料到輸出目錄），下游 `mk_audit_materials` 才能直接跑。

3. **配合新版 `AUDIT_PROMPT` 修改 `verdict()` 與 `fixes_block()`**
   - 因為要把 `【結論】` 放到 `【逐句簡核】` 之後，目前 `mk_revise_materials.py`（6.10）與 `build_a2.py`（6.17）**只掃 `v[:600]`** 可能會漏抓。
   - **修法**：把 `verdict()` 抽進 `materials_io.py` 共用（同時統一兩者原本不一致的判定邏輯），改成搜尋整份文本的 `【結論】`（再保留 `【必改硬傷】` 是否為「無」作保底）；`fixes_block()` 嚴格截到 `【可斟酌微瑕】` 為止。

4. **`PASS_A_KEEP_A` 標記容錯**
   - 模型偶爾會帶出反引號 `` `PASS_A_KEEP_A` `` 或句號。將 `mk_audit_materials.py`、`mk_revise_materials.py`、`build_a2.py`、`pack_judge.py` 四處的嚴格相等改為共用檢查（如 `.strip(" \t\r\n`*。.") == 'PASS_A_KEEP_A'`）。
