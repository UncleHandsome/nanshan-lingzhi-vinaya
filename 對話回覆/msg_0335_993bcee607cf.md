### 1. 【隱形殺手】`qwen_local.py` 的 `_split_col3()` 自己把「修正後的譯文」五字砍掉了！
* **位置**：`qwen_local.py` 第 485–490 行與第 530 行
* **程式碼現場**：
  ```python
  i = out.rfind('修正後的譯文')
  if i >= 0:
      body = out[i + len('修正後的譯文'):].lstrip('*：: \t\r\n')
      return out[:i], body
  ...
  out = head + col3   # ← 在 _save_result() 裡執行
  ```
* **發生什麼事**：
  * `head` 是 `'修正後的譯文'` **之前**的字（例如 `'3. **'`）；`col3` 是 `'修正後的譯文：\n'` **之後**的正文（`【疏文】...`）。
  * 兩段拼回去 `head + col3` 時，**正好把「`修正後的譯文：\n`」這幾個字從存檔的 `_回.txt` 裡整個刪光，變成 `'3. **【疏文】...'`**！
  * 下游 `mk_audit`、`mk_revise`、`build_a2` 全都靠 `'修正後的譯文'` 來定位第 3 欄——**這就是為什麼前面會頻繁找不到標題、被迫靠備援切段！**
* **修法**：保留標題與換行：
  `return out[:i + len('修正後的譯文')] + '：\n', body`

### 2. 【打包批必爆】「4.5 短段打包」的 `盲翻` 收到 `[1][2]` 指令，原文卻沒有編號！
* **位置**：`mk_review_materials.py` 第 228–244 行 ＋ `mk_blind_materials.py` 第 68–79 行
* **發生什麼事**：
  * `mk_review_materials.py` 產 `.md` 時有在原文與現譯前面加 `[1] `、`[2] `；但寫進 **`NN.json`** 的 `units[0]['orig']` 與 `units[0]['tr']` 時，卻**沒有把 `[1] `、`[2] ` 寫進去**！
  * `mk_blind_materials.py` 使用 `MI.load()`，因為 `.json` 存在，所以**優先讀取 `.json`**。結果盲翻檔上面印了 `【分段要求】……請保留 [1][2]… 編號`，底下的 `■ 鈔文（原文）` 裡面**完全沒有 `[1] [2]`**！
  * 同時 `mk_judge_materials.py` 寫 JSON 時漏傳 `packed` 和 `segments`，而裁決、審核、修訂也都沒帶上這句分段要求，很容易把分號拆併掉讓 `split_pack.py` 失敗。
* **修法**：
  1. `mk_review_materials.py` 寫進 JSON `units` 的 `'orig'` 與 `'tr'` 時，若 `_packed` 為真就一併帶上 `[1] `、`[2] `；
  2. `mk_judge` 寫 JSON 時透傳 `packed` 與 `segments`，且 `mk_judge`/`mk_audit`/`mk_revise` 讀到 `packed=True` 時同樣加上 `【分段要求】`。

### 3. 【中級 Bug】`build_a2.py` 用 `col3_soft()` 去切「修訂回覆」會誤殺沒標籤的譯文
* **位置**：`build_a2.py` 第 77–82 行
* **發生什麼事**：
  * `修訂（Revise）` 階段跑的是 `QWEN_RAW_SAVE=1`，只輸出純譯文（沒有第 1、2 欄）。
  * 但 `build_a2.py` 拿檢查裁決報告用的 `col3_soft()` 去讀 `修訂/回覆`：只要該段修訂回覆（例如單欄的《尼鈔》《資持記》）偶爾漏寫開頭的 `【鈔文】`／`【記文】` 標籤，`col3()` 找不到標題也找不到 `【】`，就會**直接把整份修好的譯文判為 `None` 丟掉**，默默退回沒修訂前的 `bp`，卻還計入 `fix += 1` 且沒寫進 `_未修訂清單.txt`！
* **修法**：讀取 `rp`（修訂回覆）時，只做「若開頭意外出現 `修正後的譯文` 才剝除」與 `len >= 8` 檢查，別套必須有 `【】` 的 `col3()`；若真為 `None` 再退回 `bp` 時，應計入 `unfixed` 而非 `fix += 1`。

### 4. 【中級 Bug】`divergence(rt)` 遇到 `## 3.` 標題會把整段譯文吞進分歧欄
* **位置**：`mk_audit_materials.py` 第 99 行與 `mk_revise_materials.py` 第 95 行
* **問題**：`divergence()` 的終止界線寫 `(?=\n\s*\**\s*(?:3|三)[.、．：:]|...)`，沒有允許 `#`。當裁決像 L6 那樣輸出 Markdown 標題 **`## 3. 修正後的譯文`**（或搭上 Bug 1 把 `修正後的譯文` 砍掉變成 **`## 3. 【疏文】`**）時，正則不會在 `## 3.` 停下，會一路把第 3 欄譯文吞進 `div` 裡。
* **修法**：改為 `(?=\n[#*\s]*(?:3|三)[.、．：:]|...)`。
