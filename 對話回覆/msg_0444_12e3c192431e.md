你在 L1–L7 做的診斷非常紮實（例如用實證砍掉「審慎立改」、剝除裁決理由避免審核盲從等），但每次發現單一案例出錯就把防呆句直接塞進規則裡，累積到現在 `AUDIT_PROMPT` 已有約 1,700 字、6 條無分層的長段落。這在工程上有兩個具體代價，也剛好能解釋你在第八章提到的「同組重跑會有 10–15% 段落此消彼長」以及 7.4 提到的「5–10% 漏檢率」。

## 一、會不會太 case by case？哪些該留、哪些不該留在審核 Prompt？

目前的現象可以分成三類來看：

### 1. 過度補丁化導致「注意力稀釋」與「關鍵字抽檢化」
* **「打補丁反制補丁」的防禦性條文太多**：例如先嚴抓度量數理，誤殺後又加括號「（不要求擅自換算現代公制，譯文照原稱者不得因此判 FIX）」；先抓無據增詞，發現模型不判 FIX 又連寫兩次「不得列入微瑕」「僅……得保留」；第 4 條末尾還塞進整段工具操作教學（先看背景、可同輪並行、勿為求安心重搜、改空格分隔、work 欄留空）。
* **模型會變成「對表機器」**：當條文列了「白前／白後、未受前／已受後、竟／未竟、出界／未出界、過中／未過」「豈容、寧可」「非不、無非」等具體清單時，推理模型（尤其在多輪檢索後）容易優先對這些詞做表面掃描，反而忽略**沒被列舉在範例裡**的句法倒錯或隱性邏輯漏洞。

### 2. 把「程式用 Regex 100% 抓得到」的雜務丟給 LLM 燒 Token
第 6 條讓 LLM 檢查的東西裡，有很大一塊根本不該靠提示詞解決：
* 引號 `「」『』`、括號 `（）` 未閉合（`qc_scan.py` 目前只檢查 `「」`，加 2 行就能全檢）
* 殘留網址、重貼原文、工具呼叫字面、簡體／異體字（`norm.py` 與 `qwen_local.py` 本就在處理）
* 欄位標籤（`【疏文】` 等）與打包段 `[1][2]…` 編號有無遺漏或錯位
* 殘留「問曰／答曰／難曰」前綴（這可以直接先用 Python 掃出提示旗標，或作為固定後處理）

把這些確定性規則移交給審核前／後的 Python 檢查，才能把 LLM 的認知頻寬留給真正的律義與文法判斷。

### 3. 真正高價值的領域知識（應該留，但要換位置／格式）
像**「伽論 ≠ 瑜伽、婆沙 ≠ 大婆沙、善生 ＝ 優婆塞戒經」**、**開遮模態強弱**、**他部異說 vs 四分正義**，這類是模型預訓練先驗（prior）極強、不講一定踩的領域坑，**值得保留**。但建議從長段落中抽出來，獨立成一個 2～3 行的**「高危易錯速查表」**（簡稱對照表），不要混在長句裡。

## 二、`AUDIT_PROMPT` 內部的自相矛盾與格式瑕疵

1. **「純修辭潤飾不得判 FIX」 vs. 「文言生澀／近距贅詞／歐化倒裝一律判 FIX」**
   * 底線標題寫「**只抓實質問題；純修辭潤飾不得判 FIX**」，第 5 條寫「兩通勿強改」，第 4 欄說微瑕是「極輕微之無副作用字面潤飾」。
   * 但第 6 條卻把「**近距贅詞**」「**歐化倒裝**」以及「文言實詞或短語逕留未譯（**致今語生澀**或同段內前後譯法不一），屬硬傷，**一律判 FIX**，不得列為微瑕」全劃為硬傷。
   * 「致今語生澀」「歐化倒裝」高度主觀，且南山律典大量保留半文言專名（如「作法」「說欲」「白四」「蘭若」），模型在「不可因修辭判 FIX」與「不可放過文言未譯」之間極易產生 10–15% 的隨機波動。

2. **「疏文保留原字以銜接記文」與「文言實詞未譯一律判 FIX」夾殺**
   * 第 1 條要求「確認【疏文】未隱沒【記文】所牒實詞」，第 3 條豁免「銜接【記文】所牒實詞所附極簡原字」（這條規則在第 3 條裡還不小心**重複寫了兩遍**）。
   * 但第 6 條寫「除固定專名及**帶引號之所牒引文**外，文言實詞或短語逕留未譯…一律判 FIX」。問題是：引號是加在**記文**裡，在**疏文**裡被記文牒到的那個實詞並不帶引號；疏文若直接留原字會撞第 6 條，若加圓括號附原字，在沒有嚴格區分下又常被審核誤殺為「解說性圓括注」。

3. **「每句限 1 行，勿整句照抄譯文」 vs. 「不得依文脈腦補譯文中並無的詞語」**
   * 要求第 1 欄限 1 行且不許照抄譯文，同時又要核對「實際字面、主客、界限、同義疊詞、前後譯法不一」。強迫極度壓縮引述，在長句時容易造成模型自己只抽前半句、反而漏檢後半句的詞面瑕疵。

4. **「長文切片勿強補主語／句號」寫在通用提示詞裡的副作用**
   * `AUDIT_PROMPT` 第 3 條寫「若屬長文切片且與（本段前文）／（本段後文）語氣連貫者，勿強補重複主語或結尾句號」。但一般材料根本沒有 `(本段前文)` 標記，模型很容易把這句泛化到普通連續段落，與第 6 條「動詞缺主賓」直接衝突。這條只應在處理長段切片時才動態注入（像 `mk_split_blind.py` 的 `LONG_TAIL` 一樣）。

5. **輸出格式模板有明顯筆誤**：
   第 3 欄模板目前寫成：
   `……｜問題：（全句或小注漏譯者，箭頭後寫「未譯」並標示所在前後句位）｜問題：……｜依據：……`
   **`｜問題：` 重複出現了兩次**，建議修掉前面那個，改成位置／標記說明即可。

6. **第 4 條「科判層級」缺查證指引**
   第 4 欄把「層級錯誤」列為必改硬傷，但 `AUDIT_PROMPT` 本身並不像 `BASE_PROMPT` 有明確說「層級或名目不確定時須搜尋《業疏科》《濟緣記》《行宗記》《資持記》確認」，審核模型常不知道該去哪部書核科判。

## 三、跨關卡提示詞之間的矛盾（各階段標準沒有完全對齊）

對比 `SYSTEM_PROMPT`、`BLIND_PROMPT`、`JUDGE_PROMPT`、`AUDIT_PROMPT`、`REVISE_PROMPT` 與 `BASE_PROMPT`，有幾個明顯的接縫打架：

1. **「所附極簡原字」與「`〔疑作X〕`」在四關之間標準不一**
   * **盲翻 `BLIND_PROMPT`**：允許「銜接記文所牒實詞須附原字」的圓括號，也允許「原典脫訛存疑時用 `〔補字〕／〔疑作X〕` 標明」。
   * **裁決 `JUDGE_PROMPT`**：寫「僅『不補則句意殘缺或方向相反』之省略指代與前提條件，以及原典明顯脫訛的 `〔補字〕`，方屬必要保留；其餘解說性增補一律刪除。」——**漏列了「銜接記文所牒原字」與「`〔疑作X〕`」**，但緊接著又寫「並須確保【疏文】譯詞能銜接【記文】所牒實詞」。
   * **審核 `AUDIT_PROMPT`**：把「所牒原字」豁免回來了，卻**還是沒豁免 `〔疑作X〕`**（反而第 4 條說疑字存疑要寫到第 4 欄微瑕、「勿擅造校註」）。結果就是：**盲翻按規寫了 `〔疑作X〕`，裁決／審核卻按規判它 FIX 刪掉**。

2. **`SYSTEM_PROMPT` 與 `AUDIT_PROMPT` 對「檢索依據」要求打架**
   * `SYSTEM_PROMPT`（當 `NO_CITE=0`）：「若有查證，於理由或依據中**簡註書名卷次即可**」
   * `AUDIT_PROMPT` 第 3 欄：「若經檢索查證，**除書名卷次外，須簡摘命中關鍵原句或釋義 1–2 句**，供無工具之修訂環節直接覆核」
   * 由於 `SYSTEM_PROMPT` 的優先權通常高於使用者提示，「簡註書名卷次即可」會誘使審核模型偷懶不摘原句，導致後面無工具（`NO_TOOLS=1`）的 `REVISE` 看不到實據而誤駁回。應在審核階段把 `SYSTEM_PROMPT` 改為「簡註書名卷次並摘錄關鍵原句 1–2 句」。

3. **單欄書（鈔文／資持記）硬吃雙欄疏記的 Prompt**
   * `BASE_PROMPT`（`get_prompt` / `prompt_for`）和 `BLIND_PROMPT`（`BC.cfg`）都會依書別切換單／雙欄規則；但 `AUDIT_PROMPT` **全書共用同一份**，導致審《行事鈔》《尼鈔》《義鈔》《資持記》時，模型還要讀「同段【疏】【記】自相矛盾」「勿把【記文】專論混入【疏文】」「確認【疏文】未隱沒【記文】所牒實詞」等無效指令（尤其《資持記》本身是單欄記文，更容易混淆）。

4. **`mk_audit_materials.py` 打包段注入了錯誤的指令**
   * 審核打包段（`md.get('packed')`）時，`mk_audit_materials.py` 在材料裡加了：
     `【分段要求】本單元含多個短段，請保留 [1][2]… 編號逐條對應，勿合併、增減條數或改動編號。`
   * 這句是從翻譯／裁決複製過來的，但審核的任務是**輸出 4 欄挑錯報告、不要重寫譯文**。放這句反而容易誘導審核在報告裡照抄或重排段落。

5. **（補充）其他跨關卡小縫隙**
   * 若流程有用到一審 `BASE_PROMPT`：它裡面仍寫著「**數理計數與度量換算須驗算無誤**」，與盲翻／審核的「保留古制原稱、勿擅自換算公制」方向相反。
   * 書名號與篇名號：`BLIND_PROMPT` 明確要求「獨立典籍用《》、篇品章門用〈〉」，但 `AUDIT_PROMPT` 沒檢查這點，而 `norm.py` 的 `_book_title` 正則只把誤用 `〈〉` 的書名轉成 `《》`，**沒有把誤用 `《…篇》` 的篇名轉回 `〈…篇〉`**。

## 四、順帶抓到 4 個藏在程式碼裡、直接傷及審核／修訂閉環的 Bug

看過第六章程式碼，有幾個實質 Bug 建議優先修掉：

1. **`materials_io.py` 的 `verdict()` 容易把 `PASS` 誤判成 `FIX`（假陽性）**
   ```python
   h = re.search(r'【必改硬傷】\s*(.{0,60})', rt, re.S)
   if h and not h.group(1).strip().lstrip('*：: -').startswith('無'):
       return 'FIX'
   ```
   `AUDIT_PROMPT` 第 3 欄標題是 `3. **【必改硬傷】**（無則寫「無」）：`。只要 Qwen 照著格式輸出 `**【必改硬傷】**：\n無` 或 `【必改硬傷】（無則寫「無」）：\n無`，`h.group(1)` 的開頭就會是 `**：\n無` 或 `（無則寫…`；`.lstrip('*：: -')` **不會去掉 `\n` 與 `（`**，導致 `.startswith('無')` 永遠是 `False`！結果就是模型明明判 `PASS`、硬傷寫「無」，程式卻誤判為 `FIX` 送去 `REVISE`，白燒錢還可能引發誤改。
   * 同時，同函式 `rt[:4000]` 備援搜尋若遇到極長段（`逐句簡核` 超過 4,000 字）會抓不到後面的結論；而 `mk_revise_materials.py` 的 `fixes_block()` 寫死 `(?=【可斟酌微瑕】|\Z)`，若模型漏寫 `【】` 括號，第 4 欄微瑕就會整塊灌進 `REVISE` 的硬傷清單裡。

2. **`qwen_local.py` 的 `local_search` 退額度打錯字＋快取順序錯位**
   在 `local_search` 濾掉 `own_text`（自己段落）之後：
   ```python
   if not hits:
       if stats is not None and _raw_n:
           stats['local'] = max(0, int(stats.get('local', 0)) - 1)
   ```
   整個檔案計數用的鍵名都是 `stats['locals']`（有 `s`），這裡少寫了 `s`，變成 `stats['local']`，導致「搜到自己段落被過濾歸零」時**完全沒有退回額度**。而且 `memo[key] = len(hits); memo[('R',) + key] = hits` 在 `own_text` 過濾**之前**就寫入快取了，若模型同段重叫同一個詞，快取會直接回傳沒濾過的自身命中結果。

3. **`mk_judge_materials.py` 在「甲乙字面完全相同（`_same(_a, _b)`）」時的空譯文地雷**
   當 `--a` 和 `--b` 都是回覆目錄且內容相同時，程式直接 `shutil.copy2` 把 `src`（`_材料`）的 `.md` 複製過去，並在回覆寫 `PASS_A_KEEP_A`。但 `_材料` 裡的標籤是 `■ 疏文（現譯）`，**不是 `■ 疏文（譯本甲）`**！下游 `mk_audit_materials.py` 和 `build_a2.py` 遇到 `PASS_A_KEEP_A` 呼叫 `MI.from_jia()` 時會找不到 `（譯本甲）`，直接回傳**空字串**。

4. **`REVISE_PROMPT` 承諾了做不到的條件**
   `REVISE_PROMPT` 寫「若原本譯本甲或乙已更精準，可採回原譯法」，但當裁決為 `PASS_A` 時，`mk_revise_materials.py` 附上的 `【裁決分歧】` 只有「兩譯本實質義理無分歧，沿用譯本甲」一句話，**修訂者根本看不到譯本乙**，也看不到工具（`NO_TOOLS=1`）。若沒有實質對照資料，修訂只能依賴審核第 3 欄摘錄的依據——這更凸顯上面「`SYSTEM_PROMPT` 與 `AUDIT_PROMPT` 對摘錄原句必須一致」的重要性。

## 五、具體精簡與重構建議

如果你想在不降低品質的前提下壓低波動與冗長，建議把 `AUDIT_PROMPT` 這樣拆：

1. **程式碼接管格式與文字清潔**：
   把「括號／引號閉合、標籤與 `[1][2]` 編號檢查、網址／工具字面／簡體異體殘留」從 `AUDIT_PROMPT` 移除，放進 `qc_scan.py` 或審核前驗證。
2. **依書別與類型動態組裝（像 `BLIND_PROMPT` 一樣）**：
   * 單欄書（《行事鈔》《尼鈔》《義鈔》《資持記》）抽掉所有「疏／記雙欄互核、勿偷搬記文」段落；
   * 只有長段切片（`mk_split_blind` 產物）才注入「勿補前文主語／勿強加句號」；
   * 打包段在 `mk_audit_materials.py` 改提示：「本單元含 `[1][2]…` 打包短段，只須於第 3 欄逐條加註 `[n]` 指出錯誤，**切勿重寫或整理全部段落**」。
3. **把 6 條底線濃縮成「4 條核心原則 ＋ 1 張 2 行高危速查表」**：
   * **高危陷阱速查**（放最前面或 `SYSTEM_PROMPT`）：`伽論／婆沙／善生／成論` 等展開對照，以及「`〔補字〕／〔疑作X〕`」統一處置標準。
   * **原則 1（律義、部別與科判）**：部別稱謂、他部破執 vs 本宗定論、科判動詞與層級（不確定須查科記）、雙欄互核（動態注入）。
   * **原則 2（文法邏輯與斷句）**：主客施受、開遮模態與界限、極性與範圍（否定／反詰／本數界限）、句尾虛字斷句與引文邊界。
   * **原則 3（忠實增刪）**：漏譯、無據增詞（只留消歧義與接記文原字括注）、勿依文脈腦補譯文未譯出之詞。
   * **原則 4（硬性語病與一致性）**：明確切開「純修辭不判 FIX（兩通勿強改）」與「**只針對明顯殘留文言未譯（非專名／非引號所牒）、同義重複疊詞、同段術語譯名不一致**判 FIX」，拿掉模糊的「今語生澀／歐化倒裝」。
4. **修掉那 3 個程式碼接縫**：修好 `verdict()` 的 `\n`／`（` 解析與 `fixes_block()` 邊界、`qwen_local.py` 的 `stats['locals']` 拼寫與快取順序，以及 `mk_judge_materials.py` 的 `_same()` 分支。
