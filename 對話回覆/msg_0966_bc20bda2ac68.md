### 1. `qwen_local.py` 的截斷重試（`_retry_high`）會把「殘缺的 assistant 回覆」一起送回 API
- **位置**：`qwen_local.py` 第 516–524、557、567 行邏輯
- **原因**：
  程式在收到回覆後**先執行 `messages.append(assistant_msg)`**，才檢查 `if not tool_calls:` 與 `if st == 'truncated': _retry_high()`。
  因此 `_retry_high()` 送出的 `messages` 陣列**最後一則角色是 `assistant`（且內容是被截斷的殘文）**，而不是 `user` 或 `tool`。
- **影響**：視 API 端實作，要嘛直接報 **HTTP 400**（最後一則必須是 user/tool），要嘛進入「續寫模式」只回傳後半截譯文，然後 `_save_result()` 直接用後半截覆蓋整份輸出，**前半截永遠丟失**。
- **修法**：呼叫 `_retry_high()` 前先 `messages.pop()` 把那則被截斷的 `assistant_msg` 彈出（順手把 `last_in_tok` 等也可保留），再改以 `effort='high'` 重送。

### 2. 正則 `(.+?)` 遇到「空欄位」會把整塊【後文背景】吞進正文／原文裡
- **位置**：
  - `materials_io.py`：`SRC_RE`、`TR_RE`、`from_jia()`
  - `pack_judge.py`：`LBL_RE`
  - `qwen_local.py`：`SRC_RE_ALL`
  - `qc_scan.py`：`load_material()`
- **原因**：這幾支都用相同的寫法：
  ```python
  r'■ (?:...)（譯本甲）\s*\n+(.+?)(?=\n+■ |\n+【(?:後文背景|...)|\Z)'
  ```
  當某一方剛好是空字串（例如 `mk_judge_materials.py` 裡雙欄缺記文時 `_pick()` 回傳 `''`，寫出 `■ 記文（譯本乙）\n\n\n\n【後文背景...`）：
  1. `\s*\n+` 會一口氣吃光全部 4 個 `\n`；
  2. 游標直接停在 `'【'` 字元上；
  3. 因為後面用 **`(.+?)`（至少 1 字元）**，它無法在原地匹配 `(?=\n+【後文背景)`，被迫跨過 `【`，**一路把整個【後文背景】和【所釋鈔文】吞進該欄變數裡直到檔尾**！
- **影響**：若 `譯本甲` 缺記文且裁決判 `PASS_A`，`from_jia()` 會把整段【後文背景】直接寫進定稿譯文；`pack_judge` 則會把背景整塊併進譯本欄位。
- **修法**：把 `\s*\n+(.+?)` 改為 `\s*\n(.*?)(?=\n+■ |\n+【...|\Z)`（允許空內容，且保留結尾前的 `\n` 給 lookahead 匹配），或寫出 `.md` 時空值不要寫該空塊／改寫 `（空）`。

### 3. `local_corpus.py` 的 `_juan_label` 會讓 CBETA 書的 `juan` 永遠卡在「卷第一」
- **位置**：`local_corpus.py` `_juan_label()`
- **原因**：
  ```python
  m = JUAN_RE.search(s)
  if not m or m.start() != 0:
      return None
  ```
  `m.start() != 0` 要求該行必須以「卷」字開頭。但大藏經原文行（`原文/` 下各部律論）的卷首標題大多帶書名或部別（如 `四分律卷第二`、`薩婆多毘尼毘婆沙卷第三`、`瑜伽師地論卷第五`），`卷` 字不在 index 0，全部回傳 `None`。
- **影響**：整部 60 卷《四分律》或 100 卷《瑜伽師地論》檢索回傳的 `juan` 欄位**從頭到尾都是預設值 `'卷第一'`**。由於 `AUDIT`／`JUDGE` 會把這個 `juan` 寫進【必改硬傷】的「依據欄」，會誤導人工複核查錯卷次。
- **修法**：比照 `_add_file()` 的寫法，允許 `m.start() > 0`，只要整行無句讀、長度 `<= 40` 且不以 `如／見／若` 等引文動詞開頭即更新 `juan`。

### 4. `qc_scan.py`「簡稱疑誤展開全稱」幾乎一定誤報
- **位置**：`qc_scan.py` 第 64–69 行
- **原因**：
  ```python
  for _full in ('《薩婆多部毘尼摩得勒伽》', ..., '《成實論》', '《毘尼母經》', ...):
      if _full in _out_norm and _full not in _src_norm:
          issues.append('簡稱疑誤展開全稱')
  ```
  古籍原文（`_src_norm`）沒有現代書名號 `《》`。所以哪怕原文原本就寫著全稱（例如「如成實論云」「如毘尼母經說」），譯文忠實寫成 `《成實論》`、`《毘尼母經》`，`《成實論》 not in _src_norm` **永遠為真**，直接誤判為「疑誤展開全稱」。
- **修法**：比對時把 `_full` 剝掉書名號（`re.sub(r'[《》]', '', _full)`）去對 `_src_norm`；也就是只有原文「沒有成實論三字」卻冒出 `《成實論》` 才報警。

### 5. `mother_corpus.py` 取母文的三個小漏洞（跨卷誤撈、截字、異體漏匹配）
- **位置**：`mother_corpus.py` `chao_for()` 與 `_VAR`
- **原因**：
  1. **跨卷污染**：`for j in range(k, max(-1, k - 3), -1):` 往前收 1–2 段鈔文時沒檢查 `seq[j]['doc'] == seq[k]['doc']`。若命中的是某卷開頭第 1–2 段（`k` 在卷首），會把**上一卷最末段**的鈔文撈進來當背景。
  2. **800 字預算繞過**：進入第 2 筆命中（`ms[1]`）時 `grp` 重設為 `[]`，`if grp and acc + len(c) + 1 > 800:` 在第一圈為 `False`，因此不管第 1 筆已經塞多滿都會硬加上第 2 筆，最後被 `txt[:800]` 從句中腰斬。
  3. **異體字表殘缺**：`_VAR` 只有 20 字，比 `local_corpus.py` 少了 `毗/毘、眞/真、裏/裡、牀/床、徧/遍、呪/咒、覩/睹、羣/群、竝/並` 等 17 字。一旦 docx 合編本與 `TXT_分卷/資持記_細分` 用字異體不同（尤其是常見的 `毗/毘`、`眞/真`、`竝/並`），整條記文就配不到【所釋鈔文】。
