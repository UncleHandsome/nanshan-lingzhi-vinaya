# 白話校閱執行規範（每一片都適用）

工作目錄：`C:/Users/lionc/OneDrive/桌面/XW/三大部`

## 一、必讀

1. `校閱批次/提示詞_白話校閱.md` 的「一、主提示詞」——這是**唯一判準**，包含 9 類錯誤定義、三遍方法、自我對抗、回報格式、P0/P1/P2 定義、禁止事項、輸出前自檢。
2. `校閱批次/_切片/<本次切片名>.txt`——這是你**唯一**要校閱的材料。每段為 `【NN-NNNN】<來源標籤>` + `【原文】…` + `【譯文】…`。

這是「重新校閱」：不要參考、不要沿用、不要比對任何既有報告或答案卷，只依你讀到的材料獨立判定。

## 二、效率紀律（務必遵守）

- 提示詞【方法】的三遍比對（誰→做什麼→對誰→在什麼條件下／科判語與引文界線／一致性）、【自我對抗】四問、以及最後的對抗視角回看，**全部是內在心算**，禁止在回覆或報告中逐段寫出分析過程。
- **推理務必精簡**：每段判定只在心裡用一兩句話帶過；自我對抗只對「已經懷疑有問題」的段落做一次，不要對全部段落逐一展開；對抗回看只看已列出的候選問題。禁止反覆重讀、反覆推敲、反覆自我反駁同一段。無法立刻判斷的，直接列存疑。
- 材料一次讀完即可，不要重複讀取。只有當某一行被工具截斷時，才用 Bash 跑 Python 補讀**該段**完整內容，不可憑截斷內容判定。
- 無法確定的段落直接列入「存疑」，不要反覆推敲。
- 最終報告只寫：有問題的段 ＋ 存疑區 ＋ 統計行。其餘一概不寫。

## 三、報告寫入

用 Write 工具寫入 `校閱批次/校閱結果/parts/<本次切片名>.md`（UTF-8，純 Markdown）。不要修改任何原始材料檔。

## 四、報告格式（嚴格）

每條意見：

```
### <編號>｜<來源標籤>｜P0｜<類型>
- 原文：〈逐字複製材料【原文】，不重打字、不改寫〉
- 譯文：〈逐字複製材料【譯文】〉
- 問題：〈一句話說清楚錯在哪〉
- 依據：〈原文哪一句可證明；P0 必填，引不出就降 P1 或不報〉
- 建議：〈只改錯處的最小修改，不整段重寫〉
- 信心：〈高／中／低〉
```

- 標題的編號與來源標籤必須從材料該段 `【NN-NNNN】` 之後**原樣整串照抄**，不可重編、不可只寫「段28」、不可自行加字。
- 同一段有多個問題，仍使用同一個標題，分行列出。
- 類型標題可用：意思相反／主詞施受錯／範圍改變／因果條件顛倒／術語錯／程序錯／漏譯或增譯／半譯／標點與體例。
- 只寫有問題的段；沒問題的不要寫。
- 有疑慮但無法確定 → 另起 `## 存疑` 區，每條列「編號：一句話說明」，不硬報、也不直接放過。
- P0：讀者依譯文會得到相反或錯誤結論；術語錯若改變制度事實（誰能做、誰在場、身份、程序、界、罪）算 P0，只是名相替換不影響事實者算 P1。P1：語意偏差不至於反義但會誤導。P2：標點、錯字、格式、引號。
- 檔尾固定一行（N 為本片實際段數）：`已檢查 N 段；P0 x、P1 y、P2 z；存疑 k 條（列段號）。`
- 全片無問題時，只寫該統計行。

## 五、判定紀律

- 不合併、不拆分、不增刪段數；不整段重寫；只改錯處。
- 沒有原文依據，不報 P0。
- 不編造原文、出處；不把「譯得不好」當「譯錯」；純語感差異不報。
- 不因句式與原文相近就判半譯，先確認是否為引文。
- 「X下／X中／X末」是指示段落位置的科判語（義為「自 X 以下」「在 X 這一段中」），「初X／次X／三X」是科判序，「約X／此約」是「就 X 而言」，都不是實詞；「」內是引文，（）〔〕內是夾注——引文的字要留，夾注的話要譯。
- 每段都要真的比對過**主詞、範圍、因果、程序**四項。
- 不跳過沒有命中任何類型的段（每一段都要讀過）。
- 若材料沒有資持記文可引（戒疏、業疏、尼鈔、義鈔），【依據】改引律本或該疏／鈔文本身，不可為了湊依據而編造記文。

## 六、完成回覆

只回覆一行，不要貼報告全文：

`DONE <切片名> | 已檢查 N 段 | P0 x P1 y P2 z | 存疑 k`
