## 一、這次修改中發現的 3 個程式接線漏洞（建議開跑前先修）

### 1. `run_pipeline.py` 的 `long` 分支雖然改了 `NO_TOOLS='0'`，但忘了改 `QWEN_LOCAL` 與 `QWEN_NO_WEB`
看 `run_pipeline.py` 跑 `_長段/_終修` 那段：
```python
if not run_agent('重譯/' + bk + '/_長段/_終修',
                 {'QWEN_RAW_SAVE': '1', 'QWEN_NO_CITE': '1', 'QWEN_NO_TOOLS': '0',
                  'QWEN_LOCAL': '0', 'QWEN_EFFORT': 'xhigh'}, args.workers):
```
因為 `run_agent()` 會用 `extra_env` 覆蓋預設值，這裡的 **`'QWEN_LOCAL': '0'`** 會把本地檢索關掉，且因沒設 `'QWEN_NO_WEB': '1'`，長段終修反而變成「**無本地書庫、但能上網搜**」。
* **修法**：改為 `'QWEN_LOCAL': '1', 'QWEN_NO_WEB': '1'`（與一般段的 `revise` 分支對齊）。

### 2. `run_l7.py` 雖然開了 `QWEN_LOCAL='1'`，但 `QWEN_MAX_LOCAL` 還被設成 `'0'`
看 `run_l7.py` 的 `STAGES` 與 `agent()`：
```python
'revise': dict(raw='1', cite='1', tools='0', local='0', web='1', effort='xhigh'),
...
'QWEN_MAX_LOCAL': STAGES[stage].get('local', '5'),  # ← 這裡變成了 '0'！
...
if STAGES[stage]['tools'] == '0':
    env['QWEN_NO_TOOLS'] = '0'
    env['QWEN_LOCAL'] = '1'
    env['QWEN_NO_WEB'] = '1'
```
結果會傳入 `QWEN_MAX_LOCAL='0'`；在 `qwen_local.py` 中，`stats_cap` 會直接被強制壓成 `0`，模型一呼叫 `local_search` 就會立刻收到「已達上限（0 次）」。
* **修法**：直接把 `STAGES['revise']` 改為 `tools='1', local='5', web='1'`（順便拿掉那個已經沒必要的 `if tools == '0'` 補丁），就不會再自相打架。

### 3. `pack_judge.py` 的斷行補丁只救到 `疏文`，雙欄併批時 `記文` 仍會靜默遺失
您補上了這兩行：
```python
body3 = re.sub(r'(\[\d+\])\s*(?=【)', r'\1' + chr(10), body3)
body3 = re.sub(r'(?m)^\s*\**\s*\[\s*(\d+)\s*\]\s*\**\s*\n(\s*【(?:疏文|記文|鈔文|律文|註文|序文)】)', r'\2\n[\1]', body3)
```
如果模型是**按段號為單元**輸出雙欄（這是併批時模型很常見的寫法）：
```text
[1] 【疏文】內容A 【記文】內容B
[2] 【疏文】內容C 【記文】內容D
```
經過這兩行轉換後會變成：
`【疏文】\n[1]內容A 【記文】內容B\n【疏文】\n[2]內容C 【記文】內容D`
接下來第 177 行用 `【(疏文|記文|...)】` 切分時，`lab_map['記文']` 拿到的是 `內容B\n\n內容D`——**`[1]`、`[2]` 已經被 `【疏文】` 吃掉了，`記文` 底下完全沒有編號**！進到第 210 行 `parts` 只會分出 1 塊，`per_group` 拿不到任何 `記文`，於是 **`[1]` 和 `[2]` 的 `記文` 會無聲跳過並退回沿用譯本甲**。
* **修法**：在 `secs = re.split(...)` 之前先偵測：若 `body3` 裡「`[n]` 在 `【疏文】` 之前（按段交錯輸出）」且含多欄，直接先按 `^\s*\[(\d+)\]` 切出每段 `[n]` 塊，再從各自塊內抽 `【疏文】【記文】`，就完全不會漏掉 `記文`。
