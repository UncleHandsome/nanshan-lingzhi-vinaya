### 一、會直接崩潰／讓流程失效的 7 處高危問題

#### 1. `local_corpus.py` `load()` 縮排錯位：27 部書庫全數變空
在 `local_corpus.py` `load()`（`YUAN/` 讀取迴圈）：
```python
                for i, line in enumerate(raw.split('\n')):
                    s = line.strip()
                    if not s:
                        continue
                    lab = _juan_label(s, book)
                if lab and (re.search(r'[。！？，、；：]', s) or s.startswith(('如', '見', '若'))):
                    lab = None
                    if lab:
                        juan = lab
                        continue
                    ...
                    LINES.append(rec)
```
- `if lab and ...` 以下整段被**退縮排到 `for i, line` 迴圈外面**，而且 `lab = None` 緊接著 `if lab:` 永遠為 `False`，**`LINES.append(rec)` 變成完全執行不到的死碼**（空檔還會拋 `UnboundLocalError: lab`）。
- **後果**：`YUAN/` 底下的 27 部大藏經／科文／辭典（含《四分律》《隨機羯磨》《濟緣記》《行宗記》《業疏科》《南山律學辭典》）**完全沒有建進索引**，本地搜尋只搜得到 `EXTRA` 的 6 部！

#### 2. `qwen_local.py` `_save_result` 新加的「重貼原文」分支會直接拋錯
```python
        if _looks_pasted(out, _src_unit(src_text)):
            stats['pasted_source'] = True
            extra_tag += ', 疑似重貼原文'
            _bad = os.path.join(dst, filename[:-3] + '_重貼原文.txt')
            io.open(_bad, 'w', encoding='utf-8').write(out)
            return 'pasted'
```
這 4 行一次中了三個錯：
1. `filename` 在 `_save_result` 裡**根本沒定義**（`NameError`）；
2. `dst` 是 `_回.txt` **檔案路徑**不是資料夾，應改用 `dst.replace('_回.txt', '_重貼原文.txt')`；
3. 外層用 `st, tag = _save_result(...)` 接收 **2 元組**，只 `return 'pasted'` 會拋 `ValueError: too many values to unpack`。

#### 3. `qwen_local.py` `FatalAPIError` 還是沒能走進 `sys.exit(2)`
- `except FatalAPIError` 先把 `STOP` 和 `STOP_GLOBAL` 寫出來，這會使 `main()` 結尾的 `if stop.is_set() or _stop_requested():` 變成 `True`。
- 你們新加的 `if _FATAL: ... sys.exit(2)` 放在 `else:` 裡面，**永遠執行不到**。發生 401／402 時依然會走進 `if _stop_requested()` 並以 exit code `0` 結束、也不會寫 `.stage_partial`（要把 `if _FATAL:` 移到 `if stop.is_set() or _stop_requested():` **之前**）。

#### 4. `JUDGE_PROMPT` 精簡時把 `PASS_A_KEEP_A` 標記指令刪掉了
- 新版 `JUDGE_PROMPT`（第 2.4 節與 `mk_judge_materials.py`）第 3 欄只剩：`REVISED 時完整輸出，須以原標籤開頭`。

  - 寫成 `沿用譯本甲` → `is_keep_a()` 判 `False`，把「沿用譯本甲」四個字送進終審甚至寫進定稿。

#### 5. `pack_audit.py` 完全忘了放 `AUDIT_PROMPT`，且會製造「雙重打包」
1. `pack_audit.py` 產出的 `.md` 從 `'---'` 開頭，**根本沒有插入 `AUDIT_PROMPT`**。模型送審時完全不知道要輸出 `【逐句簡核】／【結論】／【必改硬傷】` 三欄格式。
2. `pack_audit.py` 不檢查 `packed` 旗標也不檢查相鄰段號：已經在 `mk_review_materials.py` 打過 `[1][2]…` 的短段組會再被包一層 `[1][2]…`，導致下游 `pack_final.py` 的 `split_marked()` 因 `[n]` 數量對不上而整包失敗。

#### 6. `make_hybrid.py` 的四處邏輯錯誤會漏段兼重跑 6,551 組
1. **子字串誤判漏段**：`if ns and ns in big:` 把整卷文字串成 `big` 去比對。只要舊材料沒覆蓋到的短段（例如 `【疏】問。`、`【記】釋前文。`、`【疏】如上已明。`）字面剛好出現在同卷另一段長文裡，就會被誤認成已覆蓋而**永久漏掉**。
2. **新組檔名 `os.rename` 必敗**：`M.emit()` 存出來的檔名是 `{chunk}_{s0+1:04d}.md`，不是 `0001.md`，所以 `os.rename(... '%04d.md')` 全數失敗並被 `except: pass` 吞掉；更危險的是若新舊組起始行號恰好撞名，會直接覆蓋舊 `.md` 卻留著舊回覆。
3. **沒複製 `.json` 也沒複製 `_usage.json`**：舊組只複製了 `.md` 與 `_回.txt`。沒有 `_usage.json`，進 `qwen_local.py` 時會因為 `os.path.exists(_u)` 為 `False`，**把 6,551 組已預填的譯文全部重跑一遍**（且之後若重產 `_hy_盲翻/*.md` 也會因 `mtime` 較新全部變 `_STALE`）；沒有 `.json` 則會退回較脆弱的 `parse_md()`。
4. `BLOCK` 正則缺少 `(?:\[\d+\])?` 與 `【分段要求` 前瞻，遇舊打包段會把分段提示一起吞進 `body`。

#### 7. `build_a2.py` 新加的 `_plain_revise` 順序倒置，反而會讓前言流進定稿
```python
txt = _plain_revise(norm.normalize(_rt))
if not txt or not re.search(r'【', txt):
    try:
        txt = col3(_rt)
```
- 如果修訂模型在開頭寫了兩句前言（例如：`經核對硬傷清單，第 2 項已修正：\n\n【疏文】\n……`），因為裡面含有 `【`，會繞過 `col3(_rt)` 的剝頭機制，**把整段模型前言寫進最終定稿**。
- 如果修訂模型忘記寫 `【疏文】` 標籤（只有純譯文），`not re.search(r'【', txt)` 反而讓它去呼叫必敗的 `col3(_rt)`，導致**整份修訂譯文還是被丟掉**。
- 正確順序應為：**先試 `col3(_rt)`，失敗時才退回 `_plain_revise`**。

1. **`local_corpus.py` 短別名搶前綴＋未定義 `rows`**：
   - `ALIASES` 剛補上的 `('四分律含注戒本', '戒疏')` 與 `('四分律隨機羯磨', '隨機羯磨')` 排在更長的書名之前。因 `_norm_book` 用 `q.startswith(alias)`，現在查 `四分律含注戒本疏科`、`四分律含注戒本疏行宗記` 會全數錯轉成 `戒疏`；查 `四分律隨機羯磨疏` 會錯轉成 `隨機羯磨`。`ALIASES` 必須按 `len(alias)` 由長到短比對。
