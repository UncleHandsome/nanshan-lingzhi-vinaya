## 一、提示詞會不會太 case-by-case？

**核心檢核框架不過度特化，但「特定書籍規則」與「微調補丁」確實貼得太散、太細。**

1. **`SYSTEM_PROMPT` 混入了特定單書的局部規則**
   - 第 2 點突然插入 `（僅《尼鈔》）多節略自《行事鈔》……`、第 4 點寫 `《資持記》缺所釋原文時優先搜《行事鈔》`。
   - 跑《業疏》《戒疏》時每筆請求都在送這兩條無關指令（而且《尼鈔》在 `book_config.py` 已有 `NICAO_NOTE`）。這類規則應該全數退回 `book_config.py`，依當前書別動態注入。
2. **`book_config.py` 的 `SHUJI_CTX[1]` 補丁疊得太長、太繞**
   - 原文這句一口氣塞了五層轉折（140 多字）：
     > 「勿把記文專論之擴展解釋搬入疏文正文，但疏文略語……仍須參照記文……並使疏文保留銜接所牒實詞之字眼，但僅譯出原文既有字面與貼合文脈之指涉方向，勿敷衍成典故背景故事；亦須以【疏文】前提檢核【記文】科判動詞與釋義……」
   - 這是為了「水與水該刪／銜接實詞／防擴寫」等測項不斷往上打的補丁。規則愈像走鋼絲，模型反而愈容易因過度防禦而漏資訊或夾帶解釋。
3. **`SYSTEM_PROMPT` 硬寫了工具配額數字**
   - 提示詞寫「上限可達 6」「`web_search 1～2 次、web_fetch 1 次`」，但實際上 `qwen_local.py` 會依字數動態調成 1～6 次，且短文時 `web_search` 上限只有 1。提示詞只需寫「以工具回傳與上限提示為準，用完即停」，不要寫死數字跟程式打架。

## 二、自相矛盾與脫節之處

### 1. 一審 `BASE_PROMPT` 佔位符全數失效，且與執行參數衝突
- `mk_review_materials.py` 的 `get_prompt()` 和 `prompt_for()` 傳進了 `book_ctx`、`shuji_check`、`extra_ban`、`cite_source`、`tag_note`、`cite_ji` 六個參數，但現行 **`BASE_PROMPT` 字串裡已經沒有任何這些 `{...}` 佔位符**，全部被 `format()` 無聲丟棄了（即一審的疏記互核與部別說明目前根本沒送進模型）。
- `BASE_PROMPT` 的原則編號從 `1. 2.` 直接跳 `4.`（`JUDGE_PROMPT` 也是 `1.` 直接跳 `3.`）。
- 架構表（一、整體架構）仍寫一審是「三欄輸出」，但現行 `BASE_PROMPT` 已改成只輸出純譯文；然而 `run_pipeline.py` 的 `review` 階段仍設 `QWEN_RAW_SAVE=0` 與 `QWEN_NO_CITE=0`，導致 `SYSTEM_PROMPT` 叫它「於理由或依據中簡註書名卷次」，一審卻根本沒有理由欄位，還會在存檔時嘗試切 `_split_col3`。

### 2. 「禁止解說括號」與「直譯勿委婉」的跨階段衝突
- **括號與讀音標準不一**：`BLIND_PROMPT` 豁免「原文夾注與讀音釋義」可使用圓括號；`AUDIT_PROMPT` 也寫夾注、讀音得保留；但 `BASE_PROMPT` 只寫「正文不加解說括號」，沒寫明夾注與讀音豁免，一審有可能把盲翻保留的原文夾注圓括號砍掉。另外 `〔補字〕` 建議改寫為 `〔所補之字〕` 或給個小範例（如 `〔某〕`），以免模型照字面寫出 `〔補字：某〕`。
- **直譯實詞 vs 400 內容審查**：`BLIND_PROMPT` 要求「涉及戒相、身體或行為要件之實詞須精準直譯，勿改為籠統委婉語」。南山律典大量涉及婬戒、摩觸、不淨物，寫「勿委婉」會提高觸發模型平台 `data_inspection_failed`（HTTP 400）的機率，建議改為「**以中性、準確的律學／醫學實詞直譯要件，不作粗俗渲染，亦不空泛迴避**」。

### 3. 終審（有工具＋xhigh）與修訂（無工具＋high）的權責倒掛
- `mk_audit_materials.py` 刻意把裁決的第 2 欄壓縮成只剩「採甲／乙／重修＋書名線索」（防止終審員偷懶照抄）。
- 但到了 `mk_revise_materials.py`，卻把**完整版的【裁決分歧（僅供參考）】**交給一個**沒有檢索工具（`QWEN_NO_TOOLS=1`）、思考降級（`high`）**的修訂編輯，且 `REVISE_PROMPT` 授權他「可駁回硬傷清單、維持原譯」。
- 如果發生像 7.4 節 07 組「裁決自己判斷錯」的情況，終審明明靠工具查出了真硬傷，修訂編輯卻可能被裁決漂亮但錯誤的理由說服，在無工具查證下駁回終審硬傷。建議修訂階段**不要附裁決完整理由**，只附原文、目前譯文、硬傷清單即可；「駁回」條件也應收緊為「僅當清單修改將造成字面漏譯或與原文顯然背反時」。

### 4. `AUDIT_PROMPT` 塞入譯者向的「分段保留指令」
- `mk_audit_materials.py` 在打包組（`md.get('packed')`）塞進 `請保留 [1][2]… 編號逐條對應，勿合併、增減條數或改動編號`。這是給翻譯／裁決的指令，終審只輸出逐句簡核與硬傷清單，這句應改成「請於【逐句簡核】與【必改硬傷】條目前標註 `[1]`、`[2]`… 段號」。

### 5. `SYSTEM_PROMPT` 說「以 `remaining` 為準」，但網搜沒有 `remaining`
- 只有 `local_search` 回傳 `remaining` 與額度用盡 `notice`；`web_search` 與 `web_fetch` 只有超過上限後才會回傳 `error`。

## 四、其他重大問題（程式碼掃描發現的實質 Bug）

下面這幾個問題**直接影響正確率、資料完整性與 Token 費用**，建議優先檢查：

### 1. 【最嚴重】`local_corpus.py` `load()` 縮排錯位，導致 27 部《原文》書庫完全沒載入！
請看第 6.2 節 `load()` 的 `BOOKS` 迴圈：
```python
                for i, line in enumerate(raw.split('\n')):
                    s = line.strip()
                    if not s:
                        continue
                    lab = _juan_label(s, book)
                if lab and (re.search(r'[。！？，、；：]', s) or s.startswith(('如', '見', '若'))):
                    lab = None
                    if lab:
                        juan = lab
                        continue
                    if not HAN.search(s):
                        continue
                    rec = {'id': '%s|%s|%d' % (book, fn, i), 'book': book,
                           'juan': juan, 'no': i, 'text': s, 'plain': _plain(s)}
                    LINES.append(rec)
```
- `if lab and ...` **退出了 `for i, line` 迴圈**，而且後面的 `if lab:`、`LINES.append(rec)` 全都被縮排在 `lab = None` 裡面！
- 因為 `_juan_label()` 已經擋掉了標點和「如見若」，這個 `if lab and (...)` **永遠為 False**。
- **直接後果**：所有放在 `YUAN` 目錄下的 27 部典籍（《四分律》《五分律》《十誦律》《隨機羯磨》《濟緣記》《行宗記》《業疏科》《戒疏科》《南山律學辭典》《婆沙》《伽論》……）**一行都沒有進到 `LINES`**！這也解釋了為什麼文件第 4.1 節統計表總共只列出 6 部書（`44,212` 行），與 7.8 節曾提到的「255,586 行」差了二十多萬行！
- 順帶一提：同一支檔 `find()` 裡的 `if per_book is None: per_book = rows if work else 2`，`rows` 未定義（應為 `limit`）。

### 2. 【會大量重翻燒錢】`make_hybrid.py` 預填的 6,551 份譯文會被 `qwen_local.py` 全部重跑！
- `qwen_local.py` `run()` 判斷跳過的條件是：
  `if os.path.exists(dst) and os.path.getsize(dst) > 10 and os.path.exists(_u):`（必須同時有 `_回.txt` **和** `_usage.json`）。
- 但 `make_hybrid.py` 只寫出了 `_回.txt`，**沒有複製或產生 `_usage.json`**！
- 只要對 `_hy_盲翻` 執行 `qwen_local.py`，那 6,551 份已預填的舊回覆會因為缺少 `_usage.json` 而被判定為未完成，**全部重新翻譯一次**。
- 此外 `make_hybrid.py` 還有兩個 Bug：
  1. 第 105 行嘗試把 `M.emit()` 產生的檔案從 `0001.md` 改名為 `n0001.md`，但 `M.emit()` 已經改成用 `chunk_0001.md` 命名，所以 `os.rename` 會在 `try...except: pass` 裡**永遠靜默失敗**（檔案根本沒改成 `n` 開頭，甚至有撞檔覆蓋風險）。
  2. 第 62 行用 `if ns and ns in big:`（子字串比對）判斷舊組是否覆蓋某段，遇到短句（如「如文。」「釋曰。」）只要在同一個 chunk 的別段出現過，就會誤判為已覆蓋而漏掉。

### 3. 【執行期崩潰】`qwen_local.py` `_save_result()` 攔截重貼原文時會直接報 `NameError`
- 當 `QWEN_RAW_SAVE=1` 且觸發 `_looks_pasted()` 時：
  ```python
  _bad = os.path.join(dst, filename[:-3] + '_重貼原文.txt')
  io.open(_bad, 'w', encoding='utf-8').write(out)
  return 'pasted'
  ```
  這裡 `filename` 根本未定義、`dst` 是檔案路徑不是目錄，而且 `return 'pasted'` 只回傳單一字串，外層 `st, tag = _save_result(...)` 解包也會噴 `ValueError`。
- 同一支檔 `_looks_pasted()` 裡的 `r'^\s*【...】\\s*'` 多了一個反斜線，無法剝除標籤後的空白。
- 另外 `QWEN_SKIP_400` 只在 `main()` 決定要不要呼叫 `test_apis()` 時用到，沒有過濾真正送進執行緒池的 `files`，所以遇到 `_400審查.txt` 重跑時還是會重送一次。

### 4. 【流程斷鏈】`pack_audit.py` 漏了提示詞、取錯後文；`run_long_audit.py` 傳錯參數
- **`pack_audit.py`**：第 91 行組裝 `.md` 直接從 `'---'` 開始，**完全沒有放 `AUDIT_PROMPT`**。依第 4.6 節「跑審核 → 修訂 → 定稿」去跑時，模型收不到審核格式與任務說明。且 `post = pack[0]['md'].get('post', '')` 取的是第一段而非最後一段（`pack[-1]`）的後文。

### 5. 【靜默污染定稿】`norm.py` 與 `pack_judge.py` 的正則／標籤問題
- **`norm.py` 先把自創標籤寫死換成 `【鈔文】`**：第 66–68 行逐行先把行首 `【修訂譯文】`、`【修正後譯文】` 換成了 `'【鈔文】'`，導致第 70–77 行「依文本既有標籤（疏文／記文）轉換」的邏輯根本吃不到這些標籤，在《業疏》《資持記》仍會誤變 `【鈔文】`。

- **`qwen_local.py` 打包配額計算過寬**：計算 `_pn` 時 `_head` 包含了【前文背景】，若前文背景裡恰有行首 `[1]`，會誤觸發增加本地搜尋額度，應切掉 `【前文背景】` 段落再算。
