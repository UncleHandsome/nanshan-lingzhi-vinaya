### 一、`qwen_local.py` 的三個執行器細節問題

1. **審核階段（`QWEN_RAW_SAVE=1`）誤套用 `_strip_dup_labels()`**
   - 依 4.4 節，審核（`audit`）設為 `QWEN_RAW_SAVE=1`（因為要保留完整的 1～4 欄報告）。
   - 但 `_save_result` 在 `QWEN_RAW_SAVE == '1'` 分支仍執行了 `out = _strip_dup_labels(out)`，會把審核報告中行首出現第二次的 `【疏文】`／`【記文】` 標籤剝掉（該函式上方的註解也自己寫了「只應作用於第 3 欄」，但代碼沒照做）。

2. **工具函式 `**args` 無容錯，模型傳錯參數名會白耗一輪歷史**
   - `local_search(query, work=None, rows=3, stats=None)` 與 `web_search(query, ori_question=None, rows=10, stats=None)` 都直接用 `**args` 接模型參數、未加 `**kwargs`。
   - 模型只要偶爾把 `work` 誤寫成 `book`，或把 `rows` 誤寫成 `limit`／`count`，就會直接觸發 `TypeError: got an unexpected keyword argument` 回傳錯誤，白白多跑一輪並重送整段思考與上下文。

3. **達到輪數上限的催促詞會誤導盲翻模型**
   - 工具迴圈達到 `MAX_TOOL_ROUNDS = 8` 時，統一補送：
     `已達工具檢索輪數上限，請直接根據現有資料完成最終覆核並依規定格式輸出。`
   - 這句對裁決／審核沒問題，但對「盲翻」要求「完成最終覆核」容易誘發模型改寫成審校報告而非純白話譯文（改為「依原本任務規定格式直接輸出最終結果」較安全）。

### 二、`col3()` 的兜底正則會把「前幾欄報告」整個吃進譯文

- `mk_judge_materials.py`、`mk_audit_materials.py`、`mk_revise_materials.py`、`build_a2.py` 四支腳本的 `col3()` 都帶了同一段兜底邏輯：
  ```python
  _k = rt.find('分歧與裁決')
  _from = _k + 5 if _k >= 0 else 0
  mm = re.compile(r'【(?:疏文|記文|鈔文|律文|註文|序文)】').search(rt, _from)
  ```
- 一旦模型沒寫出精確字面「修正後的譯文」（例如改成 `3. 定稿譯文：`），同時在第 2 欄（或一審第 1 欄）開頭用 `【疏文】` 標記分歧條目，`mm` 就會直接命中前面欄位裡的 `【疏文】`，**把整個「分歧與裁決」或「逐句檢查」直接當成譯文送進下一關或定稿**。

### 三、`mk_judge_materials.py` 檔頭範例與 `run_pipeline.py` 的甲乙順序相反

- `mk_judge_materials.py` 檔頭用法寫 `--a out --b 盲翻/回覆`（甲＝舊譯 `out`、乙＝盲翻），但 1 節架構與 `run_pipeline.py` 實際是 `--a 盲翻/回覆 --b out`（甲＝盲翻、乙＝舊譯 `out`）。
- 由於 `PASS_A` 預設沿用**譯本甲**，這個順序並非純粹代號差異：照檔頭跑會預設保留舊譯，照 `run_pipeline.py` 跑才是保留新盲翻（建議把 `mk_judge_materials.py` 檔頭改與管線一致，避免人為手動補跑時貼反）。
- 順帶一提：`run_pipeline.py` 寫死讀取 `_材料` 與 `_盲翻`，尚未對齊 4.10 節的 `_材料_hy`／`_hy_盲翻`，也未串接 `pack_judge` 與 `_長段`。

### 四、長段與修訂材料的邊界細節

1. **`mk_split_blind.py` 對少標點文本可能從句中對半切開**
   - 依 `BOOKS` 路徑，`業疏`、`義鈔` 用標點版，但 `戒疏`、`尼鈔`、`行事鈔` 讀的是 `TXT_分卷`（無統一後加標點）。當 >500 字長段缺少 `。！？；` 時，`split_sentences` 會退化為切在頓號／逗號甚至直接 `mid = len(text) // 2` 硬砍，兩小段各自盲翻再 `''.join(segs)` 拼回時，接縫容易產生半截語法或代詞重複。
2. **`mk_revise_materials.py` 的 `【分段要求】` 位置偏後**
   - 對 `packed=True`（含 `[1][2]…`）的短段包，`mk_revise_materials.py` 把 `【分段要求】` 放在 `【目前譯文】` 之後，且 `REVISE_PROMPT` 本體未提保留 `[1][2]…`，修訂時比前面幾關更容易不小心漏掉或合併編號。
