兩件事被我混在一起，我拆開講。

## 1. 為什麼會說「少 27 行」

| 我算的 | 數字 |
|:--|--:|
| 義鈔原文行數 | 234 |
| `_裁決` 資料夾的組數 | 207 |
| 相減 | **27** |

我當時只數了 `_裁決`，**忘了把 `_長段/_終審` 的 27 個長段母段算進去**。

## 2. 但實際上沒少

| 來源 | 數量 |
|:--|--:|
| 一般段 `_裁決` | 207 |
| 長段母段 `_長段/_終審` | 27 |
| **合計** | **234** |

→ 234 = 234，**一行都沒少**。那 27 行正好是長段。

## 3. 網站為什麼變半

這才是真的 bug，跟「少 27 行」無關：

| 問題 | 說明 |
|:--|:--|
| 匯出的定稿含 `【鈔文】` 標籤 | 標籤被當成獨立一段 |
| 標籤與正文間有空行 | 一段變兩段 |
| `00_卷首` 實際 | 22 行 → 匯出成 **37 段** |
| `site_ju` 配對 | 用 `min(原文段數, 譯文段數)`，錯位後大量空白 |

## 4. 修正後

| 指標 | 值 |
|:--|--:|
| 匯出段落 | 234（與原文行數一致） |
| 卷上配對 | 70（與舊站相同） |
| 白話字數 | 61,856（比舊站多） |

## 總結

| 說法 | 對錯 |
|:--|:--|
| 「義鈔漏 27 行」 | **錯**，是我漏算長段 |
| 「網站少一半」 | 對，是標籤／空行造成段落錯位 |
| 現在修好了嗎 | 是，已重建上站 |
