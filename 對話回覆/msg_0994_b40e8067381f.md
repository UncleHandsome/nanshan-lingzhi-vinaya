## 三、程式碼修改建議（`mk_audit_materials.py` / `mk_revise_materials.py` / `qc_scan.py`）

比對你貼出的第 6 節程式碼，有幾處**實質程式 Bug** 與**機制缺失**需要一併處理：

### 1. `mk_audit_materials.py`（6.10）

1. **【實質 Bug】`資持記` 修改 `body` 發生在 `body` 賦值之前**
   現行第 6.10 節寫法：
   ```python
        if book == '資持記':
            srcs = [('記文' if lab == '鈔文' else lab, s) for lab, s in srcs]
            body = re.sub(r'(?m)^【鈔文】', '【記文】', body)   # ← 此時 body 尚未定義（或殘留上一筆！）
        for lab, s in srcs:
            L += ['■ %s（原文）' % lab, '', s.strip(), '']
        body = col3_safe(rt)
   ```
   **修法**：先把 `body = col3_safe(rt)`（含 `PASS_A` 回填 `body = _from_jia(t)`）算出，確定不為 `None` 後，再做 `if book == '資持記': body = re.sub(...)`（同時把 `srcs` 的轉換留在 `for lab, s in srcs:` 之前）。

2. **檢查 `_dual` / `_long` 與 `pack_audit.py` 的 `_dual` 變數**
   貼出來的 `mk_audit_materials.py` 與 `pack_audit.py` 裡，只有 `_has_dual = ...`，卻在 `.replace('{dual_note}', _dual).replace('{long_note}', _long)` 使用了 `_dual` 和 `_long`（若是文件貼文時漏列，請核對實碼確實有定義這兩個字串；若實碼真的沒定義，跑起來會直接 `NameError`）。

3. **【機制改良】`【裁決分歧參考】` 不要把裁決理由砍到只剩「採乙／採重修＋16字書名」**
   現在 `mk_audit_materials.py` 把 `_why` 整段丟掉，只留 `採甲／採乙／採重修` 和最多 2 個 `《書名》…` 片段。這會導致：
   - 裁決如果引的是「記云：……」「疏云：……」（沒帶 `《》`），`_srcs` 直接抓不到；
   - 裁決把甲翻掉（如 `L5 07 組` 或 `01d` 類狀況），審核看不到原「甲作」與裁決理由，就容易跟著錯誤的「重修」一起錯。
   **建議**：對 `採乙` 或 `採重修` 的分歧條目，保留完整 `_s`（或至少保留 `甲作「…」vs 乙作「…」` 與理由前 120 字，總塊上限維持 2000 字即可），只對 `採甲` 的條目做極簡壓縮。
