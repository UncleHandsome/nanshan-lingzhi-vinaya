### 一、會造成「修了卻沒套用」或「檔名覆蓋」的嚴重 Bug

1. **`build_a2.py` 未共用 `MI.verdict()`，超過 600 字的審核報告會把 `FIX` 誤判為 `PASS`**
   - 7.12 節紀錄寫已抽出 `MI.verdict()`，但只有 `mk_revise_materials.py` 呼叫了它；`build_a2.py` 自己寫了一套判斷：
     ```python
     m = re.search(r'結論[^A-Za-z]{0,12}(PASS_A|PASS|FIX)', v[:600])
     if m:
         is_fix = m.group(1) == 'FIX'
     else:
         is_fix = bool(re.search(r'^\s*[-*]?\s*\**FIX\**\s*$', v, re.M))
     ```
   - 因為 `AUDIT_PROMPT` 把 `1. 【逐句簡核】` 排在 `2. 【結論】` 前面，長段的逐句簡核只要超過 **600 字**，`v[:600]` 就抓不到結論；接著退回用 `^\s*[-*]?\s*\**FIX\**\s*$` 匹配，但 `2. 【結論】：FIX` 與標題在同一行，結果一樣匹配不到！
   - **後果**：`mk_revise_materials.py`（用 `v[:4000]`）有判 `FIX` 並送去修訂出新版譯文，但 `build_a2.py` 卻判 `is_fix=False`，**直接把修訂好的譯文丟掉、沿用有錯的裁決舊稿**。

2. **長段拼回 `merge_long.py` 與一般段的檔名差 1 號（0-based vs 1-based 撞名覆蓋）**
   - `mk_review_materials.py` 產出的檔名用 `s0 + 1`（**1-based**，第 1 段是 `_0001`）。
   - `mk_split_blind.py` 的 `idx` 用 `enumerate(lines)`（**0-based**），`merge_long.py` 直接寫出 `'%s_%04d.txt' % (chunk, idx)`。
   - 若第 11 段（`idx=10`）是超長段，拼回會叫 `chunk_0010.txt`；若將 `_長段/_定稿` 與 `_定稿` 併入同一目錄，會**直接覆蓋掉第 10 段（`s0+1=10`）的正常譯文**。

### 二、`mk_revise_materials.py` 與 `build_a2.py`（修訂→定稿）的問題

1. **`minor_block()` 跟 `REVISE_PROMPT`、`AUDIT_PROMPT` 三方矛盾**
   - `AUDIT_PROMPT` 明寫 `【可斟酌微瑕】……不列入修訂`；`REVISE_PROMPT` 也說 `只依硬傷清單逐項修正……勿為修辭改動`。
   - 但 `mk_revise_materials.py` 又用 `minor_block()` 把【可斟酌微瑕】塞進修訂提示詞末端叫模型「順手併修」——而修訂階段設了 `QWEN_NO_TOOLS=1`（完全斷網無檢索），模型根本無法查證「順手改字」有沒有律義副作用。
   - 另外 `minor_block()` 的結束條件 `(?=\n\s*\n|\Z)` 只要遇到空行就會截斷，第 2 條以後的微瑕會被切掉。

2. **`build_a2.py` 讀修訂檔沒清開場白與括號說明**
   - `build_a2.py` 讀 `_終修/回覆` 時只做 `i = txt.rfind('修正後的譯文'); txt = txt[i+6:].lstrip('*：: \t\r\n')`，不像 `col3()` 有呼叫 `_strip_head_paren`。
   - 若修訂模型回 `修正後的譯文（已依清單修正）：\n【疏文】…` 或在開頭寫了「已駁回第 2 項：」，這些說明文字會**直接流進最終定稿**。

### 四、`norm.py` 與 `run_pipeline.py` 的隱藏漏洞

1. **`norm.py` 會把 `【疏文（修訂）】`、`【記文（修訂）】` 錯改成 `【鈔文】`**
   - `norm.py` 先設 `_lab = '鈔文'`，再用 `if '【%s】' % _cand in _txt` 偵測現有標籤。
   - 若模型輸出 `【疏文（修訂）】` 或 `【記文（修訂）】`，字串裡根本沒有完整的 `'【疏文】'` 或 `'【記文】'`，結果 `_lab` 保持預設 `'鈔文'`，`LABEL_FIX` 會把它全部替換成 **`【鈔文】`**。

2. **`run_pipeline.py` 不檢查階段是否真的全部成功**
   - `qwen_local.py` 即使遇到大量 `400_blocked`、`_截斷.txt` 或 `FATAL`，最後仍會回傳 exit code `0`。
   - `run_pipeline.py` 的 `run_agent()` 只看 `returncode == 0`（完全沒檢查輸出目錄是 `.stage_done` 還是 `.stage_partial`），等於前面有缺檔、截斷或審查擋下時，管線照樣往下推到定稿。
