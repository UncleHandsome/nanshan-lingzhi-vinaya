### 一、兩個會立刻撞壞現有下游腳本的標籤問題

1. **`【沿用譯本甲】` 剛好只有 7 個字，會被 `mk_audit_materials.py` 當成異常檔直接略過！**
   - 看你們第 6.7 節 `mk_audit_materials.py` 的 `col3_safe()`（第 120 行）與 `build_a2.py`：
     ```python
     if len(body) < 8:
         return None
     ```
   - `【沿用譯本甲】` 的字串長度剛好是 **`7`（`< 8`）**！如果下游腳本還沒特別為這個標記開白名單回抓甲本，**16、20 組（以及所有 `PASS_A`）進到 `mk_audit_materials.py` 時會直接印出 `⚠ 略過異常檔` 被跳過**。
2. **`【沿用譯本甲】` 的方括號誘發模型覆蓋掉 `【鈔文】`（5／8 單欄組全壞）**
   - 因為規範裡用了帶 `【】` 的 `【沿用譯本甲】`，模型在 `REVISED` 的單欄組產生對稱聯想，把第 3 欄原本規定的 **`【鈔文】`** 擅自改寫成：
     - **01 組**：`【鈔文（修訂）】`
     - **05、12 組**：`【修訂譯文】`
     - **17、19 組**：`【修正後譯文】`
   - 更麻煩的是，`norm.py` 和 `qc_scan.py` 目前只認 `【疏文|記文|鈔文】`，**這 5 組的 `【修訂譯文】／【修正後譯文】` 不會被濾掉也不會報警，會直接殘留進最終定稿**。
   - **修法**：`PASS_A` 標記不要用 `【】`（改用 `PASS_A_沿用譯本甲` 或 `==KEEP_A==`），並在 `mk_audit_materials.py`／`build_a2.py` 優先攔截該標記、回裁決材料抓取譯本甲；同時在 `norm.py` 補剝 `【修訂譯文】／【修正後譯文】`。

### 二、為什麼這版「省量版裁決」品質退步、輸出還反增 +16%？

對照你們舊版 `xhigh 裁決`（`測20b_報告`），這版明顯出現了**「外顯第 2 欄寫得太簡略 → 連帶讓第 3 欄失去錨點而放水／錯改」**的副作用：

- **放水變懶的組明顯變多**：**08、15、16、18** 四組幾乎照搬甲本（16 組懶判 `PASS_A` 放行 `人、法、事` 與贅注；08 組連 `(把坐具交出)` `(再還回來)` 都沒動；15 組留著整句文言 `「得與不得，還報者殘」`）。
- **錯採乙說／改壞原對處變多**：
  - **04 組**：竟然錯引《濟緣記》，把 `由色變故` 改反成「隨生長而轉變」。
  - **06 組**：退回採甲 `不集合僧眾`（施受反轉），又把 `別乞` 重修成「比丘自行乞食」（《多論》明文不犯的行為！）。
  - **05 組**：把乙錯加的「不知有閏……隨人取捨」抄回正文；**11 組**：把記文改回乙錯的「少受（所受少於所失）」。
  - **07 組**：把疏文「四等」改成「四無量心」，弄斷與記文「『四等』就是慈、悲、喜、捨」的照應；**12 組**：拿《尼鈔》把《行事鈔》的 `三寶數` 改成 `僧寶之數`；**09 組**：留 `麤重罪` 又把 `彼聞便止` 寫成「對方聽到後便可停止」。
- **根本原因**：舊版 `JUDGE_PROMPT` 讓模型逐點展開寫第 2 欄，其實是強制模型做一次**結構化的「逐句對位鏈（CoT）」**；一壓縮第 2 欄的分析密度，模型少了外顯對照錨點，反而容易在內部思考繞更久（導致輸出總 token 不減反增 **+16%**），最後挑得又比舊版粗糙。
