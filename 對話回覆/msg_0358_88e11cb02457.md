## 一、10 組《定稿》譯文檢查結果

### 1. 較重要／建議修正的疑點（4 處）

1. **10 組〔疏文〕：「就只是單獨列出戒條而已」（原文：`至尼律中單列戒本`）**
   - 終審其實已經把這條列在「微瑕」裡，但因未判 `FIX` 而保留在定稿中。
   - 原文「單」是「僅、只」的意思（記文自釋為「**但列戒相而已**」），不是「另外單獨列出一處」。尼律的三十捨墮，前十八條就依序排在前面，只是省略緣起與廣解，僅列戒文。「單獨」二字容易讓讀者誤解為另闢專區，建議改為「**只列出戒條而已**」。

2. **10 組〔記文〕：「就是《四分律》的〈比丘尼犍度〉」（原文：`「尼律」，即《尼犍度》`）**
   - 《四分律》實際的卷次結構中，比丘尼三十捨墮等戒條在卷 22–30 的〈比丘尼律〉（比丘尼波羅提木叉分別），而卷 48–49 的〈比丘尼犍度〉說的是八敬法與尼受戒羯磨等法。
   - 宋代元照律師在《行宗記》此處隨口將尼律稱為《尼犍度》，譯文甲又主動補上「《四分律》的」並改標為「〈比丘尼犍度〉」，反而把原著的略稱坐實成《四分律》二十犍度中的那一篇，熟讀律藏者讀到這句會覺得出處對不上。建議維持「就是《尼犍度》」（或依《行宗記》原稱，不主動加「《四分律》的〈比丘尼……〉」）。

3. **07 組〔記文〕：「接著兩句顯示內心的過失」（原文：`上二句明結業，次二句顯情過`）**
   - 對照疏文：`今反內懷瞋忿，斷彼相續`（上二句：起瞋心＋斷命＝結成殺業），`違慈惱他，損害道器`（次二句：顯情過）。
   - 在元照律師（《行宗記》《資持記》）的慣用語彙裡，「情過」多指**犯戒的罪情過患（過失之情實輕重）**，而不專指「內心」——且「內懷瞋忿」已經在前面「上二句」講過了，後兩句講的是「違慈惱他、損害道器」的過患之深。譯為「內心的過失」略窄且與前句重疊，改作「**顯示所犯的情理過患**」或「**顯示罪情過患**」較貼切。

4. **01／05／06／08／09 組的「消歧義括注與文言殘留」標準微有參差**
   - **08 組〔疏文〕**保留了「（九十單提中的過量坐具戒）」，**06 組〔記文〕**補了「（僧殘、波逸提、提舍尼、突吉羅）」，**04 組〔記文〕**留了「（仍在生長、尚未摘取）」；但 **03、05、09 組** 同性質的「（式叉摩那…）」「（雨浴衣）」等都被裁決全數刪掉。雖然保留這幾處在義理上都正確（尤其 08 組的「九十」不補確實很難懂），整體寬嚴尺度還差一點統一。
   - **01 組〔鈔文〕**：
     - 「隨其姓名**改牒**使用」（`隨名牒用`）：「改牒」仍屬文言詞彙，一般白話宜作「依其姓名代入法文中使用」。
     - 「**先徵求與欲**、問明僧眾和合」（`上座如上欲和`）：「與欲」是未出席比丘委託他僧代為表態，上座作的是「索欲／問欲（詢問誰受委託與欲）」，寫「徵求與欲」語意略拗。
     - 同一段內先寫「這**兩位**比丘」，緊接著又寫「這**二位**比丘」，「兩／二」混用。
     - 「這樣乞求三次」（`三乞已`）：審核已指出「已」的先後次第未顯（宜作「這樣乞求三次之後」）。

### 2. 其餘可確認無誤或僅屬極輕微修辭之處

- **02 組**：`用化前人` 譯「用以化導對方」（審核已點出破僧係誑語惑眾，「化導」語氣偏正面，用「勸化／勸說」更好）；記文 `業相中，初科，又二` 譯「業相這一科中，第一段又分二」，兩個「科」字譯法不一。其餘如「身現不得→單靠身體示意不能成就」、「事理兩種不和合」皆準確。
- **03 組**：原文 `除十葉（）外` 屬形近訛字，定稿直接依記文與《優婆塞戒經》譯為「十業」，未依提示詞加 `〔業〕` 校改標記（純白話閱讀其實更乾淨，只與規則略有出入）。科判三層結構「『攝不盡』這一科中，第一科的開頭先確立論義」與《濟緣記》相契。
- **04 組**：「但名壞相，由色變故」採「因為捉觸使它色相變異」，與下句「不名惡捉，以本生故」對仗最順，且已避開誤把「壞相」混為第五門「淨生種」；記文也已改回「果菜」而不局限於「樹上」。
- **05 組**：整體極穩，「夏初立誓……反之，若夏初未曾立誓……」已修復前後不一致；「依閏／不依閏」與《摩得伽論》「成受不成受」邏輯皆正確。
- **06 組**：「有人不與僧眾同集而別取僧食」、「初篇波羅夷以外的下四篇罪」皆精確無誤。
- **09 組**：「如果已經把罪發露出來，對方聽到後便到此為止，不必再發露」中，「便到此為止」稍易被讀成對方停止動作，實指發露者向一人說完即可停止、不必再向他人重複發露。記文保留「文中的『以』字，應當寫作『已』字」，雖與輸入疏文已先校改成「已」略顯矛盾，但屬忠實翻譯原記文。
- **全批格式**：定稿的欄位標籤後換行不統一（01 組 `【鈔文】` 後空一行；02/04/06/08 組換一行；03/05/07/09/10 組不換行直接接正文），是因為 `norm.py` 未統一標籤後換行格式。

## 二、報告與程式碼中影響結果／流程的實質 Bug

比對 `校閱系統_程式與提示詞.md` 與 `測20b_報告_01-10.md` 後，發現以下幾處**確實會影響產出品質或使某幾步流程失效**的程式問題：

1. **`測20b_報告_01-10.md` 本身的報告錯位**：
   全份報告 10 組的 `### 新譯` 與 `### 裁決` 內容完全相同（連 `結論：REVISED` 和 `分歧與裁決` 都重貼了兩次），沒有把真正的「盲翻（甲）」獨立譯文印出來，導致人工覆核時看不到完整的譯本甲全貌。

2. **`mk_review_materials.py` 的 `emit()` 組了 `body_prompt` 卻忘了寫入材料**：
   ```python
   if unit == '記文':
       body_prompt = BASE_PROMPT.format(...)
   else:
       body_prompt = get_prompt(g.get('no_ji', False))
   L = ['---', '', ...]  # ← 這裡沒有放 body_prompt！
   ```
   其餘 `mk_blind` / `mk_judge` / `mk_audit` / `mk_revise` 都有把 `prompt` 放進 `L[0]`，唯獨 `mk_review_materials.py` 漏掉，若跑 `run_pipeline.py --stages review`，一審模型只會看到系統 prompt，完全收不到 `BASE_PROMPT`。

3. **`merge_long.py` 拼回超長段會出現重複標籤且沒正規化**：
   `mk_split_blind.py` 要求每一小段都以 `【疏文】……` 開頭，但 `merge_long.py` 直接 `''.join(segs)` 拼接，既沒剝掉第 2 段之後的 `【疏文】／【記文】／【鈔文】`，也沒插入換行、沒跑 `norm.normalize()`，拼回後的長段會在段落中間夾雜 `【疏文】` 標籤。

4. **`qwen_local.py` 的 `SRC_RE_ALL` 與 `_src_unit()` 在審核／修訂階段會抓過頭**：
   ```python
   SRC_RE_ALL = re.compile(r'■ (?:疏文|記文|鈔文|律文|註文|序文)（原文）'
                           r'\s*\n+(.+?)(?=\n+■ |\n+【後文背景|\Z)', re.S)
   ```
   在 `mk_audit_materials.py` 中，最後一欄原文之後接的是 `【裁決分歧參考】` 或 `【待審譯文】`，在 `mk_revise_materials.py` 中接的是 `【目前譯文】`，都不是 `■ ` 或 `【後文背景`。因此 `_raw_len()` 會把待審譯文與分歧參考也計入原文字數，讓短段在審核時通通誤拿 `>300 字` 的滿額 5 次本地配額；建議結尾 lookahead 補上 `|【裁決分歧|【待審譯文|【目前譯文`。

5. **`qwen_local.py` 的 `_quota()` 有死碼並會忽略 `QWEN_MAX_FETCH`**：
   ```python
   if not os.environ.get('QWEN_MAX_SEARCH'):
       if n < 100: return 1, 1
       if n <= 300: return 2, 1
       return 2, 1
   if os.environ.get('QWEN_MAX_SEARCH'):
       ...
       return MAX_SEARCH_PER_GROUP, _f
   if os.environ.get('QWEN_MAX_FETCH'):  # 永遠執行不到
   ```
   沒設 `QWEN_MAX_SEARCH` 時第一段就已 `return`，會直接忽略單獨設定的 `QWEN_MAX_FETCH`（例如 `run_all_books.py` 設了 `QWEN_MAX_FETCH='1'` 若想改成 `2` 其實無效），且後半段動態配額也完全變成死碼。

6. **`qwen_local.py` 的 `_save_result()` 寫不出 `src_hash`**：
   `_save_result(dst, choice, stats, extra_tag='', src_text='')` 內寫了 `io.open(src, ...)`，但 `src` 並未作為參數傳入，被 `try...except: pass` 吞掉例外後，`_usage.json` 其實永遠沒有 `src_hash`。

7. **`mk_judge_materials.py` 遇到未配對段（`律文／註文／序文`）會漏空現譯，且未真正用 JSON 資料層**：
   - 第 147 行 `--a out` 只取 `lab in ('疏文', '鈔文')` 和 `lab == '記文'`，若遇到文件 4.9 節新增的 `律文／註文／序文` 單欄組，譯本甲／乙會變成空字串；而 `split_sj()` 在 `has_ji=False` 時也不會剝掉開頭的 `【疏文】` 等標籤。
   - 雖然已建立 `materials_io.py`，但 `mk_judge_materials.py` 仍另行用正則重爬 `.md` 檔，未直接使用 `md['units']`。
   - `mk_audit_materials.py`、`mk_revise_materials.py` 與 `build_a2.py` 的 `col3()` 沒有像 `qwen_local.py` 的 `_split_col3()` 一樣剝掉標題後的圓括號，若裁決回覆照 PROMPT 原樣寫出 `修正後的譯文（無論 PASS_A 或 REVISED 都必須完整輸出）：`，括號內的提示文字會直接掉進審核與定稿開頭。

8. **`local_corpus.py` 與 `SYSTEM_PROMPT` 的檢索細節**：
   - `ALIASES` 中 `('四分律刪補隨機羯磨疏濟緣記', '業疏')` 會把搜尋《濟緣記》全稱的 `work` 導向只有 5,354 行的《業疏》正文，而非 18,739 行的《濟緣記》。
   - `qwen_local.py` 在 `NO_WEB=1` 時的 `SYSTEM_PROMPT` 寫「本地已收錄 22 部」，但書單文字只列了 17 部，漏了後來新增的《行事鈔科》《義鈔科》《尼鈔科》《薩婆多毘尼毘婆沙》《薩婆多部毘尼摩得勒伽》（`NO_WEB=0` 的分支則有列齊 22 部）。

9. **`norm.py` 與 `qc_scan.py`**：
   - `norm.py` 只替換 4 個簡體詞且 `VAR_MAP` 只有 `衆→眾`，若模型偶爾輸出「众、问、这、为、应、经」等簡體字仍會漏網；`qc_scan.py` 也漏掉 `律文|註文|序文` 原文抽取，且若單欄定稿夾帶 `【結論】` 或 `【必改硬傷】`，`out.count('【') > 2` 可能會漏報。
