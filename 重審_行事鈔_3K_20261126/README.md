# 給 AI 的處理說明：行事鈔 3K 審閱材料

你是負責校閱《四分律刪繁補闕行事鈔》白話的 AI。這個資料夾是給你「逐段檢查白話、回報修正」的工作材料。

- 共 **776 個材料檔**：`0001_xingshichao.md` … `0776_xingshichao.md`。
- 每個檔案＝**一份獨立任務**，彼此不重疊、不重複。
- 每檔開頭都附有**完整提示詞**（【檢查維度】＋【修正譯文體例】＋【輸出格式】），請完整遵守；不要自行改寫提示詞。

---

## 一、檔案結構

```
（檔首）完整提示詞

## 行事鈔／533

### 原文

【鈔文】…
### 白話

【鈔文】…

## 行事鈔／534
…
```

- `## 行事鈔／<key>` 是**一個段落單位**；`<key>` 例如 `533`，若同一列原文有多個分段則為 `330-1`、`330-2`。
- `### 原文` 是要對照的底本文字；`### 白話` 是待審白話。
- 你的工作對象是**每一段的「### 白話」**，不是改原文，也不是改檔首提示詞。

---

## 二、一份檔案怎麼處理

1. 讀完檔首提示詞，依其【檢查維度】逐段檢查每一段白話：術語、層次立場、詞句斷讀、句法指代、舉證與克制。
2. **一次處理一份檔案**（例如 `0001_xingshichao.md`），依檔案內 `##` 的順序逐段處理，**不得漏段、不得跳段、不得自行合併**。
3. 依【修正譯文體例】判斷是否需要修正；只修確切錯誤，不為潤飾而改寫。
4. 回覆依提示詞的【輸出格式】：

- **（一）考據初檢**：逐段列出檢查發現、引證依據或「存疑待查」說明；全段無誤就簡註「經核對無誤」。
- **（二）語言與定稿覆核**：逐段快速覆核錯別字、指代、修飾範圍、多餘增譯，以及擬修文句是否已消除夾譯夾疏。
- **（三）JSONL 結構化結果**：文末輸出固定錨點區塊（**不要加 code fence**）：

```
<<<JSONL_START>>>
{"key":"段落的 key（只填 ## 行事鈔／後面的代號）","status":"ok|fixed|uncertain","note":"fixed 時簡述修正原因；uncertain 時寫明存疑之處與確定誤譯處；ok 留空","translation":"status=fixed 時填修正後完整白話；ok 或 uncertain 時留空"}
<<<JSONL_END>>>
```

**status 規則**
- 全段無誤 → `ok`
- 確定要修且**沒有**任何存疑 → `fixed`，`translation` 填修正後完整白話
- 只要含任何「存疑待查」→ `uncertain`，`translation` 留空，`note` 說明存疑處（與確定誤譯處）

---

## 三、硬性規則

- **key 逐字對應**：只填 `## 行事鈔／` 後面的代號（例：`533`、`330-1`）。
- **原文不可改**；白話只改確定錯誤處，不要整段重寫文風。
- **不確定就標 `uncertain`，不要猜**；沒有依據不要推翻既有譯法。
- **JSONL 不加 code fence**；一個段落一行，行數必須等於該檔 `##` 段數。
- 回覆請用純文字（Markdown 可），不要輸出 HTML。
